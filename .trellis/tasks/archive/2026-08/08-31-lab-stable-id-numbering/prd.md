# Lab 稳定 ID 与自动编号重构

## Goal

为每个 Lab 增加可长期引用的稳定编号，并让后续作者在创建 Theory、Exercise、Project Lab 时不再人工计算编号。交流、网站、CLI 和 VS Code 应使用同一个编号定位题目，同时保留现有目录与公开 URL，避免破坏历史链接和学习进度。

## Background

- 当前目录和标题使用章节内统一流水号，例如 `lab-02-11-*`，三类 Lab 共用序号。
- 当前 `lab:new` 强制作者传入 `--order`，目录、标题和 frontmatter 顺序都由这个人工编号生成。
- 网站 URL 由目录名派生；VS Code 插件当前也使用目录名作为进度主键。
- 用户已确认第一阶段保留所有现有目录，只为存量 Lab 增加稳定 ID；新建 Lab 使用带类型标签的新目录格式。

## Requirements

### R1. 稳定编号合同

- 每个 Lab 必须拥有 `labId`，格式为 `CCTNN`、`CCENN` 或 `CCPNN`，其中章节至少两位、类型标签为 `T/E/P`、类型内序号至少两位。
- `quiz -> T`、`program -> E`、`project -> P`；README-only Lab 由显式 `labCategory` 映射，禁止按标题或 slug 猜测。
- 同一章节内三类序号分别从 1 开始且互不影响；发布后的 ID 不因删除、插入或展示顺序变化而复用或改号。
- CLI 接受 `02T3`、`2t3` 等简写并规范化为 `02T03`，对外展示使用规范形式。

### R2. 存量兼容迁移

- 所有现有 Lab 按章节、类型、现有 `order` 的相对顺序获得稳定 ID。
- 现有目录、URL、README 标题和 `order` 不批量改名。
- 无 manifest 的 Lab 必须补全明确分类；无法确定类别时迁移应失败而不是猜测。

### R3. 自动创建

- `lab:new` 不再要求作者计算类型内编号。
- 创建时按目标章节和类型读取现有 `labId`，使用该类型最大序号加一；缺号不复用。
- `order` 变为可选展示顺序；省略时使用该章节最大展示顺序加一。
- 新目录采用 `labs/chapter-CC/lab-CC-T-NN-slug`、`...-E-...` 或 `...-P-...`，README 自动包含匹配的 `labId` 和标题。
- 创建结果的人类输出与 JSON 输出都返回稳定 ID、路径、类型和展示顺序。

### R4. 定位与展示

- 新增 `lab:locate`，输入稳定 ID 或简写后返回唯一 Lab 路径；不存在或重复时给出明确错误。
- 网站内容索引、Lab 列表和详情页暴露 `labId`，新旧目录都能发现和构建。
- 章节侧栏条目使用 `labId · 题目名称`，不在稳定 ID 后重复旧 `Lab CC-NN` 编号。
- VS Code 题目树、题面和统计使用稳定 ID，并能把现有目录名键控的本地进度迁移为稳定 ID。

### R5. 校验与并发冲突

- 内容校验检查 `labId` 格式、全仓唯一性、章节一致性、类型标签一致性，以及新目录与 ID/标题的一致性。
- 旧目录继续校验原有章节、`order` 和标题前缀合同。
- 两个并行 PR 分配到相同 ID 时，CI 必须以清晰的重复 ID 错误阻止合并；不在本阶段引入中央预约服务。

### R6. 文档与测试

- 更新 `docs/LAB_AUTHORING_GUIDE.md`、Lab CLI 指南、更新流程、项目规范及其他仍声明旧创建合同的开发者文档。
- 单元测试覆盖规范化、三类独立递增、缺号不复用、可选 order、新目录、定位、重复与不匹配错误。
- 内容发现、静态产物、网站导航和 VS Code 插件测试覆盖稳定 ID 与新目录格式。

## Acceptance Criteria

- [x] 所有现有 Lab README 都有唯一、类型正确的规范 `labId`，且原目录与 URL 未改变。
- [x] 在已有 `02T01..02T03` 时创建 quiz 自动得到 `02T04`；Exercise 和 Project 仍从各自序列计算。
- [x] 删除中间编号后创建新 Lab 仍取最大编号加一。
- [x] 未传 `--order` 可以成功创建；显式 `--order` 只控制展示顺序，不改变稳定 ID。
- [x] `pnpm lab:locate -- 02T2` 能解析并输出 `02T02` 的唯一现有路径；`02T3` 一类简写可被规范化，JSON 模式提供机器可读结果。
- [x] 重复 ID、错误标签、章节不符、目录与 ID 不符均被校验器拒绝。
- [x] 网站能够发现新旧两种目录，Lab 列表和详情页显示稳定 ID，构建产物检查通过。
- [x] 章节侧栏显示 `05T01 · 森林与二叉树转换题精练`，不显示 `05T01 · Lab 05-01：...`。
- [x] VS Code 使用稳定 ID 记录新进度，并保留旧目录键对应的代码题、选择题、活动记录和历史快照可访问性。
- [x] 作者指南准确说明编号、创建、定位、并发冲突和兼容策略，文档示例由自动测试校验。
- [x] 相关内容校验、单元测试、扩展测试、类型检查、构建、静态产物检查与 Pages 导航测试全部通过。
- [x] 本地预览启动并提供给用户检阅；用户确认前不提交、不推送。

## Out of Scope

- 本阶段不批量重命名既有目录、公开 URL 或 README 标题。
- 不提供跨分支的中央编号预约服务。
- 不让 VS Code 自动判定含人工评分任务的 Project 完成状态。
- 不改变题目内容、答案、测试数据或课程知识顺序。

## Constraints

- `labId` 是发布后的永久身份；`order` 仍是可调整的展示顺序。
- 现代 Lab 类型继续以 `lab.json.type` 为单一事实来源，README 不重复维护类型标签。
- README-only Lab 必须通过 `labCategory` 明确归类。
