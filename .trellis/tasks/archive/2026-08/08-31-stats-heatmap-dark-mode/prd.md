# 增强统计面板深色模式热图

## Goal

让 VS Code 深色主题下的统计面板热图具有清晰的层次：无活动、低强度活动和高强度活动都能被快速区分，同时不破坏当前浅色主题的低噪声视觉风格。

## Background and confirmed facts

- 统计页的热图由 `tools/vscode-extension/src/statsPanel.ts:22-38` 使用 `--stats-chart-empty`、`--stats-submit-*` 和 `--stats-pass-*` 语义变量渲染；提交和通过两套热图共用同一套空状态基础色。
- 当前色阶在 `tools/vscode-extension/media/panel.css:107-116` 中主要通过 `color-mix()` 将橙色/靛蓝与当前表面混合，低强度级别在深色表面上接近背景，因此不明显。
- 热图图例、月份/星期标签和活动数据本身已有独立结构；本任务不需要修改事件记录、`intensity()` 算法、年份切换或提交/通过统计语义。
- 统计页与做题页共享 `.lab-page` 语义令牌，但统计页结构独立，不应引入侧边栏、题目导航、结果检查器或底部动作栏。

## Requirements

1. 为 VS Code 深色主题提供单独的热图语义色阶，至少覆盖：空状态、提交 1-4 级、通过 1-4 级；每套色阶从低到高具有可辨识的明度/饱和度层次。
2. 深色主题下，热图单元格与统计卡片表面、热图容器背景之间保持清晰分离；提交和通过两种指标必须能区分，图例色块必须与实际单元格一致。
3. 保持浅色主题现有配色方向和信息层次；主题切换不改变热图数据、计数、日期布局、年份选择或提交/通过切换行为。
4. 颜色优先复用 VS Code 主题变量和统计页语义 token；只在必要处增加显式深色/高对比度 fallback，不在 TypeScript 中散落按主题判断或单元格硬编码颜色。
5. 热图在桌面和窄窗口下继续只在自身 `.heatmap-scroll` 容器内横向滚动，统计页面不产生整体横向溢出；文字、图例、焦点环和控件状态保持可读。
6. 增加自动化 UI 合同测试，覆盖深色主题色 token、两类热图色阶和图例仍通过变量引用；保留现有统计纯函数及 WebView 测试。
7. 进行浅色/深色桌面与窄窗口视觉检查，确认低强度活动不再与空状态混淆。

## Out of scope

- 不修改热图事件数据、日期定位、强度分级算法、统计计数或业务语义。
- 不重做累计通过趋势、章节分布、统计页布局或做题 WebView。
- 不修改 VS Code 原生侧边栏、命令入口、插件发布流程或版本号。
- 不引入新的前端框架、远程字体、图表依赖或运行时主题配置。

## Technical notes

- 主题判断应优先依赖 VS Code WebView 提供的主题 class/变量与已有 `.lab-page` token；实现时需确认深色和高对比度 WebView 的可用变量，避免只依赖浏览器系统偏好。
- 这是轻量 UI 任务，当前阶段只需要 `prd.md`；实现前仍需经过后续规划审阅并显式启动任务。
