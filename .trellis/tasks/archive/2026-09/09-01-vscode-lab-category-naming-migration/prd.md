# VS Code 插件适配 PR#122 的 Lab 分类与编号规范

## Goal

让 VS Code 插件在仓库采用 PR#122 的新目录与编号规范后，仍能完整发现、展示、打开、判题和统计所有可作答 Lab；同时保留已有用户的做题进度，不因目录迁移丢失。

## Background

- PR#122 已将可作答内容按章节拆入 `theory/`、`exercise/`、`project/` 三类目录；当前远端 `main` 已包含这套内容结构。
- 新 README frontmatter 提供稳定 `labId`，格式为两位章节号 + 类型字母（`T`/`E`/`P`）+ 序号，例如 `01E01`、`01T01`。
- 当前插件在 `tools/vscode-extension/src/labIndex.ts` 中只扫描章节目录的直接子目录，并以目录名作为进度、活动日志、导航和命令解析主键；在新结构下会漏题或无法关联历史状态。
- 当前工作区分支 `feat/vscode-lab-extension` 已包含做题 WebView、统计面板和深色 heatmap 改动；本任务只同步内容发现与身份/状态兼容，不改变这些 UI 设计目标。

## Requirements

### R1. 发现新目录结构

插件扫描每个 `labs/chapter-*/` 下的 `theory/`、`exercise/`、`project/` 目录，并加载其中 `lab.json` 合法且类型为 `program` 或 `quiz` 的 Lab。

### R2. 使用稳定 Lab ID

插件以合法的 `frontmatter.labId` 作为 Lab 的稳定业务身份，供树节点命令参数、WebView 导航、提交记录、选择题记录、活动事件、章节统计和源码快照目录使用。缺少或格式非法的 `labId` 必须安全退回当前目录名，以兼容旧仓库/旧 learner 包。

### R3. 保持用户可见编号一致

树视图、做题 WebView 标题元信息、tooltip 和相关题目导航必须显示/传递稳定编号；显示标题不得重复渲染 README 中已存在的 `Lab 章节-类型-序号` 前缀。

### R4. 迁移旧进度

插件首次扫描新结构后，将已有的目录名主键（旧平铺目录名和新分类目录名）迁移到稳定 `labId`：

- 代码题、选择题记录和活动事件都要迁移；
- 新旧键同时存在时必须合并而非覆盖，保留最高分、通过状态、可用历史/答案与最近提交信息；
- 迁移前备份原始 globalState；旧源码快照仍必须可打开；
- 迁移完成后后续读写只使用稳定 `labId`。

### R5. 兼容命令和操作流程

从树节点、命令参数、当前编辑器和 WebView 上/下一题导航打开 Lab 时，均能解析稳定 ID；在迁移期间也接受当前目录名/旧目录名作为别名。提交、历史、并排输出对比和统计必须继续可用。

### R6. 质量边界

保持现有 `program`/`quiz` 行为、章节排序、UI、暗色热图和公开测试用例逻辑不变；新增纯函数测试覆盖稳定 ID 校验、目录发现的分类边界、旧键迁移和键冲突合并。不得修改课程内容或将 `project` 人工评审 Lab 当作自动判题题目。

## Out of Scope

- 不修改 PR#122 已落地的课程目录、README/frontmatter 或网站收录逻辑。
- 不重做 VS Code 侧边栏、做题 WebView、统计面板或 heatmap 视觉设计。
- 不迁移用户 globalStorage 中旧源码快照的物理目录；只更新引用路径和进度键。
- 不把缺少可执行 `lab.json` 的 README-only 内容或 `project` 人工评审流程加入自动判题。

## Acceptance Criteria

- [x] 在 PR#122 目录结构下，插件能发现 `theory`、`exercise`、`project` 中所有合法 `program`/`quiz` Lab，过滤 README-only 与不支持类型。
- [x] 每个合法 `labId` 被解析为稳定 ID；缺失/非法值退回目录名，不崩溃。
- [x] 树视图和做题 WebView 显示稳定题号；点击树节点、提交、历史、前后题导航和当前编辑器回退路径均能打开正确 Lab。
- [x] 从 v2 进度迁移到稳定 ID 后，代码题/选择题状态、活动日志、合并冲突和旧快照引用均满足上述 R4；迁移结果会持久化且留下备份。
- [x] 现有 UI 单测、统计/选择题单测、类型检查和插件构建通过；新增迁移/身份测试通过。
- [x] 变更范围仅覆盖插件适配及其测试/必要规范记录，不引入内容或生成物污染工作区。

## Open Questions

无。PR#122 已定义新目录、稳定编号格式和迁移方向；实现采用远端 `main` 已验证的兼容方案。
