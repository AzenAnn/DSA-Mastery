# 设计：Ch12 分治与递归整体重构

## 1. 设计原则

### 1.1 先建立共同语言，再训练题型

本章不按“经典算法清单”堆叠内容，而按学习者做题时真正需要回答的问题组织：

1. 当前递归函数究竟承诺返回什么？
2. 规模为什么一定下降，程序如何执行和返回？
3. 题目是否真的满足分治的独立子问题与可合并性？
4. Combine 要返回一个数、一个序列、一棵树还是一组结果？
5. 为什么算法会终止、为什么合并后仍然正确？
6. 总调用、每层工作、栈深度和缓冲区分别是多少？
7. 是否应该改用迭代、DP 或回溯？

16 个 Lab 按这七问形成三段梯度，而不是只按平台难度排序。

### 1.2 课程正文与 Lab 各司其职

- 正文解释可迁移的模型、证明和复杂度，不复制完整题解代码。
- Lab README 冻结单题合同、边界、步骤和复盘，并链接正式来源。
- `solution/main.cpp` 是唯一可运行参考实现；README 的参考代码若保留，应与 solution 同步且不能成为第二份漂移实现。优先用题解文字和伪代码解释，完整代码指向仓库文件。
- `tests/cases.json` 是评分结构，`.out` 是固定 oracle；所有多解题先定义可复现的规范输出。

## 2. 文章信息架构

```text
00 overview
  -> 01 递归函数合同
  -> 02 调用栈 / 递归树 / 迭代改写
  -> 03 Divide-Conquer-Combine 建模
  -> 04 五类 Combine 返回形态
  -> 05 终止性 + 强归纳 + 不变量
  -> 06 递推式 + 递归树 + 主定理 + 空间
  -> 07 与迭代 / DP / 回溯的选择边界
```

### 2.1 贯穿示例分配

| 文章 | 主示例 | 辅助反例 / 对比 |
| --- | --- | --- |
| 01 | 快速幂的函数合同 | 缺边界、规模不降、返回语义不完整 |
| 02 | 阶乘或二分幂的小规模调用栈 | “递归深度 = 调用次数”的错误猜想；显式栈改写 |
| 03 | 归并排序的 D-C-C | 二分查找只递归一侧；汉诺塔不是“三元分治” |
| 04 | 归并序列与逆序对计数 | 四叉树结构、表达式结果集、跨中点计数 |
| 05 | 归并排序强归纳证明 | quickselect 的区间不变量；P1228 的覆盖不重叠 |
| 06 | `2T(n/2)+Theta(n)` 递归树 | `T(n)=2T(n-1)+Theta(1)`、不均衡快排、输出敏感复杂度 |
| 07 | 同一递归树分别解释为分治、DP、回溯 | 栈溢出、切片复制、随机枢轴、多解输出 |

### 2.2 文章与 Lab 的连接

| 学习阶段 | 对应正文 | Lab |
| --- | --- | --- |
| 递归合同与规模下降 | 01、02 | `12E01`～`12E04` |
| 自相似与单侧/多路分治 | 03 | `12E05`～`12E10` |
| 合并、证明与计数 | 04、05、06 | `12E11`～`12E16` |
| 方法选择与迁移 | 07 | 复盘全部 Lab，并连接 Ch14/Ch15 |

`00-overview.md` 以三段表格列出全部 16 题；各正文只链接与本篇模型直接相关的题，避免每篇重复一张大表。

### 2.3 语义与可视化

- 严格概念用 `definition`，核心结论用 `theorem/property`，论证用 `proof`，渐近结论用 `complexity`，错误模型用 `pitfall/counterexample`。
- 只有调用树、四叉递归区域和“分解—递归—合并”关系确实比文字更清楚时使用 Graphviz；每图使用纯 `graphviz` fence、稳定 ASCII ID 和 caption，并设置不透明浅色画布保证双主题可读。
- 栈帧表、递推逐层代价和方法对比优先用表格；不为简单一对一关系强行画图。

## 3. Lab 结构设计

### 3.1 稳定目录与元数据

每题采用：

```text
labs/chapter-12/exercise/E-12-SS-slug/
├─ README.md
├─ lab.json
├─ Makefile
├─ student/main.cpp
├─ solution/main.cpp
└─ tests/
   ├─ cases.json
   ├─ 001-*.in
   ├─ 001-*.out
   └─ ... 020-*.out
```

- `labId` 为 `12E01`～`12E16`，`order` 为 1～16。
- `status: draft`，`contributors: ["Azen"]`。
- manifest 使用 `type: program`、`language: cpp`、`standard: c++17`、`profile: course-default`。
- Makefile 固定为共享工具的三行转发，不写单题 recipe。
- starter 保留函数骨架、输入输出和语义明确的 TODO，能够编译但不能满分；不能用故意语法错误充当未完成状态。

### 3.2 来源题的适配层

洛谷题尽量保留原标准输入输出；LeetCode 的方法签名统一适配为独立 stdin/stdout 程序。README 必须用“本 Lab 的输入输出合同”单列说明，避免读者误以为平台原题也使用该协议。

| 题目类别 | 适配决定 |
| --- | --- |
| 普通单值/数组返回 | 首行写规模与参数，次行写数组；输出空格分隔 token |
| `Pow(x,n)` | 输出双精度数值，判题使用相对/绝对容差；指数先提升为 64 位再取绝对值 |
| 四叉树 | 用前序 `I/L0/L1` 编码，孩子顺序固定 TL/TR/BL/BR；内部结点不输出无意义 val |
| 表达式所有结果 | 输出前先升序排序，保留重复结果，使“任意顺序”转为固定 oracle |
| 漂亮数组 | 冻结“递归奇数映射在前、偶数映射在后”的规范构造；额外性质检查验证合法性 |
| 地毯填补 | 冻结“先中心、再 TL/TR/BL/BR”的输出顺序；额外覆盖检查验证每格恰好一次 |

此方案保持现有 Lab CLI 不变，代价是 `12E10` 和 `12E13` 的本地满分答案是原题合法答案的一个规范子集。README 必须公开这一差异，这是比新增通用 SPJ 更小、可回滚的设计。

### 3.3 参考实现方法边界

| ID | 参考实现要求 | 关键错误模型 |
| --- | --- | --- |
| 12E01 | 三维 memo，仅缓存有效 `1..20` 状态 | 朴素递归超时、先索引后裁剪、终止行被输出 |
| 12E02 | 从最高置位到最低置位递归格式化指数 | `2(1)` 特判错误、多余 `+`、顺序反转 |
| 12E03 | 递归复制/定位字符，内存与输出上限可控 | 反斜杠转义、前导空格、尺寸翻倍错误 |
| 12E04 | exponent 使用 64 位；每层只算一次半幂 | `INT_MIN` 取负溢出、奇偶分支、多算子问题 |
| 12E05 | 递归处理三个未赦免象限或等价区域判定 | 左上区域边界、行列颠倒、输出量超限 |
| 12E06 | 找覆盖 N 的最小倍增长度，再逆映射下标 | 1/0 基下标混用、旋转首字符映射、64 位溢出 |
| 12E07 | 原地三向 partition + 只进入目标段；不用 `nth_element` | 重复值死循环、k 为 0 基、极端枢轴退化 |
| 12E08 | 自写归并排序，`O(n log n)` | 空区间/单元素、复制边界、内置 sort 绕过目标 |
| 12E09 | 区域一致则叶，否则四分递归 | 象限顺序、非叶误合并、n=1 |
| 12E10 | 中心 L 形制造三个“伪缺口”再四分 | 朝向编号、坐标 1 基、重叠/漏格 |
| 12E11 | 归并时批量增加剩余左段长度 | 相等元素误计、32 位答案溢出 |
| 12E12 | 以运算符切分，组合左右所有结果，可做区间 memo | 多位数解析、重复结果误去重、减法次序 |
| 12E13 | 递归构造 `ceil(n/2)` 奇映射和 `floor(n/2)` 偶映射 | 越界值、非排列、只过样例 |
| 12E14 | 先计跨段 `left > 2*right`，再标准归并 | 32 位乘二溢出、负数不等式、指针未单调 |
| 12E15 | 归并 `(value,index)` 并累计右侧先出数量 | 相等值误计、答案写回排序后位置 |
| 12E16 | 64 位前缀和；归并前用两个单调窗口计区间 | 上下界开闭、漏空前缀、前缀和溢出 |

### 3.4 测试设计

每题固定至少 20 个用例，每例默认 5 分，必要时可调整但总分必须 100。用例命名从行为出发，不用 `normal-1` 这类无信息名称。

建议结构：

- 2～3 个题面样例/最小可读示例；
- 5～7 个边界，包括最小规模、单元素、全相等、0/负值、极端指数或索引；
- 6～8 个针对错误模型的回归用例；
- 2～4 个较大规模/复杂度用例；
- 多解规范题额外覆盖顺序、重复值和性质检查生成的案例。

默认 `tokens`；只有行结构/字符画/固定格式使用 `exact`，浮点使用 `float`。图形和大矩阵题提高 `outputKb`，P1228 同时提高 `timeMs`。所有 `.out` 先存在占位或预期文件，再由 `lab:refresh-expected --write` 生成并审查 diff。

## 4. 生成与删除策略

### 4.1 可复现生成

新增 `scripts/generate-chapter-12-divide-conquer-labs.mjs`，数据化保存 16 题元信息、README 片段、solution/starter 与测试输入生成逻辑。脚本只允许写入 16 个精确的新目录，不扫描后拼接删除目标；重复执行时必须拒绝覆盖或只在显式 `--force` 下覆盖同一白名单路径。

生成器是批量机械文件的单一维护入口，但最终产物仍全部提交、逐题审查和运行。它不能替代手工题面核对、solution 正确性或测试充分性判断。

### 4.2 两阶段替换

1. 新 slug 与旧 slug 不同，因此可先并存；旧 `12E01`～`12E13` 与新同 ID 会暂时重复，但逐题 CLI 可按路径验证新 Lab。
2. 生成并逐题 `lab:validate`、`refresh-expected`、`lab:verify`。
3. 在 `docs/CLEANUP_REPORT.md` 写明 15 个旧目录、16 个替代目录、无外部引用证据和 `git restore` 回滚方式。
4. 用经过核对的精确路径删除旧目录；Theory/Project 放回 `.gitkeep`。
5. 修改正文与 ContentIndex，运行全仓验证，清除所有旧 slug 引用。

这样既满足“替换前先验证”，又避免把生成失败后的空目录当成完成状态。

## 6. 风险、兼容与回滚

| 风险 | 控制措施 |
| --- | --- |
| 16 题批量生成造成机械错误扩散 | 生成器白名单 + 每题 validate/verify + 全仓测试 + 代表题人工运行 |
| 固定 oracle 无法表达多解 | README 冻结规范输出；P1228/Beautiful Array 另做性质检查 |
| 大输出让本地评分 OLE/TLE | 按题提高 limits；压力用例只保留能区分复杂度的最小规模 |
| 旧 ID 复用造成身份混乱 | 只因旧题全部为 draft 才允许；删除报告记录旧新映射，不对外宣称 URL 兼容 |
| 正文泄露完整解法，削弱 Lab | 正文只给模型/局部代码；完整实现留在 solution 与折叠题解 |
| 删除误伤其他章节 | 删除前解析绝对路径并限制到 `labs/chapter-12`；仓库级引用检查；Git 可恢复 |
| Pages 本地正常、子路径失败 | 同时在 `/` 与 `/DSA-Mastery/` 构建、产物审计和 Playwright |

回滚单位按阶段划分：生成的新 Lab、旧 Lab 删除、正文重写、ContentIndex 修改分别可由 Git 恢复；不使用 `git reset --hard` 或工作区级破坏命令。
