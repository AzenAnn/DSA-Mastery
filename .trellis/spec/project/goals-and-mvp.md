# 项目目标与 MVP 边界

## 服务对象与成果

DSA Mastery 由两名学生共同维护，最终服务学校数据结构与算法课程的学习者。页面或 Lab 必须帮助读者至少形成一种可检查能力：

1. 准确解释概念、ADT、表示和关键不变量；
2. 在说明前提后推导时间与空间复杂度；
3. 从接口契约独立实现，并处理正常、边界和错误输入；
4. 用测试或小实验比较表示与算法的取舍；
5. 把方法迁移到课程题目、综合实验或新情境。

维护流程、Trellis 和网站都是质量手段，不是项目的最终卖点。

## 当前 MVP

- 保持第 0~2 章十一篇教材和八个 Lab 可阅读、可导航、可复现（第 2 章为 demo，状态 `draft`）。
- 课程路线按当前统一索引推进：3 字符串、数组与矩阵 → 4 树与二叉树 → 5 树的应用 → 6 图的基础与存储 → 7 图的遍历与应用；章节文章数按知识边界确定。Ch.5 当前由统一索引展示 5 个 Theory Lab、17 个 Exercise Lab 和 Project 空槽位；后续题目仍按学习目标决定类型，不用占位题凑数量。
- 以 Markdown + frontmatter 为内容源，由 VitePress 自动生成页面、侧栏、搜索和索引。
- 保留品牌化首页、教材/Lab 混合导航、暗色模式、公式、代码复制、目录和前后页。
- 用内容校验、静态构建、链接审计、浏览器点击与同伴 Review 保护发布。
- 以已落地的 VitePress 静态站为唯一网站运行时；发布与后续架构变更仍由人 Review 决定。

参考：`README.md`、`docs/PROJECT_BLUEPRINT.md`、`.trellis/tasks/08-10-vitepress-architecture-migration/prd.md`。

## 当前非目标

- 不新增 CMS、账户、学习进度、分析埋点或第二生产主机；课程章节只按路线图规划推进，不随意开新章。
- 不以"两篇文章 + 两个 Lab"之外的工程复杂度衡量章节完成度。
- 不建设 PDF/LaTeX 双主源码、商业级平台或大规模动画 Playground。
- 不为展示工程复杂度引入微服务、长期 `dev` 分支或重复索引。
- 不把未经人工核验的 AI 文本、复杂度、引用或运行结论发布为教材。

## 决策门禁

新增能力前回答：

- 它解决哪个已经出现的读者或维护痛点？
- 能否先用内容、VitePress 原生能力或一个小组件解决？
- 是否至少有两个真实页面需要同一抽象？
- 如何验证，并如何在失败时撤回？

没有具体需求时，优先补内容、Lab、练习和验证证据，不新增基础设施。

## 错误做法

- 用页面数量、组件数量或自动化数量衡量“掌握”。
- 为新技术改写稳定 URL 或复制一份 Markdown 数据。
- 将 `draft` 内容包装成完成品，或在未运行时声称“测试通过”。
- 让作者自行核验并合并影响知识正确性的改动。
