# 1.3 链表

## 学习目标

- 能画出单链表节点与链接关系；
- 能实现遍历、查找、插入和删除；
- 能解释“定位节点”和“修改链接”的复杂度差异；
- 能识别丢链、空指针和尾节点更新错误。

## 存储模型

单链表的每个节点保存数据与下一节点的引用。节点不要求物理连续，线性顺序由链接表达。头引用指向首节点；也可以加入不保存业务数据的哨兵节点来统一边界操作。

```text
head → [A | next] → [B | next] → [C | null]
```

## 核心操作

若已经持有前驱节点 `prev`，在其后插入新节点只需调整有限个链接：

1. `new.next = prev.next`
2. `prev.next = new`

删除 `prev` 后的节点时，应先保存目标节点，再令 `prev.next = target.next`。如果只有位置 `i`，仍需从头遍历找到前驱，因此整体通常是 `O(n)`。

## 复杂度

| 操作 | 复杂度 |
| --- | --- |
| 按位置访问/按值查找 | `O(n)` |
| 已知前驱后的插入/删除 | `O(1)` |
| 表头插入/删除 | `O(1)` |
| 尾部追加 | `O(n)`；维护尾指针后可为 `O(1)` |
| 额外空间 | 每个节点需要至少一个链接域 |

## 易错点

- 修改链接前没有保存后继，导致后半段链表丢失；
- 未处理空表、删除首节点或删除尾节点；
- 删除尾节点后忘记更新尾指针；
- 链接形成环导致遍历无法结束；
- 把“已知节点时修改链接为 `O(1)`”误写成所有插入删除都是 `O(1)`。

## 小结

链表将元素移动转化为链接修改，但按位置定位仍需要遍历。分析复杂度时必须说明调用者是否已经持有目标节点或其前驱。

## 练习

1. 画出在 `A → B → C` 中删除 `B` 前后的链接变化。
2. 哨兵节点如何减少表头插入和删除的特殊分支？
3. 设计一个测试，用来发现删除尾节点后尾指针未更新的问题。
4. 比较单链表与双链表在空间和操作便利性上的取舍。
