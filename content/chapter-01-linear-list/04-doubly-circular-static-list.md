# 1.4 双链表、循环链表与静态链表

## 学习目标

- 能画出双链表结点的三域结构，并说出带头结点循环双链表的空表判定条件；
- 能按正确顺序写出「在 p 之前插入 s」的四步链接，并指出哪些顺序可调、哪些不可调；
- 能实现双链表的插入、删除，以及用循环单链表模拟约瑟夫环；
- 能说明循环链表判空与遍历终止条件的变化，以及尾指针表示法的收益；
- 了解静态链表的结构、历史动机与局限（进阶阅读，了解即可）。

## 引入

单链表用「每结点一个指针域」换来了表头操作的 O(1)，但它的结构能力止步于「只知道后继」。由此产生三个痛点：

1. **只能向后走**：要从某个结点找它的前驱，只能从头重新遍历，最坏需要 O(n)；
2. **删除尾结点是 O(n)**：删除需要先定位前驱，而尾结点的前驱是倒数第二个结点，必须遍历到倒数第二的位置；
3. **某些应用需要反复前后移动**：文本编辑器的光标在行间上下移动、LRU 缓存要把刚访问的元素提到最前，这类「双向移动」在单链表上代价很高。

三个痛点的根源相同：结点上没有「回到前驱」的通道。双链表增加前驱指针，循环链表把首尾接成环，静态链表用数组模拟链式结构。它们各自解决一部分问题，也各自付出代价。本页先讲结构，再以两个例题验证操作细节。

## 概念与理论

**双链表：结点结构**

双链表的每个结点包含三个域：

```text
┌────────┬────────┬────────┐
│ prior  │ data   │ next   │
└────────┴────────┴────────┘
```

- `prior`：指向前驱结点的指针；
- `data`：数据域，本页以 `int` 为例（可用 `typedef ElemType` 泛化）；
- `next`：指向后继结点的指针。

双链表通常带头结点：头结点不存业务数据，只作为遍历起点与哨兵。若进一步把尾结点的 `next` 指回头结点、头结点的 `prior` 指向尾结点，就得到**带头结点的循环双链表**，此时：

- 空表判定：`L->next == L`（等价地 `L->prior == L`），即头结点自环；
- 尾结点无需单独维护尾指针：尾结点就是 `L->prior`，到达它是 O(1)。

**循环链表**

循环单链表把尾结点的 `next` 指向头结点（不带头结点时指向首结点）。它改变两个判定条件：

- 判空：带头结点时 `L->next == L`；不带头结点时 `L == NULL`；
- 遍历终止：不能再用 `p == NULL` 判断结束，而要回到起点才停（带头结点时即 `p == L`）。

「从任意结点出发都能回到自身」是循环结构的基本性质，也意味着只要循环条件写错，遍历就是死循环。

**只用尾指针的表示法**：对带头结点的循环单链表，只保留指向尾结点的指针 `rear`，则：

- 表头结点就是 `rear->next`，表头定位 O(1)；
- 表尾定位 O(1)（即 `rear` 自身）；
- 表头插入、表尾插入均为 O(1)。

代价是表尾删除仍为 O(n)：删除尾结点必须知道它的前驱（倒数第二个结点），仍需遍历定位。

循环双链表是「循环」与「双向」的组合：空表时 `L->next == L`，非空时 `L->prior` 即尾结点。它兼具双向移动与首尾相接的好处，是 LRU 缓存（见 1.5 例题）等场景的基础。

**静态链表（进阶阅读）**

静态链表用**数组 + 游标**模拟链式结构。历史动机（严蔚敏 §2.3.4）：早期的高级语言（如 FORTRAN）没有指针类型，而磁盘文件的物理块无法用内存地址引用；于是用数组元素充当「结点」、数组下标充当「指针」——下标即游标（cursor）。

结构定义：

```c
#define MAXSIZE 100
typedef struct {
    int data;   /* 数据域 */
    int cur;    /* 游标: 下一结点在数组中的下标 */
} SLinkList[MAXSIZE];
```

约定 0 号单元充当头结点，尾结点的 `cur` 置 0 表示「空」。未使用的单元串成一条**备用链表**（空闲链）：插入时从备用链表取下第一个结点，删除时把结点链回备用链表，模拟「动态分配」。

插入、删除的链接调整思路与单链表完全相同，只是把 `p->next` 换成 `S[i].cur`。它的劣势也很明显：

- 容量固定：数组长度编译期写死，没有真正的动态性；
- 每结点多一个游标域，空间开销不比真实链表小；
- 定位仍需沿游标遍历，时间上没有任何优势；
- 现代语言普遍提供指针或引用，静态链表几乎没有实际应用场景。

了解它的意义在于：链式思想不依赖具体的指针机制，「结点 + 引用」就能组织动态结构（外存文件、索引结构都沿用这一思想）。本页对静态链表只要求了解，不要求实现。

## 算法与实现

**在 p 之前插入 s：四步链接**

假设已持有目标结点 `p`（插入位置是「p 的前面」），新结点 `s` 已分配。四步：

```text
1. s->prior = p->prior        // s 的左指针接到 p 的原前驱 q
2. s->next  = p               // s 的右指针接到 p
3. p->prior->next = s         // q 的 next 跨过旧链接, 指向 s
4. p->prior = s               // p 的 prior 指向 s
```

第 1、2 步只让新结点「接上引用」，此时链表仍是完整的旧结构，只是多了一个游离的 s 引用着两侧；第 3、4 步才改动旧链上的指针。原则可概括为：**先接新结点，后断旧链**——新结点的两个指针就位之前，绝不动旧链。

顺序可调性：

- **第 4 步必须最后**：第 3 步读取 `p->prior` 的旧值，第 4 步改写它之后，第 3 步实际会变成 `s->next = s`；第 1 步同理，放在第 4 步之后会变成 `s->prior = s`；
- **第 1、2、3 步之间没有硬性依赖**：只要三步都在第 4 步之前执行完毕，最终状态都是正确的；
- 但若要求**每一步执行之后链表都保持完整**（防御异常、并发读写与调试——中间状态一旦被读到，丢链就固化了），则第 2 步必须先于第 3 步：否则第 3 步执行后 `s->next` 尚未就位，从 q 出发暂时走不到 p。满足这条更强不变式的只有 (1, 2, 3, 4) 与 (2, 1, 3, 4) 两种排列，也是推荐的写法。

**删除结点 p**

删除只需两步，且两步互不依赖，顺序可交换：

```text
1. p->prior->next = p->next    // 前驱的 next 跨过 p
2. p->next->prior = p->prior   // 后继的 prior 跨过 p
3. free(p)                     // 释放结点空间
```

删除与插入的关键差异：删除时 p 的两个邻接结点都在场，直接让它们互相指向即可；插入时新结点不在场，必须先让新结点「认识」两侧，再让两侧「认识」它。在带头结点的循环双链表中，删除首结点、尾结点与删除中间结点没有任何区别——这就是哨兵与循环带来的统一性。

**C 实现**

```c
/* 带头结点的循环双链表: 结点定义与核心操作 */
#include <stdlib.h>

typedef struct DNode {
    int data;                  /* 数据域; 可改为 typedef int ElemType 后使用 ElemType */
    struct DNode *prior;       /* 前驱指针 */
    struct DNode *next;        /* 后继指针 */
} DNode;

/* 初始化: 创建头结点并使其自环, 空表判定 L->next == L */
DNode *init_list(void) {
    DNode *L = (DNode *)malloc(sizeof(DNode));
    L->prior = L;              /* 空表时 prior 也指向自身 */
    L->next = L;
    return L;
}

/* 在结点 p 之前插入新结点 s: 四步链接, 顺序不可随意调换 */
void insert_before(DNode *p, DNode *s) {
    s->prior = p->prior;       /* 1. 新结点左指针接到 p 的原前驱 */
    s->next = p;               /* 2. 新结点右指针接到 p */
    p->prior->next = s;        /* 3. 原前驱的 next 指向 s (必须先于第 4 步) */
    p->prior = s;              /* 4. p 的 prior 指向 s */
}

/* 删除结点 p 并释放其空间 */
void delete_node(DNode *p) {
    p->prior->next = p->next;  /* 前驱的 next 跨过 p */
    p->next->prior = p->prior; /* 后继的 prior 跨过 p */
    free(p);                   /* 释放 p, 防止内存泄漏 */
}
```

## 复杂度分析

| 操作 | 双链表 | 循环单链表（尾指针） | 循环单链表（无尾指针） |
| --- | --- | --- | --- |
| 按位置定位 / 按值查找 | O(n) | O(n) | O(n) |
| 已知前驱（或已知结点）后插入、删除 | O(1) | O(1) | O(1) |
| 表头插入 / 删除 | O(1) | O(1) | O(1) |
| 表尾插入 | O(1)（尾 = L->prior） | O(1) | O(n) |
| 表尾删除 | O(1) | O(n)（需定位倒数第二结点） | O(n) |
| 额外空间 | 每结点 2 个指针 | 每结点 1 个指针 | 每结点 1 个指针 |

要点：

- 定位 O(n) 的推导：三种结构都只能从头沿链接逐结点推进，访问位置 i 需 i 步，最坏 n 步；
- 双链表的 O(1) 只体现在「已持有结点」之后的局部修改上，定位本身并不因此变快；
- 循环单链表比单链表多的是「任意结点出发可达全体」与尾指针下的表头表尾操作，不是定位速度；
- 双链表用每结点多一个指针（64 位环境约 8 字节）的空间，换来了「向前走」与两端 O(1) 的能力，空间代价的量化比较见 1.5 节。

## 例题讲解

### 例 1：双链表插入的四步链接顺序推导（难度：★★）

**题目**：在带头结点的循环双链表中，在结点 p 之前插入新结点 s。逐步画出四步链接后链表的变化；再给出一种错误顺序，分析其导致的丢链或成环后果。

**思路分析**：正确性分两层。只要求**最终状态正确**：第 4 步必须最后执行，第 1、2、3 步任意顺序皆可。若进一步要求「每一步执行之后链表都保持完整」（新结点 s 的两个指针先就位、旧链的指针后改写），则合法的只有 (1, 2, 3, 4) 与 (2, 1, 3, 4) 两种顺序——本节所有实现都采用这层更强的不变式。

**算法步骤**（链接变化图示，q 为 p 的原前驱）：

```text
初始:   … ↔ q ↔ p ↔ …          s: [prior| x | next] 尚未接入
第1步:  s->prior = q            → s 左指针就位
第2步:  s->next = p             → s 右指针就位
        此刻链上仍是 … ↔ q ↔ p ↔ …, s 与两侧互相可见但未入链
第3步:  q->next = s             → … ↔ q ↔ s → p ↔ …
第4步:  p->prior = s            → … ↔ q ↔ s ↔ p ↔ …   完成
```

错误顺序 (4, 3, 1, 2) 的变化：

```text
第4步:  p->prior = s            → p 的左指针指向 s
第3步:  p->prior->next = s      → 实际执行 s->next = s: s 右指针自环
第1步:  s->prior = p->prior     → p->prior 已是 s, 故 s->prior = s: 左指针也自环
第2步:  s->next = p             → 右指针被改写为 p, 但左指针仍指向 s
```

最终状态：`q->next` 仍指向 p，主链沿 next 方向尚可走通；但 `p->prior` 与 `s->prior` 都指向 s，prior 方向出现自环——从 p 或 s 沿 prior 遍历立即进入死循环，双向性被破坏；若第 2 步一直不执行，s 两个方向都自环，完全游离。另一种危险顺序是先执行第 3 步再执行第 2 步：`q->next = s` 之后、`s->next` 就位之前，从 q 出发暂时走不到 p——链处于断开状态（若第 2 步最终执行完，最终状态仍正确，但中间状态不堪一击：任何异常或并发读取都会让丢链固化）。这正是「先接新结点、后断旧链」的价值。

**C 实现**：即「算法与实现」一节的 `insert_before` 与 `delete_node`，此处不再重复；调用方式为 `insert_before(p, s)`，调用前需保证 s 尚未链接进任何链表。

**复杂度分析**：四步链接均为常数次指针赋值，与链表长度无关，最坏与平均同为 O(1) 时间、O(1) 额外空间——插入本身就是局部操作，不存在随 n 增长的路径。

**常见错误与变式**：

- 在 p **之后**插入是镜像四步：`s->next = p->next; s->prior = p; p->next->prior = s; p->next = s;`，同样遵循「先接新结点、后断旧链」；
- 删除结点后忘记 `free`：双链表结点含两个指针域，泄漏比单链表更浪费内存；
- 变式：带头结点的循环双链表删除表头结点 `L->next` 与删除普通结点代码完全相同，这是哨兵加循环的主要收益之一。

### 例 2：约瑟夫环（难度：★★）

**题目**：n 个人围成一圈，编号 1 到 n。从编号 1 的人开始报数，报到 m 的人出列，下一个人从 1 重新报数，如此循环，直到圈中只剩一人。用循环单链表模拟该过程，输出出列顺序与最后幸存者。演示 n = 8, m = 3。（说明：本站下标约定从 0 开始，但这里的编号是人员标签而非数组下标，习惯用 1..n；若坚持 0 起始，将编号整体减 1 即可，文末递推公式即采用 0 起始编号。）

**思路分析**：圈结构对应循环单链表：每个人是一个结点，报数对应指针沿 next 移动，出列对应删除结点。删除单链表结点需要前驱，因此让指针 cur 始终停在「待删结点的前驱」上：每轮从 cur 出发沿 next 移动 m − 1 次，`cur->next` 就是要出列的人；删除后 cur 恰好位于新一圈报数起点（原出列者的下一个）之前，无需复位。

**算法步骤**（伪代码）：

```text
输入: n, m（n ≥ 1, m ≥ 1）
创建循环单链表, 结点值为 1..n; cur 指向尾结点（即首结点的前驱）
while 圈中结点数 > 1:
    for i = 1 .. m-1:            // 报数 m-1 次
        cur = cur->next
    out = cur->next              // 出列者
    输出 out 的值
    cur->next = out->next        // 跨过 out
    free(out)
输出 cur 的值                    // 幸存者
```

**C 实现**：

```c
/* 约瑟夫环: 循环单链表模拟; n=8, m=3 时出列序列为 3 6 1 5 2 8 4, 幸存者 7 */
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;                  /* 人员编号 1..n */
    struct Node *next;
} Node;

/* 创建编号 1..n 的循环单链表, 返回尾结点指针 */
Node *create_circle(int n) {
    Node *head = NULL, *tail = NULL;
    int i;
    for (i = 1; i <= n; i++) {
        Node *p = (Node *)malloc(sizeof(Node));
        p->data = i;
        if (head == NULL) {
            head = p;
            p->next = p;       /* 单结点也成环 */
            tail = p;
        } else {
            p->next = head;    /* 新结点连回首结点 */
            tail->next = p;    /* 尾结点指向新结点 */
            tail = p;          /* 更新尾指针 */
        }
    }
    return tail;
}

int main(void) {
    int n = 8, m = 3;
    int k;
    Node *cur = create_circle(n);   /* cur 始终停在待删结点的前驱 */
    while (cur->next != cur) {      /* 环中仅剩一个结点时结束 */
        for (k = 1; k < m; k++)     /* 报数 m-1 次 */
            cur = cur->next;
        Node *out = cur->next;      /* 出列者 */
        printf("%d ", out->data);
        cur->next = out->next;      /* 跨过出列者 */
        free(out);                  /* 释放出列结点, 防止泄漏 */
    }
    printf("\n幸存者: %d\n", cur->data);
    free(cur);
    return 0;
}
```

**复杂度分析**：每轮出列一人需移动 m − 1 次指针，共出列 n − 1 人，总移动次数 (n − 1)(m − 1)，故最坏与平均均为 O(n·m)；空间 O(n)（n 个结点）。注意 m 也是输入规模：m 为常数时退化为 O(n)；m 可与 n 同阶（如 m = n），此时为 O(n²)。

**常见错误与变式**：

- 报数次数差一：报 m 数出列，指针只移动 m − 1 次（起点自身报 1）；
- 删除后忘记 `free`，或单结点链表未置自环；
- 变式（进阶，只提示不展开）：约瑟夫环存在 O(n) 的递推解法。设 $f(k)$ 为规模 k 时的幸存者编号（0 起始），有 $f(1) = 0$，$f(k) = (f(k-1) + m) \bmod k$，可在 O(n) 时间内求出幸存者；但出列顺序的完整模拟仍需 O(n·m)。

## 易错点

1. **四步链接顺序写反**：先断旧链再接新结点会造成丢链；先改 `p->prior` 再执行依赖它的第 3 步，会造成 s 自环、prior 方向死循环；
2. **删除后忘记 `free`**：链表结点含指针域，泄漏随操作次数线性累积；
3. **循环链表遍历写成死循环**：终止条件必须是与头结点比较（`p == L`），`p == NULL` 永远不会出现；
4. **判空条件随是否带头结点变化**：带头结点判 `L->next == L`，不带头结点判 `L == NULL`，混用会得到错误结果；
5. **把「循环」误当成「O(1) 定位」**：循环链表只是从任意结点可达全体，按位置定位仍是 O(n)。

## 小结

双链表用每结点一个前驱指针的空间，把「已知结点附近的修改」全部降为 O(1)，并解决了单链表删除尾结点 O(n) 的问题；循环链表用「首尾相接」换来了任意起点可达全体与尾指针表示法；静态链表展示了链式思想在无指针环境下的移植。三者共同的纪律是：链接操作先接新结点、后断旧链；删除及时 free；遍历与判空条件随结构形式变化而调整。
