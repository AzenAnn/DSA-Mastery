# 1.2 顺序表

## 学习目标

- 能说明顺序表的 `data`、`size` 与 `capacity`；
- 能解释随机访问为何是 `O(1)`；
- 能实现插入、删除和扩容；
- 能区分单次复杂度与摊还复杂度。

## 存储模型

顺序表把元素存放在一段连续空间中。`size` 表示已有元素数，`capacity` 表示当前可容纳的元素数，并保持 `0 ≤ size ≤ capacity`。

元素 `aᵢ` 的地址可以由起始地址和下标直接计算，因此按下标访问是 `O(1)`。但在中间插入或删除时，需要移动后续元素。

## 核心操作

插入位置 `i` 时：

1. 检查 `0 ≤ i ≤ size`；
2. 若空间已满，申请更大的连续空间并搬移元素；
3. 从后向前移动区间 `[i, size)`；
4. 写入新元素并增加 `size`。

删除位置 `i` 时，将区间 `(i, size)` 向前移动一格，再减少 `size`。移动方向错误会覆盖尚未搬走的数据。

## 复杂度

| 操作 | 复杂度 |
| --- | --- |
| 按下标访问/修改 | `O(1)` |
| 按值查找 | `O(n)` |
| 中间插入/删除 | `O(n)` |
| 尾部追加 | 通常为摊还 `O(1)`，扩容当次为 `O(n)` |
| 额外空间 | 由未使用容量和扩容策略决定 |

## 易错点

- 混淆 `size` 与 `capacity`；
- 扩容后忘记更新底层存储引用；
- 插入搬移时从前向后覆盖数据；
- 删除后仍访问逻辑长度之外的旧元素；
- 空表或表尾位置的下标判断差一。

## 小结

顺序表用连续空间换取快速随机访问与良好局部性。它的主要代价是中间修改需要搬移元素，以及动态扩容偶尔产生的整体复制。

## 练习

1. 画出在 `[10, 20, 30]` 的位置 `1` 插入 `15` 的搬移过程。
2. 为什么倍增扩容能使多次尾部追加具有摊还 `O(1)` 复杂度？
3. 顺序表删除元素后是否应该立刻缩容？列出一个利与一个弊。
