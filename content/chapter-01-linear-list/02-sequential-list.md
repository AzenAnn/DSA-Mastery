# 1.2 顺序表

## 学习目标

- 说清顺序表的三要素 `data`、`size`、`capacity` 与不变量 $0\le \mathrm{size}\le \mathrm{capacity}$；
- 由地址公式解释随机访问 $O(1)$ 的原理，并区分「按下标访问」与「按值查找」的本质差别；
- 用伪代码与 C 语言实现顺序表的初始化、销毁、读写、查找、插入与删除；
- 推导插入、删除的平均移动次数，并用聚合分析与记账法证明倍增扩容的摊还 $O(1)$。

## 引入

任何一门语言都提供数组。在 C 语言中，`a[i]` 被编译成 `*(a + i)`：编译器根据「起始地址 + 下标 × 元素大小」一步算出目标地址，不做任何比较。按下标访问天然是常数时间——这正是顺序表最根本的优势。

但裸数组有两个问题：其一，**容量固定**——`int a[100]` 声明之后表长不能超过 100，插满第 101 个元素时要么报错，要么手工搬到更大的数组，谁来负责、什么时候搬？其二，**中间插入贵**——在数组中间插入一个元素，它后面的所有元素都必须整体后移一格，为什么不能避免？这要付出多大代价？

顺序表（sequential list）就是对数组的封装：它把「元素个数」与「已分配容量」作为状态记录在结构体里，把「搬到更大的数组」做成自动扩容，把「移动元素」的代价量化清楚。上一节 [1.1 线性表的抽象数据类型](./01-definition-and-adt.md) 定义了操作契约，本节实现其中的顺序表存储方式；下一节 [1.3 单链表](./03-singly-linked-list.md) 将给出另一种实现，两者契约相同而代价结构完全不同。本章总览见 [00 章前导读](./00-overview.md)。

## 概念与理论

**三要素**。顺序表用一段连续的内存存放元素，并用三个字段描述状态：

- `data`：指向连续存储区的指针，第 $i$ 个元素存放在 `data[i]`；
- `size`：当前**实际**元素个数（逻辑长度）；
- `capacity`：当前**已分配**存储区可容纳的元素个数（物理容量）。

三者必须满足不变量

$$0\le \mathrm{size}\le \mathrm{capacity}.$$

为什么要求 $\mathrm{size}\le \mathrm{capacity}$？因为 `data` 只分配了 `capacity` 个位置，超出即越界写，属于未定义行为。为什么允许 $\mathrm{size}<\mathrm{capacity}$？预留的空位使插入不必每次扩容，是「空间换时间」的代价。

**下标约定**。本站统一从 0 开始记下标：$L=(a_0,a_1,\dots,a_{n-1})$，元素个数为 $n$。严蔚敏教材从 1 开始：$L=(a_1,a_2,\dots,a_n)$，对照关系是本站的 $a_i$ 即严书的 $a_{i+1}$，阅读严书时注意换算，特别是地址公式。

**地址公式与随机访问**。设每个元素占 $d$ 字节。元素连续存放，第 $i$ 个元素之前恰好有 $i$ 个元素，共占 $i\cdot d$ 字节，因此

$$\mathrm{Loc}(a_i)=\mathrm{Loc}(a_0)+i\cdot d.$$

即「起始地址 + 下标 × 元素大小」。这是一次乘加运算，与表长 $n$ 无关，所以按下标访问（get/set）是 $O(1)$——这就是随机访问（random access）的原理：下标本身携带位置信息，地址可以直接算出。严蔚敏教材从 1 起始，对应公式为 $\mathrm{Loc}(a_i)=\mathrm{Loc}(a_1)+(i-1)\cdot d$，形式略繁琐，本质相同：一个下标偏移对应一个固定的字节偏移。

**与按值查找的本质区别**。按值查找（find）不知道目标在哪个下标，只能从 `data[0]` 开始逐个与目标比较，最坏情况要比较 $n$ 次，代价 $O(n)$。对比两件事：

- 按下标访问：**算**——地址由下标用公式算出，常数时间；
- 按值查找：**比**——不知道位置，只能逐个试探，线性时间。

「能算就不必比」是顺序表最重要的直觉。代价是：插入和删除要搬移元素，见下一节。

## 算法与实现

先给出结构定义与生命周期管理，再逐个实现操作。伪代码与 C 对照给出；C 代码以 `int` 为元素类型，实践中可用 `typedef int ElemType;` 泛化为任意类型，所有操作不变。

**结构定义与初始化、销毁**。`data` 指向堆上分配的连续空间，`init` 负责分配初始容量，`destroy` 负责归还：

```text
SeqList:
    data      // 指向连续存储区（堆上分配）
    size      // 当前元素个数
    capacity  // 已分配容量

init(L, 初始容量 c):
    L.data ← 分配 c 个元素大小的空间
    L.size ← 0
    L.capacity ← c

destroy(L):
    释放 L.data 指向的空间
    L.data ← NULL; L.size ← 0; L.capacity ← 0
```
```c
#include <stdlib.h>   /* malloc / free */

#define INIT_CAPACITY 4

/* 元素类型可用 typedef int ElemType; 泛化,后续代码只需替换 int */
typedef struct {
    int *data;      /* 指向堆上分配的连续存储区 */
    int size;       /* 当前元素个数(逻辑长度) */
    int capacity;   /* 已分配容量(物理上限) */
} SeqList;

/* 初始化:分配初始容量 */
void init(SeqList *L) {
    L->data = (int *)malloc(INIT_CAPACITY * sizeof(int));
    L->size = 0;
    L->capacity = INIT_CAPACITY;
}

/* 销毁:释放存储区,并置空防止野指针 */
void destroy(SeqList *L) {
    free(L->data);
    L->data = NULL;
    L->size = 0;
    L->capacity = 0;
}
```

**get 与 set**。地址公式保证两者都是常数时间，唯一的开销是越界检查：

```text
get(L, i):    if 0 ≤ i < L.size 返回 L.data[i],否则返回失败
set(L, i, x): if 0 ≤ i < L.size 令 L.data[i] ← x,否则返回失败
```
```c
/* 读取位置 i 的元素,越界返回 0 */
int get(SeqList *L, int i, int *out) {
    if (i < 0 || i >= L->size) return 0;   /* 访问合法域:0 <= i < size */
    *out = L->data[i];                     /* 地址公式,常数时间 */
    return 1;
}

/* 修改位置 i 的元素,越界返回 0 */
int set(SeqList *L, int i, int x) {
    if (i < 0 || i >= L->size) return 0;
    L->data[i] = x;
    return 1;
}
```

**按值查找（含哨兵优化）**。普通写法每轮循环都要检查 `i < size`。哨兵优化把目标暂存表尾 `data[size]`，循环必然终止，从而省掉边界判断：

```text
find(L, x):
    L.data[L.size] ← x            // 哨兵暂存表尾,循环必然终止
    i ← 0
    while L.data[i] ≠ x: i ← i+1  // 免去每次 i < size 判断
    if i < L.size: 返回 i         // 命中
    else: 返回未找到              // 停在哨兵处
```
```c
/* 返回 x 首次出现的位置;未找到返回 -1。需 size < capacity(表尾有空位) */
int find(SeqList *L, int x) {
    L->data[L->size] = x;          /* 哨兵:暂存表尾 */
    int i = 0;
    while (L->data[i] != x) i++;   /* 循环内少一次越界判断 */
    return (i < L->size) ? i : -1; /* i == size 说明表内没有 x */
}
```

哨兵优化的原理：把目标拷贝到 `data[size]`，循环必然在 $i\le \mathrm{size}$ 处终止，只多一次（失败的）比较。注意它要求表尾有空位（$\mathrm{size}<\mathrm{capacity}$）；若表满，需先扩容或改用带边界检查的普通写法。

**insert**。三个步骤：检查合法域 $0\le i\le \mathrm{size}$ → 已满则扩容 → 从后向前搬移区间 $[i,\mathrm{size})$ 腾出位置：

```text
insert(L, i, x):       // 合法域:0 ≤ i ≤ size,插到位置 i 之前;i = size 为表尾
    if i < 0 or i > L.size: 返回失败
    if L.size = L.capacity: grow(L)   // 已满,先扩容
    for j = L.size-1 down to i:       // 从后向前搬移 [i, size)
        L.data[j+1] ← L.data[j]
    L.data[i] ← x
    L.size ← L.size + 1
```
```c
/* 扩容:容量倍增(容量为 0 时按 1 起步);成功返回 1,分配失败返回 0 且保持原状 */
static int grow(SeqList *L) {
    int newCap = (L->capacity == 0) ? 1 : L->capacity * 2;
    int *p = (int *)malloc(newCap * sizeof(int));
    if (p == NULL) return 0;         /* 分配失败:保持原状,由调用方上报错误 */
    for (int j = 0; j < L->size; j++)
        p[j] = L->data[j];           /* 把旧元素整体搬到新空间 */
    free(L->data);                   /* 释放旧存储区,避免内存泄漏 */
    L->data = p;
    L->capacity = newCap;
    return 1;
}

/* 在位置 i 之前插入 x;成功返回 1 */
int insert(SeqList *L, int i, int x) {
    if (i < 0 || i > L->size) return 0;                 /* 插入合法域:0 <= i <= size */
    if (L->size == L->capacity && !grow(L)) return 0;   /* 满则扩容;扩容失败则放弃插入 */
    for (int j = L->size - 1; j >= i; j--)
        L->data[j + 1] = L->data[j];      /* 从后向前搬移,腾出位置 i */
    L->data[i] = x;
    L->size++;
    return 1;
}
```

**为什么必须从后向前搬移**。以在 `[10, 20, 30]` 的位置 1 插入 15 为例（`_` 表示空位，容量至少 4）：

```text
第 0 步  下标: 0    1    2    3
         值:  10   20   30   _
第 1 步  从后向前,先把 30 后移:
         值:  10   20   30   30
第 2 步  再把 20 后移:
         值:  10   20   20   30
第 3 步  写入 15,size 变为 4:
         值:  10   15   20   30
```

如果反过来从前向后搬：先把 `data[1]=20` 移到 `data[2]`，就把 30 覆盖了，再搬时 `data[2]` 已经不是原来的 30——**后面的数据先被覆盖**，顺序表被破坏。搬移方向必须与数据流动方向相反：插入时数据向后流动，所以从后往前；删除时数据向前流动，所以从前往后。

**remove**。删除位置 $i$ 后，把区间 $(i,\mathrm{size})$ 向前搬移一格覆盖被删位置，再令 `size--`：

```text
remove(L, i):          // 合法域:0 ≤ i < size
    if i < 0 or i ≥ L.size: 返回失败
    x ← L.data[i]                     // 取出被删元素
    for j = i to L.size-2:            // 把 (i, size) 向前搬移一格
        L.data[j] ← L.data[j+1]
    L.size ← L.size - 1
    返回 x
```
```c
/* 删除位置 i 的元素并通过 out 返回其值;成功返回 1 */
int removeAt(SeqList *L, int i, int *out) {
    if (i < 0 || i >= L->size) return 0;   /* 删除合法域与访问一致:0 <= i < size */
    if (out) *out = L->data[i];
    for (int j = i; j < L->size - 1; j++)
        L->data[j] = L->data[j + 1];       /* 从前往后搬移,覆盖被删位置 */
    L->size--;                             /* 别忘了减小长度 */
    return 1;
}
```

删除是插入的镜像：数据向前流动一格，覆盖被删元素；末位的旧值成为「死数据」，不参与任何操作（`size` 不再包含它），下次插入时会被覆盖。

## 复杂度分析

**get / set：$O(1)$**。由地址公式 $\mathrm{Loc}(a_i)=\mathrm{Loc}(a_0)+i\cdot d$，一次乘加即可定位，与 $n$ 无关。

**按值查找：成功平均 $\frac{n+1}{2}$ 次比较，失败 $n$ 次**。若目标位于第 $k$ 个位置（$1\le k\le n$，按比较顺序计），需要 $k$ 次比较。假设目标等概率出现在每个位置，期望比较次数为 $\frac{1}{n}\sum_{k=1}^{n}k=\frac{1}{n}\cdot\frac{n(n+1)}{2}=\frac{n+1}{2}$。失败时扫描完整个表，$n$ 次比较（哨兵版多一次与哨兵的比较，为 $n+1$，数量级不变）。

**insert：最好 0 次移动，最坏 $n$ 次，平均 $\frac{n}{2}$ 次**。在位置 $i$ 插入需搬移 $[i,\mathrm{size})$ 共 $n-i$ 个元素：表尾（$i=n$）0 次，表头（$i=0$）$n$ 次。若插入位置等概率取 $0,1,\dots,n$（共 $n+1$ 个位置），期望移动次数为 $E_{\mathrm{ins}}=\frac{1}{n+1}\sum_{i=0}^{n}(n-i)=\frac{1}{n+1}\cdot\frac{n(n+1)}{2}=\frac{n}{2}$。

**remove：最好 0 次移动，最坏 $n-1$ 次，平均 $\frac{n-1}{2}$ 次**。删除位置 $i$ 需搬移 $(i,\mathrm{size})$ 共 $n-1-i$ 个元素：删表尾（$i=n-1$）0 次，删表头（$i=0$）$n-1$ 次。若删除位置等概率取 $0,1,\dots,n-1$（共 $n$ 个位置），期望移动次数为 $E_{\mathrm{del}}=\frac{1}{n}\sum_{i=0}^{n-1}(n-1-i)=\frac{1}{n}\cdot\frac{(n-1)n}{2}=\frac{n-1}{2}$。

结论：**中间插入、删除的代价与表长成正比**，这是顺序表的固有代价；而插入还隐藏着「满则扩容」的成本，单次插入可能达到 $O(n)$，见下一节。

## 动态扩容与摊还分析

本节是理论重点。问题：反复在表尾插入（append），当 $\mathrm{size}=\mathrm{capacity}$ 时需要扩容搬移，单次最坏 $O(n)$。频繁插入时总代价到底是多少？取决于扩容策略。

**固定增量 $c$ 扩容：总代价 $O(n^2)$，不可接受**。假设容量不足时一次性增加 $c$ 个空位。大约每插入 $c$ 个元素触发一次扩容，共约 $\lfloor n/c\rfloor$ 次；第 $k$ 次扩容时已有约 $kc$ 个元素，需搬移 $kc$ 个。总搬移量为

$$c\cdot\sum_{k=1}^{\lfloor n/c\rfloor}k \approx c\cdot\frac{(n/c)^2}{2}=\frac{n^2}{2c}=O(n^2/c).$$

摊还到每次插入为 $O(n^2/c)/n=O(n/c)$；$c$ 是常数时即为 $O(n)$。也就是说，用固定增量扩容，**$n$ 次插入的总代价是 $O(n^2)$**，与「每次插入都重排全表」没有本质区别，摊还分析没有带来任何改善。把 $c$ 调大只能缩小常数，不改变量级，且会浪费最多 $c$ 个空位。

**倍增扩容：总代价 $O(n)$，摊还 $O(1)$**。容量不足时翻倍。设初始容量 1，容量序列为 $1,2,4,\dots,2^k$。插入第 2 个元素时复制 1 个，插入第 3 个时复制 2 个，插入第 5 个时复制 4 个……插入 $n$ 个元素后容量翻倍了 $k$ 次（$2^{k-1}<n\le 2^k$），总复制次数为

$$1+2+4+\cdots+2^{k-1}=2^k-1<2n.$$

加上 $n$ 次写入本身，$n$ 次插入的总代价

$$\text{总代价}<n+2n=3n=O(n),$$

平均每次 $O(1)$。这是摊还分析的第一种证法——**聚合分析（aggregate analysis）**：先算出任意 $n$ 次操作的总代价上界，再除以 $n$。注意「总代价 $<3n$」不依赖任何概率假设，对任意插入序列成立。

**记账法（accounting method）**是第二种证法，也更有解释力。设想每次插入收费 3 元：1 元支付本次写入，2 元作为「信用」存入。当容量从 $m$ 翻倍到 $2m$ 时，需要搬移 $m$ 个元素，费用 $m$ 元；而自上次扩容（容量 $m/2$）以来恰好插入了 $m/2$ 个元素，累计信用 $m$ 元，正好付清这次搬移。首次扩容（容量 1→2）只搬 1 个元素，而第一个元素插入时存了 2 元，也足够。由归纳法，**信用余额恒非负**，故 3 元/次的总收费 $3n$ 是任意 $n$ 次操作总代价的上界，摊还 $O(1)$。这正是 CLRS §17.4「动态表」的论证思路。

**摊还 ≠ 平均，务必辨析**。平均复杂度对**输入分布**取期望（如上一节「插入位置等概率」的假设），摊还分析不假设任何概率，是对**任意操作序列**的确定性保证；单次插入的最坏情况仍是 $O(n)$——某次扩容当次确实要搬移 $n$ 个元素，摊还分析并不否认这一点。摊还 $O(1)$ 的准确含义是：**任意 $n$ 次操作的总代价为 $O(n)$**，偶发的昂贵操作被频繁的廉价操作「消化」了。

**缩容问题（提一句）**。删除使 $\mathrm{size}$ 缩小后，若永远不缩容，容量可能长期浪费；若 $\mathrm{size}<\mathrm{capacity}/2$ 就立即减半，则插入删除在边界附近反复触发扩容-缩容，每次 $O(n)$，「抖动」抵消了摊还收益。标准做法是**延迟缩容**：只在负载因子 $\alpha=\mathrm{size}/\mathrm{capacity}$ 低于下界 $\frac14$ 时才减半——满时倍增、低于 $\frac14$ 时减半，两条规则共同保证 $\alpha$ 始终落在 $[\frac14,1]$（倍增发生在 $\alpha=1$，减半发生在 $\alpha\approx\frac14$，减半后 $\alpha\approx\frac12$），摊还 $O(1)$ 依然成立（思想见 CLRS 练习 17.4-2）。本节不展开完整证明。

## 例题讲解

### 例 1：在位置 1 插入 15（难度：★）

**题目**。顺序表 `[10, 20, 30]` 中在位置 1（下标从 0 计）插入 15，写出搬移过程，并推导等概率下插入的平均移动次数公式。

**思路分析**。位置 1 在 10 与 20 之间。插入使 $[1,\mathrm{size})$ 即 20、30 各后移一格，腾出 `data[1]` 再写入 15。

**算法步骤（伪代码）**。

```text
i = 1, x = 15, n = 3
for j = n-1 down to i: data[j+1] ← data[j]   // 从最后开始依次后移
data[1] ← 15
size ← 4
```

**C 实现**（展开循环体，调用前已保证 $0\le i\le \mathrm{size}$ 且表未满）：

```c
/* 在位置 i 之前插入 x 的循环体演示:data[3]←30, data[2]←20, data[1]←15 */
void insertDemo(SeqList *L) {
    int i = 1, x = 15;
    for (int j = L->size - 1; j >= i; j--)
        L->data[j + 1] = L->data[j];   /* 从后向前搬移 */
    L->data[i] = x;                    /* 写入新元素 */
    L->size++;                         /* 3 → 4 */
}
```

**复杂度分析**。本例搬移 $n-i=2$ 个元素。一般地，在位置 $i$ 插入搬移 $n-i$ 个：表头 $i=0$ 时最坏 $n$ 个，表尾 $i=n$ 时 0 个。插入位置等概率取 $n+1$ 个值时，平均移动次数 $E_{\mathrm{ins}}=\frac{1}{n+1}\sum_{i=0}^{n}(n-i)=\frac{1}{n+1}\cdot\frac{n(n+1)}{2}=\frac{n}{2}$，即最坏 $O(n)$、平均 $O(n)$。

**常见错误与变式**。搬移方向写反会覆盖 30；忘记 `size++` 导致逻辑长度不变；`i` 超出 $[0,n]$ 未检查会写坏内存。变式：若表已满，插入前须先扩容（见第 4 节 `grow`）。

### 例 2：顺序表就地逆置（难度：★）

**题目**。将顺序表就地（in-place）逆置，如 `[1,2,3,4,5]` 变为 `[5,4,3,2,1]`。要求 $O(n)$ 时间、$O(1)$ 额外空间。

**思路分析**。首尾对称交换：`data[i]` 与 `data[n-1-i]` 互换。只需遍历前半段（$i<n/2$），后半段随交换自动就位。

**算法步骤（伪代码）**。

```text
reverse(L):
    for i = 0 to ⌊L.size/2⌋ - 1:
        交换 L.data[i] 与 L.data[L.size-1-i]
```

**C 实现**。

```c
void reverse(SeqList *L) {
    for (int i = 0; i < L->size / 2; i++) {
        int t = L->data[i];                    /* 交换 data[i] 与 data[n-1-i] */
        L->data[i] = L->data[L->size - 1 - i];
        L->data[L->size - 1 - i] = t;
    }
}
```

**复杂度分析**。交换 $\lfloor n/2\rfloor$ 次，每次 $O(1)$：时间 $O(n)$；只用了常数个临时变量，空间 $O(1)$。

**常见错误与变式**。循环边界写成 `i < L.size` 会把每对元素交换两次、白做一遍；$n$ 为奇数时中间元素（`data[n/2]`）不动，是正确的。变式：**循环左移 $k$ 位**可用「三次逆置」完成——先逆置前 $k$ 个、再逆置后 $n-k$ 个、最后整体逆置，时间 $O(n)$、空间 $O(1)$。

### 例 3：删除所有值为 x 的元素（难度：★★）

**题目**。删除顺序表中所有值为 `x` 的元素，要求一趟扫描完成，时间 $O(n)$、额外空间 $O(1)$。

**思路分析**。朴素做法是反复「find + remove」：find 平均 $O(n)$，remove 平均 $O(n)$，删除 $k$ 个元素总代价 $O(kn)=O(n^2)$。改进：用两个游标一趟扫描——**读游标** `r` 遍历全表，**写游标** `w` 指向下一个保留元素的落点；`data[r] != x` 时把它写到 `data[w]` 并前进 `w`。扫描结束，`w` 就是新逻辑长度。每个元素至多被写一次，故 $O(n)$。

**算法步骤（伪代码）**。

```text
removeAll(L, x):
    w ← 0                              // 写游标
    for r = 0 to L.size-1:             // 读游标扫描全表
        if L.data[r] ≠ x:
            L.data[w] ← L.data[r]
            w ← w + 1
    L.size ← w
```

**C 实现**。

```c
/* 删除所有值为 x 的元素,返回被删个数 */
int removeAll(SeqList *L, int x) {
    int w = 0;                           /* 写游标:下一个保留元素的落点 */
    for (int r = 0; r < L->size; r++) {  /* 读游标:扫描全表 */
        if (L->data[r] != x)
            L->data[w++] = L->data[r];   /* 保留元素向前聚集 */
    }
    int removed = L->size - w;           /* 被删个数 */
    L->size = w;                         /* 新逻辑长度 = 保留元素个数 */
    return removed;
}
```

**复杂度分析**。循环执行 $n$ 次，每次常数操作；写游标累计至多写 $n$ 次。最坏（全表都是 $x$）与平均（任意比例）均为 $O(n)$ 时间、$O(1)$ 额外空间，且不触发扩容。

**常见错误与变式**。忘记在保留分支里递增 `w` 会让保留元素互相覆盖；把条件写成 `== x` 则变成「只留 x」。变式：**顺序表去重**——对有序表，只需与「写游标前一个元素」比较即可一趟去重；对无序表，先排序再去重，代价为排序的 $O(n\log n)$。

### 例 4：合并两个有序顺序表（难度：★★）

**题目**。两个升序顺序表 `A`、`B` 合并为一个升序顺序表 `C`，要求时间 $O(n+m)$，空间 $O(n+m)$。

**思路分析**。双指针 `i`、`j` 分别指向 `A`、`B` 当前最小的未取元素，每次取较小者写入 `C` 并前进对应指针；一方耗尽后，另一方的余下部分整体续接。相等时取 `A` 的元素，保持稳定。

**算法步骤（伪代码）**。

```text
merge(A, B):
    C ← 分配 A.size + B.size 个元素的空间
    i ← 0; j ← 0; k ← 0
    while i < A.size and j < B.size:          // 双指针取较小者
        if A.data[i] ≤ B.data[j]: C.data[k] ← A.data[i]; i ← i+1
        else: C.data[k] ← B.data[j]; j ← j+1
        k ← k+1
    while i < A.size: C.data[k] ← A.data[i]; i ← i+1; k ← k+1  // 收尾
    while j < B.size: C.data[k] ← B.data[j]; j ← j+1; k ← k+1
    C.size ← k
    返回 C
```

**C 实现**。

```c
/* 合并两个升序表,返回新的升序表(调用方负责 destroy) */
SeqList merge(const SeqList *A, const SeqList *B) {
    SeqList C;
    C.size = A->size + B->size;
    C.capacity = C.size;
    C.data = (int *)malloc(C.capacity * sizeof(int));
    int i = 0, j = 0, k = 0;
    while (i < A->size && j < B->size) {      /* 双指针取较小者 */
        if (A->data[i] <= B->data[j])
            C.data[k++] = A->data[i++];       /* 相等时取 A,保持稳定 */
        else
            C.data[k++] = B->data[j++];
    }
    while (i < A->size) C.data[k++] = A->data[i++];  /* 收尾 */
    while (j < B->size) C.data[k++] = B->data[j++];
    return C;
}
```

**复杂度分析**。每个元素恰好被比较并写入一次：时间 $O(n+m)$。结果表需要 $n+m$ 个位置：空间 $O(n+m)$。

**常见错误与变式**。漏写两个收尾循环，会丢掉 `A` 或 `B` 的剩余元素；相等元素取 `A`（用 `<=`）保证稳定，换成 `<` 结果仍有序但来源互换；分配结果表失败未处理。变式：求两个有序表的交集，同样用双指针一趟扫描，时间 $O(n+m)$。

### 例 5：倍增扩容的摊还核算（难度：★★★）

**题目**。初始容量 1、倍增扩容。列出插入第 1 到第 8 个元素时，各自发生的复制代价与累计复制代价；计算 8 次插入的平均总代价，并与摊还上界 3 对照解释。

**思路分析**。复制只发生在「表满」的那几次插入：插入第 2 个（容量 1→2）、第 3 个（2→4）、第 5 个（4→8）时，复制次数分别为 1、2、4。其余插入无复制。

**算法步骤（伪代码）**。

```text
size ← 0; cap ← 1; total ← 0
for k = 1 to 8:
    cost ← 0
    if size = cap:             // 触发扩容
        cost ← size; cap ← cap × 2   // 复制全部老元素,容量翻倍
    size ← size + 1
    total ← total + cost
    输出第 k 次插入的 cost 与 total
```

**C 实现**（模拟并输出每次的复制代价）：

```c
#include <stdio.h>

int main(void) {
    int cap = 1, size = 0, total = 0;
    for (int k = 1; k <= 8; k++) {
        int cost = 0;
        if (size == cap) {      /* 满则扩容:复制 size 个老元素 */
            cost = size;
            cap *= 2;
        }
        size++;                 /* 写入新元素本身不计入复制 */
        total += cost;
        printf("插入第 %d 个:本次复制 %d,累计复制 %d\n", k, cost, total);
    }
    return 0;
}
```

**核算表**（运行上述程序可得，也可手工推演）：

| 插入序号 $k$ | 是否扩容 | 本次复制代价 | 累计复制代价 |
| --- | --- | --- | --- |
| 1 | 否 | 0 | 0 |
| 2 | 是（1→2） | 1 | 1 |
| 3 | 是（2→4） | 2 | 3 |
| 4 | 否 | 0 | 3 |
| 5 | 是（4→8） | 4 | 7 |
| 6 | 否 | 0 | 7 |
| 7 | 否 | 0 | 7 |
| 8 | 否 | 0 | 7 |

**复杂度分析**。8 次插入总复制 7 次，加上 8 次写入，总代价 15，平均 $15/8\approx 1.88<3$，摊还上界成立且偏保守；聚合分析中的 $2n$ 来自 $2^k-1<2n$，此处 $7<16$。单次最坏发生在第 5 次插入（复制 4 个老元素，当次 $O(n)$），但 8 次平均远小于 3——偶发的昂贵扩容被廉价插入消化，正是摊还 $O(1)$ 的含义。若继续插入到第 16 个元素，累计复制 $1+2+4+8=15$，仍满足 $<2n$。

## 易错点

1. **混淆 `size` 与 `capacity`**。遍历、查找、打印一律用 `size`（逻辑长度），只有分配才涉及 `capacity`；用 `capacity` 当长度会读到从未写入的垃圾值，用 `size` 当容量则越界写。
2. **扩容后旧指针未释放或引用未更新**。`grow` 把 `data` 指向新空间后必须 `free` 旧空间，否则泄漏；任何在扩容前拿到的 `data` 指针在扩容后失效，必须重新取 `L->data`。
3. **搬移方向写反**。插入必须从后向前、删除必须从前向后；方向反了会先覆盖未搬走的数据（见「为什么必须从后向前搬移」）。
4. **删除后忘记 `size--`**。逻辑长度虚高，表尾旧值会再次参与遍历与查找，后续插入还会把数据写进本应「已删除」的区域。
5. **插入合法域与访问合法域混用**。插入允许 $0\le i\le n$（$i=n$ 是表尾插入），访问与删除只允许 $0\le i<n$。把 $i=n$ 传给 `get` 或 `remove` 会越界。

## 小结

顺序表用一段连续存储换取两件事：常数时间的随机访问（地址公式「算」出位置）与良好的缓存局部性（元素相邻存放）。代价同样明确：中间插入、删除平均要搬移 $\frac n2$、$\frac{n-1}{2}$ 个元素，单次 $O(n)$；按值查找只能逐个比较，$O(n)$。动态扩容必须用倍增策略，聚合分析与记账法都能证明任意 $n$ 次插入总代价 $O(n)$、摊还 $O(1)$，但单次最坏仍是 $O(n)$。选择哪种存储方式取决于操作分布，[1.5 存储结构的比较与选择](./05-comparison-and-selection.md) 将给出系统对比。
