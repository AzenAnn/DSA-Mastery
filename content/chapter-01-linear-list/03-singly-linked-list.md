# 1.3 单链表

## 学习目标

- 能画出单链表的结点结构与链接关系，说出头结点的作用与判空条件；能实现头插法、尾插法建表，以及按位查找、按值查找、插入与删除；
- 能把任意操作拆成「定位」与「改链」两步并给出正确的复杂度；能运用双指针（先行指针、快慢指针）解决倒数第 k 个、求中点等扫描问题。

## 引入

上一节的顺序表把元素放进一段连续空间，换来 $O(1)$ 的随机访问，但留下了两个难以回避的问题：一是容量难预估，空间不够时只能申请更大空间并把全部元素搬移过去；二是中间插入或删除要把后续元素逐个搬移，最坏要移动 $O(n)$ 个元素（见 [1.2 顺序表](./02-sequential-list.md)）。如果应用的主要操作是「表头增删、按顺序遍历」，顺序表的优势用不上，搬移成本却一分不少。链式思想正是针对这两个痛点：放弃物理上的连续存放，让每个元素独立成一个**结点**，结点可以分散在内存的任何位置，结点内用一个**链接**（指针）指明下一个结点在哪里，元素之间的顺序关系完全由链接表达。于是插入和删除只改链接、不搬元素，容量也按需逐个申请结点，不再有大块搬移。代价是失去了随机访问：要访问第 $i$ 个元素，只能从头顺着链接逐个走。本章后续的双链表、循环链表与静态链表都是这一思想的变体（[04 节](./04-doubly-circular-static-list.md)）；Knuth 在《计算机程序设计艺术》第 1 卷 §2.2 系统梳理了链表分配方法的历史与各种变体。

## 概念与理论

**结点结构。** 单链表的基本单位是结点，包含数据域与指针域：

```c
/* 单链表结点：数据域 + 指针域 */
typedef struct LNode {
    int data;              /* 数据域：此处为 int，可用 typedef ElemType 泛化为任意类型 */
    struct LNode *next;    /* 指针域：指向下一个结点 */
} LNode;
```

两点说明。第一，结构体内部必须写 `struct LNode *next` 而不能写 `LNode *next`——typedef 名字 `LNode` 要到结构体定义结束后才生效，这称为**自引用结构体**，C 语言只能通过 `struct` 标签完成。第二，C 中结构体标签与 typedef 名分属不同命名空间，`struct LNode` 与 `LNode` 可以共存；不用 typedef 时引用处写作 `struct LNode *p`，严蔚敏教材即采用 typedef 简写（严蔚敏 §2.3.1）。

**头指针与链表示意。** 用一个指针 `head` 指向链表的第一个结点，称为**头指针**；链表的结束用空指针 `NULL` 标记。存储示意：

```text
head → [A|next] → [B|next] → [C|next] → NULL
```

方括号表示一个结点，左侧是数据，右侧是链接。结点 A、B、C 的物理地址可以互不相邻，线性顺序完全由 `next` 域串起来。要访问 C，必须先经过 A、B——这就是「顺序表 $O(1)$ 访问，链表 $O(n)$ 访问」的结构根源。

**头结点（哨兵）专题。** 「第一个结点由谁指出」有两种约定，务必一开始就分清。**带头结点**：`head` 指向一个不存业务数据的哨兵结点，真正的首元结点是 `head->next`；空表判定为 `head->next == NULL`，表头插入与表头删除时前驱就是 `head`，与中间操作共用同一段代码，无需任何特判；严蔚敏 §2.3.1 与王道 2.3 均采用这一约定，是国内教材的主流。**不带头结点**：`head` 直接指向首元结点，空表判定为 `head == NULL`，表头插入或删除首元结点时必须特判「链表是否为空」「删除后 `head` 是否变为 `NULL`」，代码出现分支；Sedgewick & Wayne《Algorithms》§1.3 用裸 `first` 引用直接指向首结点，属于这一风格。

头结点的代价是一个不存数据的结点空间；收益是判空条件统一为 `head->next == NULL`，表头操作与中间操作代码完全同构、没有特判分支。两者都是合法的工程选择，**关键是在整个程序里保持一致**。本教程约定：**全文实现一律采用带头结点的单链表**，除非某道例题明确说明；文中「链表长度 $n$」均指首元结点的个数，不含头结点。

## 算法与实现

本节的 C 代码默认已经包含标准头文件（`malloc`/`free` 来自 `<stdlib.h>`）以及前文定义的 `LNode`。为便于阅读，代码以「定位 + 改链」为主线：先讲清楚每个操作的两个环节。

**建表：头插法与尾插法。** 从输入序列建立链表有两种基本方法。头插法把每个新结点插到头结点之后，先插入的结点被后来者挤出首元位置，结果与输入顺序**相反**；尾插法把新结点接到表尾，借助尾指针 `tail` 保持输入顺序；两种方法每步 $O(1)$，建表总成本 $O(n)$，完整 C 实现见例 1。

```text
// 头插法：新结点总插在头结点之后
head ← 新建头结点
对每个输入元素 x：
    新建结点 p，p.data ← x
    p.next ← head.next      // 先接住原首元结点
    head.next ← p

// 尾插法：新结点总接在表尾，维护尾指针 tail
head ← 新建头结点；tail ← head     // 初始时头结点即表尾
对每个输入元素 x：
    新建结点 p，p.data ← x，p.next ← NULL
    tail.next ← p           // 接到当前表尾之后
    tail ← p                // 尾指针后移
```

**查找：按位与按值。** 单链表没有下标，查找只能从头遍历。位序约定与本站一致从 0 开始：第 0 个结点即首元结点。严蔚敏教材从 1 开始计数（「第 1 个结点」是首元结点），只是记号差异，做题与阅读时注意换算（严蔚敏 §2.3.1）。

```text
// 按位查找：返回第 i 个结点（i 从 0 开始）
p ← head.next               // 从首元结点出发
j ← 0
当 p ≠ NULL 且 j < i：p ← p.next；j ← j + 1
返回 p                      // 越界时返回 NULL

// 按值查找：返回第一个 data = x 的结点
p ← head.next
当 p ≠ NULL 且 p.data ≠ x：p ← p.next
返回 p                      // 找不到返回 NULL
```

```c
/* 按位查找：返回第 i 个结点（i 从 0 开始），越界返回 NULL */
LNode *get_node(LNode *head, int i)
{
    if (i < 0) {
        return NULL;         /* 负数下标直接失败 */
    }
    LNode *p = head->next;   /* 从首元结点出发 */
    int j = 0;               /* 已越过 j 个结点 */
    while (p != NULL && j < i) {
        p = p->next;
        j++;
    }
    return p;                /* 找到返回结点，越界返回 NULL */
}

/* 按值查找：返回第一个 data 等于 x 的结点，找不到返回 NULL */
LNode *locate_node(LNode *head, int x)
{
    LNode *p = head->next;
    while (p != NULL && p->data != x) {
        p = p->next;
    }
    return p;
}
```

**插入：先定位前驱，再两步改链。** 在已知前驱 `prev` 的情况下，插入只做两件事：

```text
第一步：new.next ← prev.next   // 新结点先指向原后继
第二步：prev.next ← new        // 前驱再指向新结点
```

图示（在原链 `prev → X → Y` 中于 `prev` 之后插入 `new`）：

```text
原链：    prev → [X|next] → [Y|next] → [Z|next] → NULL
第一步后：new 已指向 Y，prev 尚未变化
第二步后：prev → [X|next] → [new|next] → [Y|next] → [Z|next] → NULL
```

两步顺序**不可颠倒**：若先执行 `prev.next ← new`，`prev` 与 Y 之间的链接被切断，Y 及其后的整段结点失去入口——这就是丢链：

```text
错误顺序（先改 prev.next）：prev → [X|next] → [new|next] → ???
Y、Z 结点仍存在，但整段链已不可达
```

按位置插入的完整流程是先花 $O(n)$ 定位前驱，再 $O(1)$ 改链：

```text
// 在第 i 个位置插入 x（0 ≤ i ≤ 表长 n）
prev ← head                 // 从 head 出发走 i 步即为前驱，中途遇 NULL 则越界、失败
new.data ← x
new.next ← prev.next        // 第一步
prev.next ← new             // 第二步
```

```c
/* 在第 i 个位置插入 x（i 从 0 开始）；成功返回 1，越界或空间不足返回 0 */
int insert_at(LNode *head, int i, int x)
{
    LNode *prev = head;      /* 定位前驱：从 head 出发走 i 步 */
    int j = 0;
    while (j < i && prev != NULL) {
        prev = prev->next;
        j++;
    }
    if (prev == NULL) {
        return 0;            /* i 大于表长，越界 */
    }
    LNode *p = (LNode *)malloc(sizeof(LNode));
    if (p == NULL) {
        return 0;            /* 空间不足 */
    }
    p->data = x;
    p->next = prev->next;    /* 第一步：新结点指向原后继 */
    prev->next = p;          /* 第二步：前驱指向新结点 */
    return 1;
}
```

注意 `insert_at(head, 0, x)` 就是表头插入：前驱是头结点，无需任何特判——头结点的收益在此第一次体现。

**删除：保存待删结点，改链，再释放。** 删除 `prev` 的后继 `target` 的流程：

```text
// 删除第 i 个结点（0 ≤ i < 表长 n）
prev ← head                 // 定位前驱，方法与插入相同
target ← prev.next          // 保存待删结点
prev.next ← target.next     // 跨过 target 改链
销毁 target                 // 释放结点空间
```

```c
/* 删除第 i 个结点（i 从 0 开始）；成功返回 1，越界或空表返回 0 */
int delete_at(LNode *head, int i)
{
    LNode *prev = head;      /* 定位前驱 */
    int j = 0;
    while (prev->next != NULL && j < i) {
        prev = prev->next;
        j++;
    }
    if (prev->next == NULL) {
        return 0;            /* 空表，或 i 越界：没有可删的结点 */
    }
    LNode *target = prev->next;  /* 保存待删结点 */
    prev->next = target->next;   /* 改链：跨过 target */
    free(target);                /* 释放空间，防止内存泄漏 */
    return 1;
}
```

**表头与表尾操作。** 表头插入与表头删除的前驱就是头结点，`insert_at(head, 0, x)` 与 `delete_at(head, 0)` 均为 $O(1)$、无特判。删除尾结点时 `target->next` 恰为 `NULL`，改链语句天然把它处理成新表尾，**不需要单独的分支**，真正要特判的是空表与越界。表尾插入若维护尾指针 `tail`，前驱由尾指针直接给出，$O(1)$，但 `tail` 必须随每次尾插、尾删正确更新；表尾删除则是 $O(n)$：删除尾结点必须把其前驱的 `next` 置为 `NULL`，而单链表结点**没有前驱指针**，只能从头遍历找前驱，删尾后也无法 $O(1)$ 回退尾指针。这是单链表的固有弱点，双链表用 `prev` 指针解决（见 [04 节](./04-doubly-circular-static-list.md)）。

## 复杂度分析

**定位与改链分离。** 单链表的每个操作都由两个性质完全不同的环节组成，必须分开计费：

| 环节 | 复杂度 | 说明 |
| --- | --- | --- |
| 定位：按位/按值找到目标结点或其前驱 | $O(n)$ | 只能从头遍历，平均访问 $n/2$ 个结点 |
| 改链：已知前驱后的插入/删除 | $O(1)$ | 只修改常数个链接域，不搬移任何数据 |

**常见操作的总成本：**

| 操作 | 复杂度 | 原因 |
| --- | --- | --- |
| 表头插入 / 表头删除 | $O(1)$ | 前驱就是头结点，免去定位 |
| 按位置插入 / 删除第 $i$ 个结点 | $O(n)$ | $O(n)$ 定位 + $O(1)$ 改链 |
| 按值查找 / 按值删除 | $O(n)$ | 平均 $n/2$ 次比较 |
| 表尾插入（维护尾指针） | $O(1)$ | 尾指针直接给出前驱 |
| 表尾删除 | $O(n)$ | 须从头找到尾结点的前驱 |

**「链表插入是 $O(1)$」的说法为什么不准确。** 精确的表述是：**已知前驱指针时**，插入与删除只需 $O(1)$ 改链；但按位置插入必须先花 $O(n)$ 定位前驱。CLRS §10.2 把「在给定结点之后插入」列为常数时间操作，并明确指出按位置插入的代价来自查找；Sedgewick §1.3 同样把「找到结点」与「修改链接」分开计费。把 $O(1)$ 误推广为「任意插入删除都常数时间」，是分析链表算法时最常见的失分点。空间上，$n$ 个结点需要 $n$ 个链接域，合计 $O(n)$ 指针开销；链表没有 `capacity` 概念、不会浪费未用容量，但每结点多一个指针，且分散存放导致缓存局部性差。

## 例题讲解

### 例 1：头插法与尾插法建表（难度：★）

**题目。** 从数组 `{1, 2, 3}` 依次读入元素，分别用头插法和尾插法建立带头结点的单链表。写出两个建表函数，并说明建表完成后链表中元素的次序。**思路分析。** 头插法把每个新结点插到头结点之后：先插入的 1 被后来的 2、3 一步步挤出首元位置，最终 3 成为首元结点，结果与输入顺序相反。尾插法把新结点接到表尾：`tail` 初始指向头结点，每插一次后移一次，结果与输入顺序相同。两者的每步操作都是常数时间，区别只在「插到哪」与「结果是否逆序」。

**算法步骤（伪代码）。**

```text
// 头插法
head ← 新建头结点
对每个元素 x：p ← 新建结点(x)；p.next ← head.next；head.next ← p

// 尾插法
head ← 新建头结点；tail ← head
对每个元素 x：p ← 新建结点(x)，p.next ← NULL；tail.next ← p；tail ← p
```

**C 实现。**

```c
/* 头插法建表：返回带头结点的链表，结果与输入顺序相反 */
LNode *create_by_head_insert(int a[], int n)
{
    LNode *head = (LNode *)malloc(sizeof(LNode));
    head->next = NULL;           /* 头结点的 next 置空 */
    for (int i = 0; i < n; i++) {
        LNode *p = (LNode *)malloc(sizeof(LNode));
        p->data = a[i];
        p->next = head->next;    /* 新结点指向原首元结点 */
        head->next = p;          /* 头结点指向新结点 */
    }
    return head;
}
/* 尾插法建表：返回带头结点的链表，结果与输入顺序相同 */
LNode *create_by_tail_insert(int a[], int n)
{
    LNode *head = (LNode *)malloc(sizeof(LNode));
    LNode *tail = head;          /* 尾指针：初始指向头结点 */
    for (int i = 0; i < n; i++) {
        LNode *p = (LNode *)malloc(sizeof(LNode));
        p->data = a[i];
        p->next = NULL;          /* 新结点将成为新表尾 */
        tail->next = p;          /* 接到表尾之后 */
        tail = p;                /* 尾指针后移 */
    }
    return head;
}
```

**复杂度分析。** 每个结点插入 $O(1)$：头插的前驱就是头结点，尾插由尾指针直接给出前驱，都不需要定位。$n$ 个结点总成本 $O(n)$，最坏与平均一致；额外空间 $O(1)$（尾指针只是一个指针变量）。输入 `{1, 2, 3}` 时，头插法得到 `3 → 2 → 1`，尾插法得到 `1 → 2 → 3`。

**常见错误与变式。** 头插法漏写 `p->next = head->next` 会直接丢链；尾插法忘记更新 `tail` 会让后续结点全部插在旧表尾之后，退化成头插。为突出建表逻辑，本例省略了 `malloc` 返回值检查，工程代码应像「插入」一节的 `insert_at` 那样检查。变式：需要逆序结果时可先用头插法直接得到逆序表；也可以用头插法把一条链表复制成逆序的新表，作为「复制 + 逆置」的组合练习。

### 例 2：单链表就地逆置（难度：★★）

**题目。** 给定带头结点的单链表，**就地**把它逆置：不新建数据结点、只改链接。输入 `1 → 2 → 3` 应变为 `3 → 2 → 1`。

**思路分析。** 遍历链表，把每个结点的 `next` 反转，指向前一个结点。需要三个指针：`prev` 指向已逆置部分的首结点（初始为 `NULL`），`cur` 指向当前待处理结点，`next` 保存 `cur` 的原后继。关键与「插入两步改链」同理：**改 `cur->next` 之前必须先用 `next` 保存原后继**，否则后半段链丢失。循环结束后 `cur` 走到 `NULL`，`prev` 正是新链表的首元结点，把它挂回头结点即可。

**算法步骤（伪代码）。**

```text
prev ← NULL；cur ← head.next      // 已逆置部分首结点 / 当前结点
当 cur ≠ NULL：
    next ← cur.next               // ① 先保存原后继
    cur.next ← prev               // ② 反转指针
    prev ← cur；cur ← next        // ③ ④ 两指针前移
head.next ← prev                  // 头结点指向新首元结点
```

**C 实现。**

```c
/* 就地逆置带头结点的单链表：三指针迭代，O(n) 时间、O(1) 空间 */
void reverse_list(LNode *head)
{
    LNode *prev = NULL;          /* 已逆置部分的首结点 */
    LNode *cur = head->next;     /* 当前待处理结点 */
    while (cur != NULL) {
        LNode *next = cur->next; /* ① 先保存原后继 */
        cur->next = prev;        /* ② 反转指针 */
        prev = cur;              /* ③ prev 前移 */
        cur = next;              /* ④ cur 前移 */
    }
    head->next = prev;           /* 头结点指向新的首元结点 */
}
```

**复杂度分析。** 每个结点恰被处理一次，最坏与平均均为 $O(n)$ 时间；只用了三个指针，$O(1)$ 额外空间；就地，不申请任何新结点，原有 $n$ 个结点全部复用。

**常见错误与变式。** 忘记第①步保存后继（丢链）；循环结束后忘记 `head->next = prev`（头结点仍指向旧首元结点，逆置后链表只剩下一个结点可达）。变式：递归逆置——`reverse(p)` 先逆置以 `p` 的后继为头的那段子链表，再把 `p` 接到新表尾之后（调用时写 `head->next = reverse_recursive(head->next)`）：

```c
/* 递归逆置：返回以 p 为首的子链表逆置后的首结点 */
LNode *reverse_recursive(LNode *p)
{
    if (p == NULL || p->next == NULL) {
        return p;                /* 空表或单结点：无需逆置 */
    }
    LNode *new_head = reverse_recursive(p->next); /* 先逆置后半段 */
    p->next->next = p;           /* p 成为新表尾的后继 */
    p->next = NULL;              /* p 成为新表尾 */
    return new_head;
}
```

递归版代码更短，但递归深度为 $O(n)$，栈空间 $O(n)$；表很长时可能栈溢出，工程上迭代版更稳妥。

### 例 3：删除倒数第 k 个结点（难度：★★）

**题目。** 给定带头结点的单链表与正整数 $k$，删除倒数第 $k$ 个结点（$k = 1$ 表示尾结点）。若 $k$ 大于表长 $n$，链表保持不变。

**思路分析。** 双指针：先行指针 `p` 先走 $k$ 步，再与后行指针 `q` 同步前进。`p` 到达 `NULL` 时，`q` 恰好停在**倒数第 $k$ 个结点的前驱**上——同步期间两者始终保持 $k$ 的间距，一趟扫描完成定位、无需先求表长。边界：$k > n$ 时 `p` 走不满 $k$ 步就碰到 `NULL`，判定无此结点、不删；$k = n$ 时 `p` 恰好走到 `NULL`、`q` 停在头结点，删除的正是首元结点（带头结点下无须特判）；$k = 1$ 时删除尾结点，改链后新表尾的 `next` 自动为 `NULL`。

**算法步骤（伪代码）。**

```text
若 k ≤ 0：直接返回
p ← head.next；q ← head；step ← 0
当 p ≠ NULL 且 step < k：p ← p.next；step ← step + 1
若 step < k：返回               // k 大于表长，不删
当 p ≠ NULL：p ← p.next；q ← q.next   // 保持 k 的间距同步前进
target ← q.next                 // q 是倒数第 k 个结点的前驱
q.next ← target.next；销毁 target
```

**C 实现。**

```c
/* 删除倒数第 k 个结点（k ≥ 1）；k 非法或 k 大于表长时链表不变 */
void remove_kth_from_end(LNode *head, int k)
{
    if (k <= 0) {
        return;                /* k 必须为正整数 */
    }
    LNode *p = head->next;     /* 先行指针 */
    LNode *q = head;           /* 后行指针：最终停在待删结点的前驱 */
    int step = 0;
    while (p != NULL && step < k) {   /* p 先走 k 步 */
        p = p->next;
        step++;
    }
    if (step < k) {
        return;                /* k 大于表长：不存在倒数第 k 个结点 */
    }
    while (p != NULL) {
        p = p->next;           /* 两指针同步前进 */
        q = q->next;           /* 始终保持 k 的间距 */
    }
    LNode *target = q->next;   /* q 即倒数第 k 个结点的前驱 */
    q->next = target->next;    /* 跨过 target 改链 */
    free(target);              /* 释放空间 */
}
```

**复杂度分析。** 两个指针各遍历链表一遍，最坏与平均均为 $O(n)$ 时间、$O(1)$ 空间。对照「先求表长 $n$、再走 $n - k$ 步」的两趟方案（同是 $O(n)$），两者的指针移动总量相同（都约为 $2n-k$ 次）；一趟方案的优势不在常数，而在只需一次遍历、无需事先知道表长——当链表在遍历过程中会变化、或场景不允许两趟扫描时，它是唯一选择。

**常见错误与变式。** 忘记检查 $k \le 0$；把 $k$ 从 0 计数导致差一错误（约定 $k = 1$ 是尾结点）；`q` 初始化为 `head->next` 会停在待删结点而非其前驱。变式一：求倒数第 $k$ 个结点（不删除）只需返回 `q->next`；变式二：若链表同时维护尾指针，且删除的恰是尾结点，必须重新定位新表尾（$O(n)$），否则尾指针悬空。

### 例 4：求链表中点（难度：★★）

**题目。** 给定带头结点的单链表，求它的中间结点。**约定**：表长为偶数时返回前中点（例如 4 个结点返回第 2 个，即下标 1）。

**思路分析。** 快慢指针：`slow` 每步走 1，`fast` 每步走 2。`fast` 无法再走两步时（`fast->next` 或 `fast->next->next` 为 `NULL`），`slow` 恰好落在中点。必须先把「偶数长度取前中点还是后中点」定义清楚：取前中点，停止条件是「`fast` 不能再走两步」；若取后中点，停止条件是「`fast` 不能再走一步」。两种约定都很常见，实现必须与约定保持一致。边界：空表返回 `NULL`；单结点返回该结点。

**算法步骤（伪代码）。**

```text
若 head.next = NULL：返回 NULL          // 空表
slow ← head.next；fast ← head.next
当 fast.next ≠ NULL 且 fast.next.next ≠ NULL：
    slow ← slow.next；fast ← fast.next.next   // 慢走一步、快走两步
返回 slow                              // 偶数长度时 slow 是前中点
```

**C 实现。**

```c
/* 求链表中点：偶数长度返回前中点；空表返回 NULL */
LNode *middle_node(LNode *head)
{
    if (head->next == NULL) {
        return NULL;           /* 空表 */
    }
    LNode *slow = head->next;  /* 慢指针：每次走一步 */
    LNode *fast = head->next;  /* 快指针：每次走两步 */
    while (fast->next != NULL && fast->next->next != NULL) {
        slow = slow->next;         /* slow 走一步 */
        fast = fast->next->next;   /* fast 走两步 */
    }
    return slow;               /* 偶数长度时落在前中点 */
}
```

**复杂度分析。** `fast` 到达表尾时 `slow` 恰好走完一半路程，一趟扫描，$O(n)$ 时间、$O(1)$ 空间，且不需要事先知道表长。

**常见错误与变式。** 偶数长度的中点约定含糊（前中点与后中点的停止条件不同，先说清楚再实现）；循环条件只写 `fast != NULL` 会得到后中点版本，与「前中点」的声明不一致；空表直接解引用 `fast->next` 会崩溃。变式一：判断长度奇偶——本例循环结束后，`fast->next == NULL` 当且仅当表长为奇数（`fast` 停在尾结点），可据此在 $O(n/2)$ 内判奇偶；变式二：若约定偶数长度取后中点，把循环条件改为 `while (fast != NULL && fast->next != NULL)`，`n = 2` 时 `slow` 落在第 2 个结点、`n = 4` 时落在第 3 个结点，与约定一致。

### 例 5：两个有序单链表原地合并（难度：★★）

**题目。** 给定两个递增有序的带头结点单链表 `l1`、`l2`，把它们**原地**合并为一个递增有序链表：不新建任何数据结点，只改链接；$O(n + m)$ 时间、$O(1)$ 额外空间。

**思路分析。** 归并思想：游标 `p`、`q` 分别扫描两条链表，每次把较小者从原链取下、接到结果链表的表尾；任一条扫描完，把另一条的剩余部分整体挂接。关键设计：**直接复用 `l1` 的头结点作为结果链表的头结点**，于是首元结点的确定与后续结点完全同构，由同一条 `tail->next = 较小者` 语句完成，不需要特判「结果链表是否为空」。这正是头结点价值的集中体现：若是不带头结点的裸 `first`，第一次挂接必须单独处理结果头指针。

**算法步骤（伪代码）。**

```text
tail ← l1；p ← l1.next；q ← l2.next    // 复用 l1 的头结点
当 p ≠ NULL 且 q ≠ NULL：
    若 p.data ≤ q.data：tail.next ← p；p ← p.next
    否则：tail.next ← q；q ← q.next
    tail ← tail.next
tail.next ← 剩余非空链表的头      // p 与 q 至多一个非空
销毁 l2 的头结点；返回 l1
```

**C 实现。**

```c
/* 原地合并两个递增有序链表：复用 l1 的头结点，O(n+m) 时间、O(1) 空间 */
LNode *merge_sorted(LNode *l1, LNode *l2)
{
    LNode *tail = l1;          /* 结果链表从头结点 l1 开始 */
    LNode *p = l1->next;       /* 游标 p 扫描 l1 */
    LNode *q = l2->next;       /* 游标 q 扫描 l2 */
    while (p != NULL && q != NULL) {
        if (p->data <= q->data) {
            tail->next = p;    /* 取下 p 的当前结点 */
            p = p->next;
        } else {
            tail->next = q;    /* 取下 q 的当前结点 */
            q = q->next;
        }
        tail = tail->next;     /* 尾指针前进 */
    }
    tail->next = (p != NULL) ? p : q;  /* 剩余部分整体挂接 */
    free(l2);                  /* l2 的头结点已无用，释放 */
    return l1;
}
```

**复杂度分析。** 每个结点至多被比较并挂接一次，最坏与平均均为 $O(n + m)$ 时间；只用了常数个指针，$O(1)$ 额外空间；不新建任何数据结点，是真正的原地合并。合并后原链表已融为一体，调用方不应再分别释放 `l1`、`l2` 的结点。

**常见错误与变式。** 比较后忘记推进游标（死循环）；漏掉循环结束后剩余部分的整体挂接（结果链表不完整）；释放 `l2` 头结点后仍在别处使用 `q`。变式：若要求不破坏原链表，新建一个头结点并申请 $n + m$ 个新结点即可，合并逻辑不变；也可用递归写合并，但递归深度与栈空间为 $O(n + m)$。

## 易错点

- **改链顺序写反丢链**：插入时先执行 `prev->next = new` 再改 `new->next`，原后继及其后整段结点失去入口；删除、逆置时不先保存后继就改链接，同理丢链。**删除后忘记 `free`**：C 语言中结点空间不会自动回收，忘记释放会内存泄漏；正确顺序是「先保存、再改链、后释放」。
- **删尾后尾指针未更新**：维护尾指针的链表删除尾结点后，必须把 `tail` 回退到新表尾；单链表无法 $O(1)$ 回退，只能从头找，忘记更新会让后续尾插把结点接到已释放的结点上。
- **空表/单结点特判遗漏**：查找、删除、求中点等操作对空表解引用 `head->next` 或 `fast->next` 会崩溃；单结点情形常与空表情形写进同一分支。
- **带头结点与不带头结点的判空条件混用**：前者判 `head->next == NULL`，后者判 `head == NULL`；从一种约定切换到另一种时，所有函数都要逐一核对，判空与头插、头删的分支都不同。
- **把「已知前驱 $O(1)$」误写成「所有插入删除 $O(1)$」**：按位置插入还需 $O(n)$ 定位前驱，陈述复杂度必须说明调用方是否已经持有前驱（见「复杂度分析」一节）。

## 小结

单链表用「分散的结点 + 链接」表达线性关系，把顺序表的「搬移元素」转化为「修改链接」。本节要点：结点含数据域与指针域，自引用结构体中必须写 `struct LNode *next`；头结点（哨兵）把判空、头插、头删统一为一般情形，代价是一个结点的空间；所有操作都是「定位 + 改链」两步，定位 $O(n)$（表头、带尾指针的表尾除外）、改链 $O(1)$；单链表结点没有前驱指针，表尾删除只能从头找前驱 $O(n)$——这是它与双链表的根本差别（[04 节](./04-doubly-circular-static-list.md)）；双指针技巧（先行指针、快慢指针）可在 $O(n)$ 一趟扫描内完成倒数第 $k$ 个、中点等定位任务。与顺序表的全面对比见 [05 节](./05-comparison-and-selection.md)，配套实验 [lab-01-02-linked-list](../../labs/chapter-01/lab-01-02-linked-list/README.md) 提供可运行的完整实现。
