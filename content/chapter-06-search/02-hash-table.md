# 6.2 散列表

BST 的查找仍然依赖"比较"，平均 $O(\log n)$。**散列表**（哈希表）换了一条路：通过**散列函数** `h(key)` 直接计算关键字的存储位置，理想情况下一次定位，平均查找 `O(1)`。

## 学习目标

- 设计散列函数并理解其要求；
- 实现链地址法与开放定址法两种冲突处理；
- 解释负载因子如何影响性能，论证平均 `O(1)` 的前提。

## 散列函数

散列函数把关键字映射到表地址：`pos = h(key) mod m`（`m` 为表长）。好的散列函数应让关键字**均匀分布**到各槽位，且计算快速。对整数常用取模；对字符串常用加权和：

$$
h(s) = \left( \sum_{i=0}^{k-1} s_i \cdot 31^{k-1-i} \right) \bmod m.
$$

::: warning 散列函数选择表长有讲究
表长取素数能减少取模的周期性聚集；取 2 的幂则相当于丢弃高位、只保留低位，容易让相近关键字聚集到相邻槽位。
:::

## 冲突与链地址法

不同关键字映射到同一地址称为**冲突**，散列函数设计得再好也无法避免（鸽巢原理）。**链地址法**把每个槽位变成一条链表，冲突关键字挂到同一条链上：

```cpp:line-numbers [chaining.cpp]
// 槽位 = 链表头；插入 O(1)（头插），查找遍历链表
struct Slot { std::vector<std::pair<int, Value>> items; };

Value* get(const std::vector<Slot>& table, int key) {
    auto& slot = table[hash(key) % table.size()];
    for (auto& [k, v] : slot.items)
        if (k == key) return &v;
    return nullptr;                      // 查找失败的约定
}
```

查找代价 = `O(1)` 定位 + 链表内比较。链表期望长度等于**负载因子**：

$$
\alpha = \frac{\text{已存元素数}}{\text{槽位数}}.
$$

在均匀散列的假设下，链地址法查找成功的期望比较次数约为 $1 + \alpha/2$——$\alpha$ 是常数（如 0.75）时就是 `O(1)`。

## 开放定址法

不建链表，冲突时按探测序列在表内找下一个空位。线性探测 `pos = (h(key) + i) mod m` 最简单，但会产生**聚集**；二次探测与双重散列减少聚集，代价是删除时需要标记"已删除"而非直接清空，否则会断掉探测链。

::: warning 开放定址的删除陷阱
开放定址表删除元素时若直接置空，后续查找会提前终止而误判"不存在"。必须用特殊标记区分"空槽"与"已删除槽"。
:::

## 何时退化

最坏情况是散列函数把全部关键字映射到同一槽位：链地址法退化成一条 `O(n)` 链表，与顺序查找无异。控制手段是选择均匀的散列函数 + 维持 $\alpha$ 低于阈值（超阈值时**再散列**扩容）。"平均 `O(1)`"依赖均匀散列假设，这正是与 BST 有保证的 $O(\log n)$ 不同之处。

## 小结

散列表把"比较查找"变成"计算位置"，用空间换取平均常数时间；它的性能承诺依赖均匀散列与负载因子控制。选择散列还是树：需要按键精确查找且不要求顺序，散列更快；需要有序遍历、范围查询或有最坏性能保证，树更合适。
