# 7.1 十大排序详解与证明

排序是算法世界里最经典、最基础的问题之一。本节把十种经典排序**一次性串起来**，从「怎么做」讲到「为什么对」「为什么快」，并补齐一个重要的层次——**正确性证明**。

为什么值得单独写证明？因为排序是学习「证明算法正确」的最佳素材：代码短、直觉清晰，但「直觉觉得对」和「严格证明它对」之间隔着一道门槛。跨过这道门槛，你就能把同样的方法（循环不变式、分治归纳、决策树下界）迁移到任何算法。

## 排序问题怎么分类

排序问题可以粗略分成两大类：

- **比较排序**：通过比较关键字大小来确定顺序；
- **非比较排序**：利用关键字的值域特性，如整数范围、位分解等，绕过比较。

本节把常见的十类经典排序一并串起来。先看一张总览表。

## 7.1.1 十大排序一张图

| 分类 | 排序 | 最好 | 平均 | 最坏 | 额外空间 | 稳定性 | 直觉 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 比较排序 | 插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 打扑克牌，摸一张插一张 |
| 比较排序 | 选择排序 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 不稳定 | 每次挑最小的放前面 |
| 比较排序 | 冒泡排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 大的气泡往上冒，相邻交换 |
| 比较排序 | 希尔排序 | $O(n\log n)$ | 约 $O(n^{1.3})$ | $O(n^2)$ | $O(1)$ | 不稳定 | 先粗排再细排，缩小增量 |
| 比较排序 | 归并排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | 稳定 | 分治经典，先拆后合 |

| 非比较排序 | 计数排序 | $O(n+k)$ | $O(n+k)$ | $O(n+k)$ | $O(n+k)$ | 稳定 | 数每个值出现几次，直接填 |
| 非比较排序 | 桶排序 | $O(n)$ | $O(n)$ | 视桶内排序 | $O(n)$ | 视桶内而定 | 分桶装，桶内再排 |

::: tip 结论先行
如果关键字只能比较大小，则任何比较排序都不可能优于 $\Omega(n\log n)$；但如果关键字拥有更强结构（如整数的十进制位、有限值域），就可以透过「非比较」方式突破这个下界。打个比方：蒙着眼只能比身高，你至少要问 $n\log n$ 次；但如果每个人胸前挂着编号牌，你直接看编号排，线性时间就能搞定。
:::

## 7.1.2 插入排序

### 思路

插入排序把待排序数组视作「已排好序的前缀 + 未排序的后缀」。每次从后缀取出一个元素 `key`，把它插入到前缀中适当的位置。

直觉就是打扑克牌：每摸一张牌，从右往左找到它该插的位置插进去。手牌始终有序，每张新牌只是「插入」到正确位置。

```cpp:line-numbers [insertion-sort.cpp]
void insertionSort(int a[], int n) {
    for (int i = 1; i < n; ++i) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
}
```

### 正确性证明：循环不变式

**循环不变式：** 在外层循环每轮开始时，`a[0..i-1]` 已经有序，并且恰好包含原数组中前 `i` 个元素的所有值。

- **初始化：** `i = 1` 时，`a[0]` 显然有序，不变式成立。
- **保持：** 设当前 `key = a[i]`，内层循环把所有大于 `key` 的元素右移，直到找到正确插入位置 `j + 1`，此时前缀 `a[0..i]` 仍然有序。
- **终止：** 当 `i = n` 时，整个数组有序。

循环不变式就像归纳假设——你要证明三件事：开始时对、每步保持对、结束时恰好是你想要的。

### 复杂度与稳定性

| 情况 | 时间复杂度 | 直觉 |
|------|-----------|------|
| 最好 | $O(n)$ | 数组本来有序，`key` 每次直接放回原位，内层循环几乎不执行 |
| 最坏 | $O(n^2)$ | 逆序，每个 `key` 要一直移到最前面，内层循环执行 $i$ 次 |
| 平均 | $O(n^2)$ | 随机数据，`key` 平均要移动 $i/2$ 次 |

**稳定性：** 稳定。因为只有 `a[j] > key` 时才右移，等于 `key` 的元素不移动，相同关键字顺序保持。

::: tip 插入排序的实战价值
虽然理论上是 $O(n^2)$，但它对**近乎有序**的数组极快（接近 $O(n)$），常数因子也极小。所以很多高级排序（如 TimSort）在小段或近乎有序段会退回插入排序——这不是「落后」，而是「精明」。
:::

## 7.1.3 选择排序

### 思路

每一趟从未排序区间里选择最小值，并交换到当前起始位置。

直觉就像排队：每次从剩下的人里挑最矮的，站到队首。简单，但每次挑人都要扫一遍，效率不高。

```cpp:line-numbers [selection-sort.cpp]
void selectionSort(int a[], int n) {
    for (int i = 0; i < n - 1; ++i) {
        int minIndex = i;
        for (int j = i + 1; j < n; ++j) {
            if (a[j] < a[minIndex]) minIndex = j;
        }
        if (minIndex != i) std::swap(a[i], a[minIndex]);
    }
}
```

### 正确性证明

**循环不变式：** 在第 `i` 轮开始前，前 `i` 个位置已经放置了最小的 `i` 个元素，且按排序要求排列。

- **初始化：** `i = 0` 无前元素，成立。
- **保持：** 在未排序区间选出最小值 `m`，交换到第 `i` 位，因此前 `i + 1` 个位置一定是当前最小的 `i + 1` 个元素。
- **终止：** 当 `i = n - 1` 时，全部元素有序。

### 复杂度与稳定性

外层循环做 $n-1$ 趟，每趟扫描剩余部分：

$$
T(n) = \sum_{i=0}^{n-1} (n-i-1) = \frac{n(n-1)}{2} = O(n^2).
$$

选择排序的最好、平均、最坏**全是** $O(n^2)$——它不像插入排序有「最好 $O(n)$」的福利，因为不管数组多有序，每趟都得扫完剩余部分才能确定最小值。空间复杂度 $O(1)$。

**稳定性：** 不稳定。交换最小值时，可能把与它相等的元素从后面换到前面，打乱相对顺序。

> **反例：** `[5a, 5b, 3]`，第一趟选出最小值 `3` 与 `5a` 交换 → `[3, 5b, 5a]`，两个 `5` 的相对顺序变了。

## 7.1.4 冒泡排序

### 思路

每一趟相邻比较，若前一个大于后一个就交换。这样每一轮都能把当前最大元素「冒泡」到末尾。

直觉是水里的气泡——越大的气泡浮得越快。每轮扫描，最大的元素就像气泡一路「冒」到最后面。

```cpp:line-numbers [bubble-sort.cpp]
void bubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; ++i) {
        bool swapped = false;
        for (int j = 0; j < n - i - 1; ++j) {
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // 早停：这趟没交换，已经有序
    }
}
```

### 正确性证明

**循环不变式：** 在一趟冒泡结束后，当前未排序区间的最大元素已经被放到区间末尾。

- 一轮扫描中，如果 `a[j] > a[j+1]` 就交换，保证较大的元素向右移动。
- 经过整趟扫描，所有大于当前末尾元素的值都会被「冒」过去，最大值落在末尾。
- 重复 $n-1$ 趟后（或早停），数组整体有序。

### 复杂度与稳定性

| 情况 | 时间复杂度 | 直觉 |
|------|-----------|------|
| 最好 | $O(n)$ | 已排序 + 早停：第一趟没有交换，直接结束 |
| 最坏 | $\Theta(n^2)$ | 逆序：每次比较都要交换 |
| 平均 | $O(n^2)$ | 随机数据，约一半的比较需要交换 |

**稳定性：** 稳定。因为只有 `a[j] > a[j+1]` 时才交换，相等元素不交换，顺序保持不变。

::: tip 冒泡 vs 插入
两者最好都是 $O(n)$、最坏都是 $O(n^2)$、都稳定。但插入排序只移动必要的元素，冒泡每次交换要 3 次赋值，所以实战中插入通常更快。
:::

## 7.1.5 希尔排序

### 思路

希尔排序不是一次性按相邻元素比较，而是先按「间隔 $gap$」分组，组内做插入排序；随后逐渐缩小 $gap$，直到 $gap = 1$。

普通插入排序只能一个一个挪，遇到逆序就慢。希尔排序的妙处在于——先大步跳着排，把远处的逆序快速消除；再小步走，把细节理顺。就像整理书架，先把明显放错位置的大部头搬好，再微调每本书的位置。

```cpp:line-numbers [shell-sort.cpp]
void shellSort(int a[], int n) {
    for (int gap = n / 2; gap > 0; gap /= 2) {
        for (int i = gap; i < n; ++i) {
            int key = a[i];
            int j = i - gap;
            while (j >= 0 && a[j] > key) {
                a[j + gap] = a[j];
                j -= gap;
            }
            a[j + gap] = key;
        }
    }
}
```

### 正确性证明

希尔排序的正确性基于「每次增量排序后，间隔为 `gap` 的子序列有序」。

- 对固定 `gap`，把数组拆成多个长度约为 $n/gap$ 的子序列，每个子序列做插入排序，保证它内部有序。
- 当 `gap` 逐步缩小到 `1` 时，最后一轮就是普通插入排序。

关键在最后一步：此时数组已经经过大步长预处理，远处的逆序已经很少，所以这趟插入排序非常快——这正是希尔排序比纯插入排序快的根本原因。因此最后一轮 `gap = 1` 结束时数组有序。

### 复杂度与稳定性

希尔排序的复杂度**依赖增量序列**，没有一个统一的通式：

| 增量序列 | 最坏时间复杂度 | 说明 |
|---------|--------------|------|
| Shell 原始：$n/2, n/4, \ldots, 1$ | $O(n^2)$ | 简单但不够优 |
| Hibbard：$2^k - 1$ | $O(n^{1.5})$ | 常用，效果不错 |
| Sedgewick | $O(n^{4/3})$ | 更优，工程常用 |
| Pratt（所有 $2^p 3^q$） | $O(n\log^2 n)$ | 接近最优但序列太长 |

空间复杂度 $O(1)$。

::: warning 别把希尔排序笼统写成 O(n log n)
希尔排序的**最好情况**是 $O(n\log n)$——数组已有序时，每个增量只做 $O(n)$ 次比较，共约 $\log n$ 个增量。但它的**平均与最坏**达不到这个量级：平均通常经验值约 $O(n^{1.3})$，介于 $O(n\log n)$ 与 $O(n^2)$ 之间，且**强烈依赖增量序列**。严谨的说法是「最好 $O(n\log n)$；最坏 $O(n^2)$（简单序列）、$O(n^{1.5})$（Hibbard）；平均约 $O(n^{1.3})$」。
:::

::: tip 为什么有的教材说最好情况是 O(n)
你可能会在别处看到希尔排序「最好 $O(n)$」的写法，这里写 $O(n\log n)$，到底哪个对？

分歧来自「最好情况」到底数了几遍。已有序时，**每一趟**（每个 gap）确实只花 $O(n)$——内层 while 第一次比较就退出，每个元素只比一次。但希尔排序不是一趟，它有 $\lfloor\log_2 n\rfloor$ 个 gap，外层循环每个 gap 都要把数组完整扫一遍，所以总比较次数是：

$$
(n-\tfrac n2) + (n-\tfrac n4) + \cdots + (n-1) \approx n\log_2 n.
$$

说 $O(n)$ 的写法，是把「每一趟 $O(n)$」误当成了「总共 $O(n)$」，漏掉了 gap 有 $\log n$ 层这个事实。只有当增量序列只有常数个 gap 时（比如 gap = `{1}`，即退化成插入排序），最好情况才是 $O(n)$。对标准的 $n/2$ 递减序列，最好情况是 $O(n\log n)$。
:::

**稳定性：** 不稳定。元素可能跨不同 `gap` 距离移动，破坏等值元素的相对顺序。

## 7.1.6 归并排序

### 思路

归并排序把数组一分为二，递归排序左右两半，再把两个有序子数组归并成一个有序数组。

这是分治思想的教科书范例——大问题拆成小问题，小问题解决了，合并起来大问题也解决了。就像整理一摞试卷：先分成两半分别排好，再把两摞有序试卷逐个比较，合并成一摞。

```cpp:line-numbers [merge-sort.cpp]
void mergeSort(int a[], int l, int r) {
    if (l >= r) return;
    int mid = (l + r) / 2;
    mergeSort(a, l, mid);
    mergeSort(a, mid + 1, r);
    merge(a, l, mid, r);   // 把 a[l..mid] 与 a[mid+1..r] 归并
}
```

其中 `merge` 用两个指针分别扫两段有序区间，每次把头部较小的元素放进辅助数组，直到一段耗尽，再把另一段剩余元素直接追加。

### 正确性证明

归并排序的证明使用「分治法 + 归并保持有序」。

- **归并前提：** 左右两半都已经有序（递归假设）。
- **归并过程：** 每次取两段头部较小的元素放进辅助数组，直到一段耗尽；另一段剩余元素直接追加。
- **归并结果：** 每次取出的元素都不小于已放入的元素，因此结果有序。
- **递归基础：** 单元素显然有序。

直觉上，归并就像合并两个已经排好队的队伍——每次看两队排头谁更矮，谁先出列。因为两队本身有序，出队的人也一定有序。

### 复杂度与稳定性

递推为：

$$
T(n) = 2T(n/2) + O(n).
$$

按主定理（$a=2$、$b=2$、$f(n)=\Theta(n)$，属于情况 2，$n^{\log_2 2}=n$）：

$$
T(n) = \Theta(n\log n).
$$

最好、平均、最坏**全是** $O(n\log n)$——归并排序不挑数据，这是它最大的优点。额外空间 $O(n)$（辅助数组）。

**稳定性：** 稳定。归并时对相等元素优先取左侧段，保留原相对顺序。

::: tip 归并 vs 快排
归并最坏也是 $O(n\log n)$ 且稳定，那为什么实战中快排更常用？因为快排是原地排序（不需要 $O(n)$ 辅助数组）、缓存友好（访问局部性好）、常数因子更小。归并则在要求稳定、外部排序、链表排序等场景不可替代。
:::

## 7.1.7 快速排序

### 思路

快速排序选定一个枢轴 `pivot`，将数组划分为「左边都 ≤ pivot、右边都 ≥ pivot」两部分，然后递归处理左右两侧。

快排的核心就一件事——**选标杆，分两边**。标杆左边都比它矮，右边都比它高，标杆自己已经站到最终位置。然后左右两边各自再选标杆，分到不能再分，排序完成。

```cpp:line-numbers [quick-sort.cpp]
int partition(int a[], int l, int r) {
    int pivot = a[r];
    int i = l - 1;
    for (int j = l; j < r; ++j) {
        if (a[j] <= pivot) {
            ++i;
            std::swap(a[i], a[j]);
        }
    }
    std::swap(a[i + 1], a[r]);
    return i + 1;
}

void quickSort(int a[], int l, int r) {
    if (l >= r) return;
    int p = partition(a, l, r);
    quickSort(a, l, p - 1);
    quickSort(a, p + 1, r);
}
```

### 正确性证明

设分区函数返回位置 `p`，则：

- 所有 `a[l..p-1] <= a[p]`；
- 所有 `a[p+1..r] >= a[p]`；
- `a[p]` 已处于最终位置。

扫描过程中，`i` 维护「已放置到左边的较小元素」的下界；每遇到一个不大于 `pivot` 的元素，就放到 `i+1` 位置，保证左边区间全部满足条件；最后把 `pivot` 交换到 `i+1`，得到正确分界。随后递归处理左右两边，最终整个数组有序。

直觉上，`partition` 就像体育课排队——选一个人当标杆，比他矮的站左边，比他高的站右边，标杆不用再动；左右两队再各选标杆，直到每队只有 0 或 1 人。

### 复杂度与稳定性

| 情况 | 递推式 | 时间复杂度 | 直觉 |
|------|--------|-----------|------|
| 最好 | $T(n) = 2T(n/2) + O(n)$ | $O(n\log n)$ | 每次均匀划分，和归并一样 |
| 最坏 | $T(n) = T(n-1) + O(n)$ | $O(n^2)$ | 枢轴总是最值，退化为逐个扫描 |
| 平均 | 随机划分 | $O(n\log n)$ | 大部分划分比较均匀 |

**最坏情况怎么来的？** 如果数组已经有序，而每次选最后一个元素做 pivot，左边是空集、右边是 $n-1$ 个元素——每层只减少一个元素，递归深度 $n$，每层 $O(n)$，总计 $O(n^2)$。

额外空间为递归栈 $O(\log n)$（平均），但最坏递归深度可达 $O(n)$。

**稳定性：** 不稳定。分区交换过程中等值元素可能跨过对方交换位置，顺序被打乱。

::: tip 工程优化
| 策略 | 说明 | 效果 |
|------|------|------|
| 随机枢轴 | `swap(a[r], a[rand()])` | 期望均匀划分 |
| 三数取中 | 取 `a[l]`、`a[mid]`、`a[r]` 的中值做 pivot | 避免已有序退化 |
| 小段转插入 | 子数组长度 < 阈值时用插入排序 | 减少递归开销 |
| 尾递归优化 | 先递归小的半边，大的半边用循环 | 保证栈深度 $O(\log n)$ |
:::

## 7.1.8 堆排序

### 思路

堆排序借助最大堆或最小堆。建立堆后，每次把堆顶元素放到数组尾部，调整堆，再继续。

直觉是一个选拔赛——堆顶永远是当前最强的人。每轮把最强的「淘汰」到最终位置，再重新组织剩下的比赛（`siftDown` 恢复堆性质），重复 $n$ 轮完成选拔。

```cpp:line-numbers [heap-sort.cpp]
void heapSort(int a[], int n) {
    makeHeap(a, n);               // 建大根堆
    for (int i = n - 1; i > 0; --i) {
        std::swap(a[0], a[i]);
        siftDown(a, 0, i);        // 维护堆性质
    }
}
```

### 正确性证明

堆的核心性质：堆顶一定是当前最大值（大根堆）。

- 建堆后，堆顶是当前最大元素。
- 把堆顶与末尾交换后，最大元素已落到最终位置；剩余前部仍构成堆。
- 重新执行 `siftDown`，恢复堆性质。
- 重复这一过程，所有元素从大到小依次落到最终位置，数组整体有序。

堆是一种「部分有序」结构——只保证父节点 ≥ 子节点，不保证左右子节点的大小关系。但这已经够了：我们只需每轮知道谁是最大值，不需要完全排序。

### 复杂度与稳定性

| 步骤 | 复杂度 | 说明 |
|------|--------|------|
| 建堆 | $O(n)$ | 从底向上 `siftDown`，看似 $O(n\log n)$ 实则 $O(n)$ |
| 取堆顶 + 调整 | $(n-1) \times O(\log n)$ | 每次 `siftDown` 最多走树高 $\log n$ |

所以：

$$
T(n) = O(n) + O(n\log n) = O(n\log n).
$$

最好、平均、最坏都为 $O(n\log n)$——堆排序和归并一样不挑数据、不退化。

::: tip 建堆为什么是 O(n) 而不是 O(n log n)
直觉上 $n$ 个元素每个 `siftDown` 最多 $\log n$，应该是 $O(n\log n)$。但实际上**大部分节点在树的下层**，`siftDown` 路径很短。精确计算 $\sum_{h=0}^{\log n} \frac{n}{2^{h+1}} \cdot O(h) = O(n)$——叶子节点（占一半）根本不用动。
:::

空间复杂度 $O(1)$（原地）。

**稳定性：** 不稳定。堆顶与末尾交换时，等值元素可能发生位置变化。

::: tip 堆排序的独特价值
它是唯一一个既原地（$O(1)$ 额外空间）又最坏 $O(n\log n)$ 的比较排序——归并需要 $O(n)$ 空间，快排最坏 $O(n^2)$，堆排序两头都占了。但它的缓存不友好（数据访问跳跃大），所以实测通常比快排慢。
:::

## 7.1.9 计数排序

### 思路

计数排序适用于整数序列，且关键字范围不大。它统计每个关键字出现次数，再按计数回填结果。

直觉是唱票——不比较谁多谁少，直接数「得 1 票的有几人、得 2 票的有几人……」，然后按票数填回结果。快是快，但前提是票的种数（值域 $k$）不能太多，否则计数数组爆炸。

```cpp:line-numbers [counting-sort.cpp]
void countingSort(int a[], int n, int k) {
    vector<int> cnt(k + 1, 0);
    for (int i = 0; i < n; ++i) ++cnt[a[i]];         // 计数
    for (int i = 1; i <= k; ++i) cnt[i] += cnt[i - 1]; // 前缀和
    vector<int> out(n);
    for (int i = n - 1; i >= 0; --i) {               // 从后往前回填（保稳定）
        out[--cnt[a[i]]] = a[i];
    }
    for (int i = 0; i < n; ++i) a[i] = out[i];
}
```

### 正确性证明

计数排序的核心是「`cnt[x]` 表示元素值不超过 `x` 的个数」。

- 计算前缀和后，`cnt[x]` 表示元素值 $\le x$ 的个数。
- 因此元素值为 `x` 的所有实例都应落在区间 `[cnt[x-1], cnt[x]-1]` 中。
- 从后往前遍历原数组并逆序填充，保证相等元素在输出中的相对顺序不被破坏。

**为什么要从后往前填？** 因为 `cnt[x]` 是「不超过」的累积值，从后往前能保证相同值的元素里，原数组靠后的在输出中也靠后——这就是稳定性。

### 复杂度与稳定性

$$
T(n) = O(n + k).
$$

其中 $k$ 是关键字最大值（值域大小）。空间复杂度为计数数组 $O(k)$ + 输出数组 $O(n)$ = $O(n+k)$。

**稳定性：** 稳定（采用从后往前的逆序回填时）。

::: warning 适用条件
关键字必须是整数，且值域不大（$k = O(n)$ 或更小）。如果 $k \gg n$（比如 10 个数但值域到 $10^9$），计数数组爆炸，时间和空间都扛不住——这时候计数排序不比比较排序好，甚至更差。
:::

## 7.1.10 桶排序

### 思路

桶排序把值域划分成若干个区间（桶），把元素放进对应桶中，再在每个桶内排序，最后按桶序合并。

直觉是按成绩分班——90~100 分一班、80~90 分一班……每个班内部再排成绩，最后按班序输出。如果成绩均匀分布，每班人数差不多，班内排序很快，整体接近线性；但如果全挤在一个班，就退化了。

```cpp:line-numbers [bucket-sort.cpp]
void bucketSort(vector<double>& a, int m) {
    vector<vector<double>> buckets(m);
    for (double x : a) {                 // 分桶
        int idx = (int)(x * m);
        if (idx >= m) idx = m - 1;
        buckets[idx].push_back(x);
    }
    int p = 0;
    for (auto& b : buckets) {            // 桶内排序 + 拼接
        std::sort(b.begin(), b.end());
        for (double x : b) a[p++] = x;
    }
}
```

### 正确性证明

- 每个元素都会被放进唯一对应的桶；
- 桶内排序后，桶内元素从小到大排列；
- 桶编号按区间顺序排列，桶间元素大小关系也正确；
- 因此按桶序合并后得到全局有序序列。

### 复杂度与稳定性

设有 $m$ 个桶，平均每个桶里有 $n/m$ 个元素。若每个桶内用插入排序：

$$
T(n) = O(n) + m \cdot O\!\left(\left(\frac{n}{m}\right)^2\right) = O(n) + O\!\left(\frac{n^2}{m}\right).
$$

| 情况 | 时间复杂度 | 直觉 |
|------|-----------|------|
| 最好 | $O(n)$ | 每个桶最多 1 个元素，桶内不用排 |
| 平均（均匀分布） | $O(n)$ | 每桶约 $n/m$ 个，$m$ 取 $\Theta(n)$ 时 |
| 最坏 | 视桶内排序 | 所有元素落入同一桶时退化为桶内排序的复杂度 |

::: warning 桶排序最坏复杂度取决于桶内算法
总览表里「最坏 $O(n^2)$」有一个隐藏前提：**桶内用插入排序**。若桶内用 `std::sort`（内省排序），最坏是 $O(n\log n)$。所以桶排序的最坏复杂度没有统一值，要写明桶内用什么排序。
:::

空间复杂度 $O(n)$（桶 + 桶内元素）。

**稳定性：** 视桶内排序策略而定；若桶内使用稳定排序并按桶顺序合并，可保持稳定。

## 7.1.11 基数排序

### 思路

基数排序适用于「关键字可以表示为若干位」的数据，例如十进制整数、字符串或定长字串。它通常采用 LSD（Least Significant Digit，最低位优先）策略：先按最低位分配到桶，再按桶序收集，继续处理更高位，直到最高位。

直觉是按学号排队——先看最后一位排好；再看倒数第二位排好（保持最后一位顺序不变）；……最后看第一位。因为每次都稳定，高位排序不会打乱低位已经排好的顺序。

```cpp:line-numbers [radix-sort.cpp]
void radixSort(int a[], int n) {
    int maxVal = *max_element(a, a + n);
    for (int exp = 1; maxVal / exp > 0; exp *= 10) {
        countingSortByDigit(a, n, exp);  // 稳定计数排序按当前位分配
    }
}
```

### 正确性证明

基数排序的有效性来自「稳定性 + 位级排序」。

- 对当前位做一次稳定排序；
- 稳定意味着较高位相同的元素，低位排序结果不会打乱它们的相对顺序；
- 处理完最低位后，数值按最低位有序；
- 再按次低位稳定排序，次低位优先于更高位的比较关系被正确保留；
- 最终所有位都处理完，整个关键字顺序正确。

**为什么必须稳定？** 假设当前排十位，两个数的十位相同但个位不同（如 23 和 27）。若排序不稳定，27 可能排到 23 前面——个位排序就白做了。稳定性保证「低位辛苦排好的顺序，高位排序不会搞乱」。

### 复杂度与稳定性

若关键字有 $d$ 位，每位基数为 $r$，则每趟分配/收集为 $O(n+r)$，总复杂度：

$$
T(n) = O\bigl(d(n+r)\bigr).
$$

若 $d$ 与 $r$ 是常数（如 32 位整数按字节分解：$d=4$、$r=256$），可看作线性时间 $O(n)$。

**稳定性：** 稳定（前提是每一位的排序都稳定）。

::: tip 基数排序 vs 比较排序
基数排序不是「比较排序」——它不依赖元素之间必须比较大小，而是依赖「按位检查」，所以不违背比较排序的 $\Omega(n\log n)$ 下界，只是使用了更强的输入结构信息（关键字可按键分解）。就像考试不能带计算器（比较排序），但如果你自己心算能力够强（非比较排序），算得比别人快不犯规。
:::

## 7.1.12 比较排序的下界

这是排序理论中最漂亮的结果之一——$\Omega(n\log n)$ 下界。它告诉我们：如果只有「比较」这一种手段，那 $n\log n$ 就是天花板，不可能更快。这不是某个算法的局限，而是**所有**比较排序的共同命运。

### 决策树模型

任何比较排序算法都可以看作一棵二叉树：

- 内部节点表示一次比较；
- 左/右分支对应「$a[i] < a[j]$」或「$a[i] > a[j]$」；
- 叶子节点对应排序完成后的一个排列。

决策树就是算法的「执行路线图」——每个输入对应树中从根到叶的一条路径，路径上的节点就是算法执行的比较操作。不同输入走不同的路，到达不同叶子（排列）。

当输入有 $n$ 个不同元素时，最终排序结果共有 $n!$ 种可能排列，所以决策树至少需要 $n!$ 个叶子节点。树高为 $h$，二叉树叶子数上界为 $2^h$，因此：

$$
2^h \ge n!.
$$

两边取对数：

$$
h \ge \log_2(n!) = \Omega(n\log n).
$$

最后一步用 Stirling 近似：$\log_2(n!) \approx n\log_2 n - n\log_2 e + O(\log n) = \Theta(n\log n)$。

直觉上，$n!$ 个排列至少需要 $\log_2(n!)$ 次二元决策才能区分——就像猜数字游戏，$M$ 个可能答案至少需要 $\log_2 M$ 次「是/否」问题。$n!$ 个排列就是 $n!$ 个「答案」，每次比较是一次「是/否」，所以至少 $\log_2(n!) = \Omega(n\log n)$ 次比较。这不是某个算法的问题，是信息论的基本限制。

### 这为什么不否定基数排序

因为基数排序不是「基于比较」决定顺序，而是利用了关键字的位结构（整数的十进制/二进制表示、定长字符串、有限值域）。它按位分桶，并非直接比较元素大小，因此不适用比较排序的决策树下界。

下界限制的是「只能比较大小」这种手段。如果还有别的信息（比如知道元素是 0~999 的整数），就可以直接看值放位置，不需要比较。决策树模型只建模了「比较」操作，没有建模「检查第几位是什么」——所以这个下界管不到非比较排序。

| 类型 | 可用信息 | 下界 | 能否突破 $n\log n$ |
|------|---------|------|-------------------|
| 比较排序 | 只能比较大小 | $\Omega(n\log n)$ | 不能 |
| 非比较排序 | 值域结构、位分解 | 无此限制 | 可以（但数据有要求） |

## 小结

本节把十种排序的「怎么做」「为什么对」「为什么快」三层串了起来。比较排序的终点由决策树下界划定为 $\Omega(n\log n)$，归并和堆排序达到了它；非比较排序用关键字的额外结构换来了线性时间，但前提是数据要满足特定条件。这也正是整个排序主题反复强调的一句话：**没有万能算法，只有前提与权衡**。
