# 2.3 栈与队列的应用

前两篇介绍了栈与队列的语义与实现。本篇把这两个结构放到真实问题中：括号匹配与表达式求值依赖"最近未匹配"的访问顺序，广度优先遍历依赖"按到达顺序处理"。理解这些场景，才能明白限制操作位置并不是缺点，而是设计本身。

## 学习目标

- 用栈实现括号匹配，并论证其时间与空间复杂度；
- 用栈完成中缀转后缀与后缀表达式求值；
- 解释单调栈如何把"下一个更大元素"的暴力扫描压到 `O(n)`；
- 说明为什么广度优先遍历需要队列而不是栈。

## 括号匹配

给定一个只含 `( ) [ ] { }` 的字符串，判断括号是否合法成对且正确嵌套。核心观察是：**最近出现的左括号必须最先被右括号匹配**——这正是后进先出。

算法：遇到左括号就压栈；遇到右括号时，若栈顶是与它配对的左括号则弹栈，否则匹配失败；扫描结束后栈必须为空。

```cpp:line-numbers [bracket-match.cpp]
bool is_balanced(std::string_view s) {
    std::stack<char> st;
    for (char ch : s) {
        if (ch == '(' || ch == '[' || ch == '{') {
            st.push(ch);
        } else {
            if (st.empty()) return false;            // 右括号没有可配对的左括号
            if (pair_of(ch) != st.top()) return false; // 括号类型不匹配
            st.pop();
        }
    }
    return st.empty();                               // 左括号是否全部被关闭
}
```

复杂度：每个字符最多入栈一次、出栈一次，所以时间 `O(n)`；最坏情况下全部是左括号，栈深 `O(n)`，因此空间 `O(n)`。

## 中缀转后缀与表达式求值

人类习惯中缀表达式 `a + b * c`，但计算顺序依赖括号与优先级。后缀表达式 `a b c * +` 没有括号，从左到右即可求值：遇到操作数压栈，遇到运算符弹出两个操作数计算后压回。

转换使用**调度场算法**（shunting-yard）：扫描中缀表达式，操作数直接输出，运算符与栈顶比较优先级。定义运算符优先级：

$$
P(o) = \begin{cases} 2 & o \in \{*, /\},\\ 1 & o \in \{+, -\},\\ 0 & o \text{ 是左括号。} \end{cases}
$$

遇到右括号时，一直弹出运算符直到栈顶为左括号，再把左括号弹出。每个运算符入栈一次、出栈一次，因此转换总时间 $O(n)$；后缀求值同理，每个操作数与运算符都只被处理一次。

::: details 用调度场转换 `a + b * c` 的全过程
1. 读 `a`：操作数，直接输出 → `a`。
2. 读 `+`：栈空，入栈 → 栈：`+`。
3. 读 `b`：输出 → `a b`。
4. 读 `*`：优先级 `2 > 1`，入栈 → 栈：`+ *`。
5. 读 `c`：输出 → `a b c`。
6. 结束：依次弹出 → `a b c * +`。

得到后缀表达式 `a b c * +`，与乘法优先于加法的规则一致。
:::

## 单调栈：下一个更大元素

问题：给定数组，对每个位置求出"右边第一个比它大的元素"。暴力做法对每个位置向后扫描，时间 `O(n²)`。

单调栈维护一个栈内元素严格递减的栈（栈顶最小）。从左到右扫描，新元素比栈顶大时，栈顶元素的下一个更大元素就是当前元素，于是弹栈并记录答案。因为每个元素最多入栈一次、出栈一次：

$$
T(n) = \sum_{\text{each element}} O(1) = O(n).
$$

空间 `O(n)` 用于栈本身。

## 队列与广度优先

当问题要求"按到达顺序处理"时，队列是自然选择。例如图的广度优先遍历（BFS）：从起点出发，先把相邻节点全部入队，再按入队顺序逐个取出并扩展。后进先出的栈在这里会产生深度优先的探索顺序，与"逐层扩散"的要求矛盾。

::: warning 栈与队列的选择取决于"谁先被处理"
同样遍历一张图，用队列得到广度优先顺序，用栈得到深度优先顺序。结构本身不决定结果正确与否，但决定遍历的语义——这是结构即语义最直观的例子。
:::

## 小结

栈擅长表达"最近未处理"的依赖：括号嵌套、表达式递归结构、单调栈中"下一个更大"的最近比较；队列擅长表达"先来先处理"：BFS 逐层扩散、任务按到达顺序调度。两者的共同点是：用受限的接口换取可预测的行为，并让关键操作达到 `O(1)`。
