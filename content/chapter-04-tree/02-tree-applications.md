# 4.2 树的应用：Huffman 与表达式树

树结构的两类典型应用：**Huffman 编码**把频率不等的字符组织成最优前缀编码，是贪心算法的经典例子；**表达式树**把中缀表达式的运算结构显式呈现，其后序遍历正是第 2 章的后缀表达式求值。

## 学习目标

- 构造 Huffman 树并计算带权路径长度（WPL）；
- 说明 Huffman 编码是前缀编码，且是最优的；
- 用表达式树解释中缀、后缀表达式的对应关系。

## 带权路径长度与 Huffman 树

给定 `n` 个叶子，权值分别为 `w₁, …, wₙ`，叶子深度为 `dᵢ`，树的**带权路径长度**定义为：

$$
\mathrm{WPL} = \sum_{i=1}^{n} w_i \, d_i.
$$

对同样的叶子权值，不同二叉树的结构会产生不同的 WPL。**Huffman 树**是使 WPL 最小的二叉树，构造算法（贪心）：

1. 把 `n` 个叶子各自作为一棵单节点树，权值为叶子权值；
2. 每次取出权值最小的两棵树，合并为一棵新树，权值为两者之和；
3. 重复直到只剩一棵树。

```cpp:line-numbers [huffman-merge.cpp]
// 用最小堆维护候选树；每次弹出两个最小的合并
// 以下为合并一步的示意，完整编码见 Lab 04-02
auto [w1, t1] = heap.pop_min();
auto [w2, t2] = heap.pop_min();
Node* merged = new Node{/* weight = */ w1 + w2, t1, t2};
heap.push({w1 + w2, merged});
```

**贪心正确性**：最小权值的两个节点必须位于最底层且互为兄弟，否则交换可以把它们移到底层并降低 WPL——这就是"每次合并最小的两个"不会错的原因。

## Huffman 编码

给每个字符一个编码，要求任何字符的编码**不是**另一个字符编码的前缀（前缀编码），解码才能无歧义。把每个字符作为叶子、沿"左 0 右 1"记录路径，Huffman 树自然给出前缀编码，且高频字符深度小、编码短：

$$
\text{平均码长} = \frac{\mathrm{WPL}}{\sum w_i}.
$$

因为 Huffman 树使 WPL 最小，所以它给出的前缀编码在所有前缀编码中平均码长最短。

::: warning 不是频率越高码长越短就一定最优
直觉上"高频短码"是对的，但字符之间会互相影响（前缀约束）。必须用贪心合并构造整棵树，而不是独立地为每个字符定码长。
:::

## 表达式树

中缀表达式 `(a + b) * (c - d)` 可以建成一棵二叉树：内部节点是运算符，叶子是操作数，运算符的左右子树是两个操作数对应的表达式。对这棵树做**后序遍历**得到：

```
a b + c d - *
```

正是第 2 章的后缀表达式——用栈即可求值。表达式树让运算结构可见，也解释了为什么后缀表达式不需要括号：运算顺序完全由树的后序决定。

## 小结

Huffman 树展示了"以树为结构、以贪心为方法"解决问题的完整路径：定义目标函数 WPL → 贪心合并 → 证明最优 → 得到编码。表达式树则把"表达式"这种语法结构与二叉树一一对应，是编译器与公式处理的基础模型。
