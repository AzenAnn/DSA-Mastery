# 3.2 模式匹配与 KMP

**模式匹配**：在主串 `S`（长度为 `n`）中查找模式串 `P`（长度为 `m`）首次出现的位置。这是文本编辑器、搜索引擎与生物信息学中的基础操作。朴素算法简单直观但最坏情况退化为 $O(n\cdot m)$；KMP（Knuth–Morris–Pratt）算法把匹配时间压到 `O(n + m)`。

## 学习目标

- 实现朴素匹配并构造其最坏情况输入；
- 解释朴素匹配的指针回退浪费了什么信息；
- 手工推导模式串的 next 数组；
- 论证 KMP 的复杂度为 `O(n + m)`。

## 朴素匹配

从左到右逐位比较：主串指针 `i` 指向本次尝试的起点，模式串指针 `j` 从 0 开始；一旦失配，`i` 回退到本次起点 + 1，`j` 归零重来。

```cpp:line-numbers [naive-match.cpp]
int naive_match(std::string_view s, std::string_view p) {
    int n = s.size(), m = p.size();
    for (int i = 0; i + m <= n; ++i) {      // i 是本次尝试的起点
        int j = 0;
        while (j < m && s[i + j] == p[j]) ++j;
        if (j == m) return i;               // 完全匹配
    }
    return -1;
}
```

最坏情况出现在**大量部分匹配后失配**：主串 `"aaaaaaaaab"`、模式 `"aaab"`，每次尝试都比较到模式末尾才发现第 4 个字符不同。此时约比较 $(n-m+1) \times m$ 次，复杂度 $O(n\cdot m)$。

## KMP 的核心思想

朴素算法在失配时把 `i` 回退到起点 + 1，把**已经匹配成功的部分全部作废**。观察 `S = "abababc"` 与 `P = "ababc"`：匹配到 `P[4]` 时失配，但此前 `P[0..3] = "abab"` 已经与主串对齐成功。主串这段的**后缀** `"ab"` 恰好是模式的**前缀**，于是模式可以直接右移两位，从 `P[2]` 开始继续——`i` 不后退。

因此 KMP 只需：失配时，把模式串指针 `j` 移动到"模式自己的最长相等前后缀"的长度，继续比较 `S[i]` 与 `P[j]`。

## next 数组

对模式串的每个位置 `j` 定义：

$$
next[j] = \max\{ k \mid 0 \le k < j,\ P[0..k-1] = P[j-k..j-1] \},
$$

即 `P[0..j-1]` 的**最长相等真前后缀**长度；无相等前后缀时 `next[j] = 0`。失配于 `P[j]` 时，就把 `j` 置为 `next[j]` 再继续。

例如模式 `P = "ababc"`：

| j | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| P[j] | a | b | a | b | c |
| next[j] | 0 | 0 | 0 | 1 | 2 |

::: details 手工推导 `next[4] = 2`
`P[0..3] = "abab"`，按候选长度从大到小检查真前后缀：长度为 3 时前缀 `"aba"`、后缀 `"bab"`，不等；长度为 2 时前缀 `"ab"`、后缀 `"ab"`，相等。因此最长相等真前后缀长度为 2，即 `next[4] = 2`。失配于 `P[4]` 时，模式整体右移，直接用 `P[2]` 与主串当前字符继续比较。
:::

::: warning next 数组的定义因约定而异
教材常有两种约定：`next[0] = -1` 版本（失配时同时移动主串指针）与 `next[0] = 0` 版本（主串指针不动，只移动模式指针）。本教程采用 `next[0] = 0`、失配时**主串指针不回退**的约定，与文中的推导一致。实现前先确认自己所学的教材采用哪种。
:::

用递推计算 next：已知 `next[j] = k`，比较 `P[j]` 与 `P[k]`；相等则 `next[j+1] = k+1`，否则令 `k = next[k]` 继续比较。

## KMP 复杂度

匹配过程里，主串指针 `i` 只前进不回退，最多移动 `n` 次；模式指针 `j` 每次失配最多回退到 `next[j] < j`，总回退量不超过总前进量 `m`。因此：

$$
T(n, m) = O(n + m).
$$

构建 next 数组的代价同样为 `O(m)`（递推中 `k` 的总前进与回退量都是 `O(m)`）。

## 小结

KMP 的关键不是"跳过比较"，而是**把已匹配的文本信息保留下来**：失配时利用模式自身的相等前后缀，让模式滑动而不让主串回退。这种"利用已知信息避免重复工作"的思想，同样出现在单调栈、并查集路径压缩等后续算法中。
