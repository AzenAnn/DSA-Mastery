# 3.1 字符串的存储与基本操作

字符串（串）是零个或多个字符组成的有限序列，记为 `S = "a₀a₁…aₙ₋₁"`，其中 `n` 为串长，`n = 0` 时为空串。串是字符的线性表，但它的核心操作不是随机存取某个字符，而是**子串查找、拼接与比较**，这决定了它的存储设计重点与线性表不同。

## 学习目标

- 区分串长、子串、位置等术语，理解空串与空格串的差别；
- 比较三种存储表示的分配方式与操作代价；
- 实现求长、取子串、定位、拼接等基本操作并分析复杂度。

## 串的存储表示

### 定长顺序存储

用固定大小的字符数组保存串，另用一个长度变量记录实际长度。优点是访问任意字符 `O(1)`、缓存友好；缺点是**长度受限**，拼接或插入可能截断，且需要约定截断时的失败方式。

```
| a | b | c | d | \0 | ... |
└── 数组前 n 格存放内容，length = 4 ──┘
```

定长串的最大长度在编译期确定，实际内容超长时必须处理"截断"或"失败"，接口要提前约定。

### 堆分配存储

运行时按串的实际长度动态分配一块连续内存，长度由长度变量维护。长度不受固定上限约束，拼接时重新分配即可；代价是每次拼接、截取都可能涉及内存分配与复制。

```cpp:line-numbers [heap-string.cpp]
struct HeapString {
    char* data = nullptr;   // 指向堆上连续内存
    std::size_t length = 0;
};

HeapString concat(HeapString a, HeapString b) {
    HeapString out;
    out.length = a.length + b.length;
    out.data = new char[out.length + 1];   // 分配一次，整体复制
    std::copy(a.data, a.data + a.length, out.data);
    std::copy(b.data, b.data + b.length, out.data + a.length);
    out.data[out.length] = '\0';
    return out;
}
```

`concat` 的复杂度是 `O(len(a) + len(b))`。连续多次拼接（如循环中逐字符追加）会导致反复整体复制，总代价会退化为 `O(k²)`——这是"字符串拼接要谨慎"这一经验的原因。

### 块链存储

把字符分块存入链表节点，每块保存若干字符。适合超长文本的批量处理，能避免整串搬移；代价是访问第 `i` 个字符需要沿链接行走，且每块内部可能有未用空间。

## 基本操作与复杂度

| 操作 | 行为约定 | 复杂度（堆分配） |
| --- | --- | --- |
| `length(s)` | 返回串长 | `O(1)` |
| `substr(s, pos, len)` | 返回从 `pos` 起长为 `len` 的子串；越界失败 | `O(len)` |
| `concat(a, b)` | 返回 `a + b` | `O(len(a) + len(b))` |
| `index(s, t)` | 返回子串 `t` 在 `s` 中首次出现的位置；无则返回约定结果 | `O(n·m)` 最坏（见 3.2） |
| `compare(a, b)` | 按字典序比较 | `O(min(len(a), len(b)))` |

::: warning 串比较不是长度比较
`"ab" < "abc"`，因为短串是长串的前缀时短串更小；`"abc" < "abd"`，因为第一个不同字符 `c < d`。比较必须逐字符按字典序进行，而不是先比长度。
:::

## 小结

串的三种存储方式对应三种取舍：定长存储简单但受限，堆分配灵活但拼接昂贵，块链适合批量但随机访问慢。选择取决于操作模式——是频繁比较、频繁拼接，还是大文本的流式处理。

2. 循环中逐字符拼接为什么代价是 `O(k²)`？如何改写才能变成 `O(k)`？
3. 定长存储的串在 `concat` 超长时应该怎样失败？给出两种可行约定并比较。
4. 为 `substr` 写出前置条件与后置条件。
