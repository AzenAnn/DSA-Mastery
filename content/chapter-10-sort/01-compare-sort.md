# 10.1 比较排序

**比较排序**通过两两比较关键字的大小决定顺序。本节从三类 $O(n^2)$ 基础方法讲起，再介绍两类 $O(n \log n)$ 方法，最后用决策树证明：比较排序不可能快于 $\Omega(n \log n)$。

## 学习目标

- 实现插入、冒泡、选择、归并、快速排序；
- 区分各算法的稳定性与额外空间；
- 用决策树论证比较排序的下界。

## O(n²) 三件套

**插入排序**把待排元素插入已有序前缀的正确位置；**冒泡排序**相邻比较交换、每趟把最大元素"冒"到末尾；**选择排序**每趟选出剩余最小值放到当前位。三者时间都为 $O(n^2)$，但差异在细节：

| 算法 | 最好情况 | 与初始顺序的关系 | 稳定性 |
| --- | --- | --- | --- |
| 插入排序 | `O(n)`（已有序） | 越有序越快 | 稳定 |
| 冒泡排序 | `O(n)`（已有序） | 越有序越快 | 稳定 |
| 选择排序 | $O(n^2)$ | 与初始顺序无关 | 不稳定 |

选择排序不稳定：选出最小值与当前位交换时，可能把相同关键字的相对顺序打乱。

```cpp:line-numbers [insertion-sort.cpp]
// 插入排序：向前比较，找到位置后后移元素
void insertionSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}
```

## O(n log n) 两类方法

**归并排序**分而治之：把数组对半分、各自排序、再线性归并。每次归并 `O(n)`，分 $\log n$ 层，总代价：

$$
T(n) = 2\,T\!\left(\frac{n}{2}\right) + O(n) = O(n \log n).
$$

归并稳定，但需要 `O(n)` 额外空间。

**快速排序**选一个**枢轴**，一趟划分把数组分成"小于枢轴 / 大于枢轴"两半，再递归两侧。平均 $O(n \log n)$，但划分严重失衡时（如每次枢轴都是最值）退化成：

$$
T_{worst}(n) = T(n-1) + O(n) = O(n^2).
$$

快排原地在数组上操作，只需递归栈 $O(\log n)$ 空间，但**不稳定**——划分交换时相同关键字可能错位。

::: warning 快排的退化输入
对已有序（或逆序）的数组，若固定取首元素作枢轴，每次划分都会极端失衡。实际实现用随机枢轴或三数取中来规避。
:::

## 比较排序的下界：决策树

任何比较排序都可以抽象成一棵**决策树**：每个内部节点是一次比较，叶子对应一种排列。`n` 个互异元素的排序有 `n!` 种可能结果，所以决策树至少需要 `n!` 片叶子。树高（即最坏比较次数）因此满足：

$$
2^h \ge n! \quad\Longrightarrow\quad h \ge \log_2(n!) = \Omega(n \log n).
$$

归并排序的 $O(n \log n)$ 已经达到这个下界——比较排序不可能更快，只能优化常数。

## 小结

比较排序的性能谱系是：$O(n^2)$ 简单但慢，$O(n \log n)$ 快但有代价（归并的空间、快排的不稳定性与退化）。决策树给出了这一谱系的终点：$\Omega(n \log n)$。在"比较"这个框架内，归并排序已经是最优复杂度。
