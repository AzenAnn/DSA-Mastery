# 第 5 章 树的应用

第 4 章回答了“树是什么、怎样存、怎样遍历”。本章继续追问：==一旦给树附加有序性、完全性、权重或集合语义，它能替我们解决什么问题？==

二叉搜索树把比较结果变成搜索方向；AVL 树用旋转控制高度；堆只维护局部偏序，却能持续取出最高优先级；赫夫曼树把频率变成短码；并查集用一片浅森林维护集合划分；B 树与 B+ 树则用高分支降低外存访问次数。这些结构的共同点不是“都长得像树”，而是都在维护一种可利用的不变量。

## 本章定位

::: intuition 从形状到约束
普通二叉树只规定每个节点至多有两个有序孩子。本章的结构会再增加一层合同：

- 二叉搜索树要求左小右大；
- AVL 树要求每个节点左右高度差受限；
- 堆要求父节点与孩子保持偏序；
- 赫夫曼树让高频符号靠近根；
- 并查集让每个集合由一棵代表树管理；
- B 树与 B+ 树让一个外存页容纳大量分支。

新增的约束会带来更强的操作保证，也会增加插入、删除时维护不变量的成本。
:::

## 学习目标

完成本章后，你应该能够：

1. 根据二叉搜索树的不变量完成查找、插入、删除，并解释退化原因；
2. 识别 AVL 树的 LL、RR、LR、RL 四类失衡，选择正确旋转恢复平衡；
3. 用数组实现堆，推导自底向上建堆为什么是 $O(n)$，并使用优先队列解决 Top-K 等问题；
4. 从字符权重构造赫夫曼树，计算 WPL，生成前缀码并完成编码、解码；
5. 实现带路径压缩和按秩或按大小合并的并查集，说明 $\alpha(n)$ 结论的前提；
6. 解释 B 树与 B+ 树为什么适合外存，手算查找、分裂、借位和合并过程；
7. 面对新问题时，从高频操作、数据规模和存储层级出发选择结构，而不是只凭名称套模板。

```text [chapter-05-map.txt]
        ├─ 加入完全形态与局部偏序 ──> 堆 ──> 优先队列
        │                                      │
        │                                      └─> 赫夫曼贪心构造
        │

        │
        └─ 提高单节点分支数 ──> B 树 / B+ 树 ──> 外存与数据库索引
```

横向比较时始终问三个问题：

1. **维护什么不变量？** 它决定操作正确性。
2. **一次操作会触碰多高或多少个节点？** 它决定时间复杂度。
3. **节点位于内存还是外存页？** 它决定真正昂贵的成本单位。

## 推荐学习顺序

1. 先学 BST 与 AVL，建立“更新后修复不变量”的基本模式。
2. 再学堆与优先队列，体会只维护部分顺序也能高效解决问题。
3. 用优先队列构造赫夫曼树，把结构选择与贪心策略连接起来。
4. 学并查集，理解树不一定用于遍历，也可以用来压缩代表关系。
5. 最后学习 B 树与 B+ 树，把复杂度视角从 CPU 操作扩展到页 I/O。

## 学习方法

- **先手算再运行**：对旋转、堆调整、赫夫曼合并和 B 树分裂，先画出每一步的局部结构。
- **把复杂度写成结构参数**：先用树高 $h$、符号种类数 $\sigma$、堆大小 $k$ 表达，再代入平衡条件。
- **主动制造反例**：递增插入 BST、在堆中误用二分查找、让并查集执行删除，观察不变量在哪里失效。
- **区分逻辑成本和存储成本**：B+ 树的优势主要来自减少页 I/O，不只是比较次数更少。

准备好后，从[5.1 二叉搜索树与平衡](./01-binary-search-tree-and-avl.md)开始。
