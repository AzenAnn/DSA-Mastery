# 第 0 章 绪论

数据结构研究如何组织数据，算法研究如何用有限、明确的步骤解决问题。本章先建立共同语言，再说明我们将如何通过“解释、实现、测试和复盘”来学习这门课。

## 学习目标

完成本章后，你应该能够：

- 区分数据、数据元素、数据结构和抽象数据类型；
- 从输入、输出、正确性和资源消耗四个角度描述算法；
- 使用数量级初步比较两个算法；
- 说清楚本项目如何用理论、实验与主动输出共同训练课程能力。

## 核心概念

| 概念 | 暂定理解 |
| --- | --- |
| 数据结构 | 数据元素及其关系，以及这些关系在计算机中的表示 |
| 抽象数据类型（ADT） | 对数据对象与允许操作的行为约定，不限定具体实现 |
| 算法 | 为解决一类问题而设计的有限、明确、可执行步骤 |
| 实现 | 使用具体语言和存储方式兑现 ADT 的约定 |
| 测试 | 用正常、边界和异常输入检查实现是否符合约定 |

## 课程地图

我们会从线性结构出发，逐步学习栈、队列、树、图、查找与排序，并在每章重复以下过程：

> 理解问题 → 写出解释 → 编程实现 → 设计测试 → 同伴审阅 → 修改发布

## 复杂度概览

时间复杂度描述运行时间随问题规模增长的趋势，空间复杂度描述额外存储随规模增长的趋势。它们不是秒表读数，也不代表可以忽略常数、输入分布和工程环境。

常见数量级从低到高大致为：

`O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n²)`。

## 章节小结

数据结构、算法、实现与测试是同一条学习链上的不同环节。后续章节不仅要回答“它是什么”，还要回答“为什么这样设计、代价是什么、如何证明实现可信”。

## 练习

1. 用自己的话说明 ADT 与具体代码实现的区别。
2. 举出一个现实生活中的“数据结构”，说明元素之间的关系。
3. 为什么只比较两段程序在自己电脑上的一次运行时间并不可靠？
4. 为本学期写下一个可验收的学习目标。
