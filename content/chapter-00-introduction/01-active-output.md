# 0.1 主动输出式学习

## 学习目标

- 能为一个知识点设计可检查的学习产出；
- 能区分“看懂了”和“能够独立解释、实现、测试”；
- 能在两人协作中完成作者与审阅者的角色轮换。

## 学习闭环

每个主题都尽量留下可以被他人检查的证据：

| 阶段 | 关键问题 | 最小产出 |
| --- | --- | --- |
| 输入 | 我参考了什么？ | 来源与问题清单 |
| 理解 | 我能否不用原文说明？ | 概念草图或口头讲解 |
| 解释 | 别人能否读懂？ | Markdown 初稿 |
| 实现 | 约定能否运行？ | 最小可执行代码 |
| 测试 | 哪些情况可能出错？ | 正常与边界测试 |
| 审阅 | 结论是否正确、清楚？ | Review 记录 |
| 改进 | 下一版改什么？ | 修订与待办 |

## 两人如何轮换

本章作者负责组织内容与实现，审阅者负责提出反例、运行测试和检查表述；下一章交换角色。审阅者不是“挑错的人”，而是帮助作者证明内容可信的人。

## 一个最小示例

学习“顺序表插入”时，不以读完一节为终点，而应至少做到：

1. 画出插入前后的元素位置；
2. 写出操作的前置条件和结果；
3. 实现插入并处理越界；
4. 测试空表、表头、表尾和容量已满；
5. 解释为什么最坏时间复杂度是 `O(n)`。

## 易错点

- 用改写教材句子代替自己的理解；
- 只测试示例输入，不测试边界；
- 为追求完整而一次写太多，长期无法完成；
- 让同一个人长期只写理论或只写代码。

## 小结

主动输出不是增加作业量，而是把“是否真正理解”变成可见、可审阅、可迭代的证据。每次先完成最小闭环，再逐步扩写。

## 练习

1. 为“数组下标访问”设计一份最小学习产出清单。
2. 选一个你以为已经掌握的概念，在三分钟内不看资料讲给同伴听，并记录卡住的地方。
3. 分别写出作者和审阅者在一次章节 Pull Request 中最重要的两项责任。
