# 0.2 复杂度入门

## 学习目标

- 能为简单问题选择合理的问题规模 `n`；
- 能识别 `O(1)`、`O(log n)`、`O(n)` 和 `O(n²)` 的典型代码形态；
- 能分别说明最坏情况、平均情况与最好情况；
- 能区分理论增长趋势与实际计时。

## 先确定问题规模

复杂度中的 `n` 必须有含义。例如，顺序查找的 `n` 可以是元素个数，图算法可能同时涉及顶点数 `V` 和边数 `E`。如果没有先说明规模，复杂度结论就不完整。

## 常见增长数量级

| 数量级 | 直观代码形态 | 示例 |
| --- | --- | --- |
| `O(1)` | 执行次数不随 `n` 增长 | 按下标读取数组元素 |
| `O(log n)` | 每步缩小固定比例 | 二分查找 |
| `O(n)` | 扫描全部元素一次 | 顺序查找最坏情况 |
| `O(n log n)` | 分层处理且每层总工作量为 `n` | 归并排序 |
| `O(n²)` | 两层都与 `n` 相关的遍历 | 简单两两比较 |

## 时间与空间

时间复杂度关注基本操作次数的增长趋势；空间复杂度通常关注算法运行时使用的额外空间。原地修改数组的算法也会占用输入本身的空间，因此写结论时应说明统计口径。

## 分析步骤

1. 定义输入规模；
2. 选择能代表主要工作的基本操作；
3. 计算该操作随规模增长的执行次数；
4. 说明分析的是最好、平均还是最坏情况；
5. 保留主导项，写出数量级；
6. 如有必要，再用实验验证常数因素和真实环境影响。

## 易错点

- 把 `O(n)` 读成“运行时间等于 n 秒”；
- 忽略提前退出导致的不同情况；
- 看到两层循环就直接断定为 `O(n²)`；
- 只写时间复杂度，不说明额外空间；
- 用少量计时数据替代理论分析。

## 小结

复杂度是一种描述增长趋势的语言。可靠结论应同时交代规模、基本操作、输入情况和空间统计口径。

## 练习

1. 分析在长度为 `n` 的数组中读取第一个元素的时间复杂度。
2. 分析顺序查找在最好与最坏情况下的比较次数。
3. 一个循环每次将 `n` 除以 2，最多执行多少次？
4. 找出一个“两层循环但不是 `O(n²)`”的例子，并说明原因。
