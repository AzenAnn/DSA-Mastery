# Lab 06-E-05：小镇法官

> 题目来源：[LeetCode 997](https://leetcode.com/problems/find-the-town-judge/)。保留原题图语义，将函数参数与返回值改为标准输入输出。

## 学习目标

- [ ] 记录每个人直接信任他人的次数和被直接信任的次数。
- [ ] 同时检查两个条件，保留不存在法官时的 -1。
- [ ] 能解释算法正确性与复杂度，并通过正常、边界和回归用例。

先阅读 [6.1 图的基本概念](../../../../content/chapter-06-graph-foundations/01-graph-basics.md)。环境需要 Node.js、pnpm 和支持 C++17 的编译器；Make 可选，可用下方 pnpm 命令替代。

## 题目

小镇有 n 个人。每条信任记录 u v 表示 u 信任 v。若存在一个人不信任任何人，且其余 n-1 人都信任他，则他是法官。请返回法官编号；不存在则输出 -1。信任不是双向关系，也不具有传递性。

## 输入格式

第一行 `n m`，随后 `m` 行为信任记录 `u v`。

### 数据范围

`1 <= n <= 1000`，`0 <= m <= 10000`，顶点编号 `1..n`；`u != v`，每个有序对最多出现一次。

输入为单组有效数据，所有整数和命令按空白分隔。自动评分不包含非法编号、非法命令或违反上述限制的图，不需要额外输出输入校验提示。

## 输出格式

输出法官编号；不存在时输出 `-1`。

只向标准输出写入答案；调试信息写入标准错误。按题面规定分行，评分按空白分隔的 token 比较。

## 样例

### 样例输入

```text
3 2
1 3
2 3
```

### 样例输出

```text
3
```

1 和 2 都信任 3，3 没有向外的信任记录，因此法官是 3。

## 正常、边界与错误情况

- 正常情况：按题目定义处理全部输入，输出与输入边的排列顺序无关。
- n=1、m=0：唯一的人满足条件，输出 1。
- n>1、m=0：没有人得到全部信任，输出 -1。
- 常见错误：只看入度会把仍信任别人的人判为法官；相互信任不能合并成无向边。
- 非法输入不在评分范围；不要在标准输出中添加提示词、调试标记或额外解释。

## 正确性说明

出度为 0 等价于不信任任何人；在无自环且有序对不重复的条件下，入度为 n-1 等价于其余所有人都信任该人。两个条件同时成立正好与法官定义等价。

## 复杂度分析

时间 `O(n+m)`，额外空间 `O(n)`；不需要邻接矩阵。
