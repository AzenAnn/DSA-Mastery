# Lab 07-08：显式栈 DFS

## 学习目标

- [ ] 能用显式栈帧实现 DFS，并在发现顶点时立即标记；
- [ ] 能逐个处理升序邻居，使访问顺序与递归升序一致；
- [ ] 能说明递归 DFS 在深图上爆栈、显式栈不爆栈的原因。

## 前置知识

完成前建议先阅读[第 7.1 节 图的遍历：DFS 与 BFS](../../../content/chapter-07-graph-traversal/01-dfs-and-bfs.md)的"显式栈实现"小节。你需要准备支持 C++17 的编译器；可先运行 `make doctor` 检查环境。

## 输入格式

第一行包含三个整数 `n m s`，分别表示顶点数、无向边数和 DFS 起点。顶点编号为 `0` 到 `n-1`。

接下来 `m` 行，每行包含两个整数 `u v`，表示一条无向边。输入保证：

- `1 <= n <= 1000000`；
- `0 <= m <= 1000000`；
- `0 <= s, u, v < n`；
- 不包含自环和重复边；
- 图不保证连通，也不保证从 `s` 能到达全部顶点。

为保证结果唯一，每个顶点的邻居必须按编号**升序**排序；显式栈必须保存“顶点 + 下一个邻居下标”的递归帧，逐个处理邻居，使访问顺序与递归 DFS 的升序访问一致。

## 输出格式

输出一行，包含从起点 `s` 出发能访问到的所有顶点，按首次进入顶点的 DFS 发现顺序排列，顶点间用单个空格隔开，行末无空格。不可达顶点不输出。

### 样例输入

```input
5 4 0
1 3
0 1
1 4
0 2
```

### 样例输出

```output
0 1 3 4 2
```

## 任务

1. 读入无向图，构建邻接表并升序排序；
2. 用显式栈保存 `(顶点, 下一个邻居下标)`，起点入栈时立即标记并访问；
3. 每次只推进当前帧的一个升序邻居，发现新顶点后压入新帧；邻居处理完毕后弹出当前帧；
4. 栈空时结束，输出访问顺序。

::: tip 两个必须
- **发现时标记**：否则同一顶点会被多个邻居重复压栈，栈膨胀到 `O(n^2)`；
- **递归帧**：一次只处理一个邻居，避免“批量入栈”改变 DFS 回溯顺序。
:::

::: tip 内存建议
深图（如 `n = 10^6` 的链）上，建议用保存 `Frame` 的 `std::vector<Frame>` 作为栈并先 `reserve(n)`；递归实现会直接栈溢出，本题必须使用显式栈。
:::

## 正常、边界与错误情况

| 情况 | 预期行为 |
| --- | --- |
| 一般连通图 | 访问顺序与递归升序 DFS 一致 |
| 百万级长链 | 显式栈正常完成，递归实现会爆栈 |
| 星形图 | 帧栈峰值约为 2，验证逐邻居推进 |
| 单顶点图 | 只输出起点 |
| 非连通图 | 只输出从 `s` 可达的顶点，不可达顶点不输出 |
| 含环图 | 入栈时标记阻止重复入栈 |

## 复杂度分析

每个顶点恰好入栈一次、出栈一次，每条边扫描一次，时间为 `O(n + m)`；显式栈、`visited` 与邻接表共占 `O(n + m)` 空间。显式栈把系统递归栈换成了自己管理的内存，深度不再受系统栈大小限制。

## 思考与复盘

### 1. 如果不保存“下一个邻居下标”，而是一次性处理全部邻居，会怎样影响交叉边场景的访问顺序？

::: details 参考答案
批量把邻居压栈会让后压入的邻居先被访问，顺序与递归 DFS 相反或产生额外变化；在交叉边场景中，这还可能改变某顶点先被哪条边发现。保存下标并一次推进一个邻居才能与递归升序完全一致。
:::

### 2. 链状图上 BFS 队列只有 `O(1)` 大小，为什么这里仍强调 DFS 的显式栈？

::: details 参考答案
BFS 和 DFS 的辅助空间取决于各自 frontier：链上 BFS 的 frontier 很小，但 DFS 需要同时保留从根到当前点的全部未完成帧，深度为 `O(n)`。显式栈避免这部分深度占用系统调用栈。
:::

### 3. 若图是一棵有 `10^6` 个节点的树，递归 DFS 会发生什么？显式栈的空间是 `O(n)` 还是 `O(树高)`？

::: details 参考答案
若树退化成链，递归深度达到 `10^6`，通常会栈溢出；显式栈峰值是当前 DFS 路径长度，即 `O(树高)`，最坏仍为 `O(n)`，但由堆内存和程序自行管理。
:::
