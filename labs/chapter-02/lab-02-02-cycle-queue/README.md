# Lab 02-02：循环队列的边界测试

## 目标

实现循环队列，用空、满、环绕三种边界场景验证判空判满与长度公式的正确性。

## 前置知识

- 第 2.2 节队列的 ADT、假溢出与循环队列公式。

## 建议用时

90～120 分钟。

## 任务

1. 用数组实现循环队列（容量 `cap` 的数组只允许存放 `cap - 1` 个元素），公开 `enqueue`、`dequeue`、`front`、`is_empty`、`is_full`、`size` 六个操作。
2. 逐个验证边界场景并记录每一步的 `front`、`rear` 下标：
   - 空队列：`dequeue`/`front` 必须失败，`is_empty() == true`；
   - 满队列：连续入队到 `cap - 1` 个，再 `enqueue` 必须失败，`is_full() == true`；
   - 环绕：入队 `cap - 1` 个、出队 `cap - 2` 个、再入队 `cap - 2` 个，验证 `front` 越过数组末尾回到开头后 `size` 仍正确；
   - 长度公式：随机混合入队/出队 100 次，每次断言 `size() == 队列实际元素数`。
3. 输出每次操作后的下标快照，用于人工核对。

## 提交物

- 可运行代码（含测试入口）；
- 运行结果输出（至少包含下方验收清单的全部场景）；
- 100～200 字说明：为什么必须空出一格才能区分空与满。

## 验收标准

- [ ] 空队列 `dequeue`/`front` 返回明确失败，程序不崩溃；
- [ ] 满队列 `enqueue` 返回明确失败；
- [ ] 队列元素数从未超过 `cap - 1`；
- [ ] 环绕一圈后 `size`、`is_empty`、`is_full` 仍正确；
- [ ] 100 次随机操作的断言全部通过；
- [ ] 报告每个场景的退出码或断言结果；
- [ ] 说明文字能解释空出一格的必要性。

## 加分项

- 实现 `grow()`：队列满时容量翻倍并重新映射元素下标，复用同一组测试验证扩容后行为不变；
- 对比链队列实现，在报告中给出两种实现的边界约定差异。
