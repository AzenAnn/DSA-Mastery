# Lab 02-02：队列选择题精练

## 目标

辨析队列的先进先出语义、`front` 与 `dequeue` 的行为差异，推导循环队列的下标与长度，并检查链队列边界、复杂度和工程选型中的常见误区。

## 前置知识

建议先阅读[第 2.2 节队列](../../../content/chapter-02-stack-queue/02-queue.md)，并确认采用正文的统一约定：`front` 指向队头元素，`rear` 指向下一次入队写入位置，循环队列使用空一格方案。题目中的物理槽位数均以 `m` 表示。

正文循环队列部分已有 3 道随堂复习题，分别检查有效容量、判满条件和满队列入队失败后的状态。本 Lab 不重复这些题目，而是进一步检查操作序列、公式应用、链式边界与实现取舍。

## 环境、输入与预期输出

- **环境**：任意现代浏览器；建议准备纸笔画出队头、队尾和逻辑顺序。
- **输入**：本页按源文件顺序加载的 10 道单项选择题。
- **预期输出**：一份独立作答记录，以及每道错题的错误原因和正确推导。

## 作答方法

1. 先写出当前逻辑队列，不要只观察数组中的物理位置；
2. 涉及循环下标时，明确 `m`、`front`、`rear` 的含义后再代入公式；
3. 选择答案并提交，再核对反馈、提示和题解；
4. 做错后点击“重新作答”，在不看解析的情况下重新推导。

## 思考题

1. 为什么逻辑队列顺序不能直接由数组下标从小到大判断？
2. 动态扩容队列的“摊还 `O(1)`”为什么不等于每次入队最坏 `O(1)`？
3. 链队列若只维护 `head` 而不维护 `tail`，哪项基本操作可能退化为 `O(n)`？
4. 双栈队列中，一个元素为什么不会在两个栈之间反复来回移动？

## 复盘

- 我最容易混淆的是 FIFO 语义、循环下标，还是物理容量与逻辑长度？
- 代入公式前，我是否先确认了 `front` 和 `rear` 的具体约定？
- 面对实现选型题时，我是否先看容量、分配和延迟约束，而不是只看容器名称？
