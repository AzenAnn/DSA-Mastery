# Lab 08-E-09：【模板】普通平衡树

> 题目来源：改编自 [洛谷 P3369【模板】普通平衡树](https://www.luogu.com.cn/problem/P3369)。本 Lab 使用课程自定义输入输出协议和独立测试，不复制来源站点的代码或测试。

## 学习目标

- [ ] 实现一棵**手写** AVL 树：结点维护 `height` 与子树大小 `size`，插入与删除后沿回溯路径逐层 `rebalance`；
- [ ] 熟练处理四种失衡形态 LL、RR、LR、RL——LR/RL 要"先拉直再单旋"，删除引发的失衡可能在回溯路上连续出现；
- [ ] 借助 `size` 实现"严格小于 x 的元素个数"与"第 k 小"，把排名、第 k 小、前驱、后继都做到单次 $O(\log n)$。

## 前置知识与环境

先阅读[第 8.3 节 平衡查找树](../../../../content/chapter-08-search/03-balanced-search-tree.md)的"AVL 树"（含"四种失衡形态""LR 与 RL：先把折线拉直"）、"AVL 插入流程""AVL 删除"与"AVL 的高度与复杂度"几节。

**与 [Lab 08-E-01](../E-08-01-bst-operations/)（普通 BST 增删查）的差异**：E-08-01 的数据是随机到达、规模很小，普通 BST 就够用；本题操作数达到 10⁵，且压力用例里包含**升序插入**序列——普通 BST 会退化成一条长度 5×10⁴ 的链，每次操作 $O(n)$，在时限内必然超时（用例 006 就是专门为此设计的）。这正是 8.2 节"何时不该用普通 BST"强调的结论：只有维护平衡，才能保证每次操作 $O(\log n)$。

在 Lab 目录执行 `make doctor` 检查环境；未安装 Make 时可在仓库根使用 pnpm 兜底命令（见下文"运行"）。

## 任务

维护一个**可重复**的整数多重集合，初始为空，依次处理 `n` 个操作：

| 操作 | 含义 |
| --- | --- |
| `1 x` | 插入 `x`（可与已有元素重复） |
| `2 x` | 删除一个 `x`（若有多个只删一个；数据保证 `x` 存在） |
| `3 x` | 查询 `x` 的排名：**严格小于** `x` 的元素个数 + 1（`x` 不一定在集合中） |
| `4 r` | 查询排名为 `r` 的数（即第 `r` 小；保证 1 ≤ r ≤ 当前元素个数） |
| `5 x` | 查询 `x` 的前驱：严格小于 `x` 的最大元素（数据保证存在） |
| `6 x` | 查询 `x` 的后继：严格大于 `x` 的最小元素（数据保证存在） |

### 输入格式

- 第一行：一个整数 `n`，为操作总数；
- 接下来 `n` 行：每行两个整数 `opt x`，含义见上表。

### 输出格式

对每个 `opt = 3/4/5/6` 的操作，输出一行一个整数；`opt = 1/2` 不产生输出。

### 数据范围与限制

| 项目 | 范围 |
| --- | --- |
| 操作数 `n` | 1 ≤ n ≤ 10⁵ |
| 元素值 `x` | \|x\| ≤ 10⁷ |
| 排名查询 `r` | 保证 1 ≤ r ≤ 当前元素个数 |
| 前驱 / 后继 | 数据保证存在（不必处理"不存在"的输出） |
| 删除操作 | 保证被删元素在集合中 |
| 实现要求 | **手写** AVL 树（不得用 `std::map` / `std::multiset` 等关联容器代替），插入、删除都要维护 `size` |
| 时间复杂度要求 | 每个操作 $O(\log n)$；普通 BST 在用例 006 的升序插入下会退化成链而超时 |

### 正常、边界与错误情况

- **重复值**：插入同一个值多次后，`3` 的排名要把所有严格小于它的元素都数进去；删除只移除一个实例；
- **排名边界**：查询最小元素的排名（结果为 1）与最大元素的排名（结果为当前元素个数）；第 1 小与最后一小；
- **前驱后继**：前驱可能就是相邻的重复实例之间的关系（如多重集合中 0 有多个时，0 的后继是下一个更大的值而非 0 本身）；
- **空集合**：操作 4/5/6 保证合法，因此不会在空集合上查询，但删除使集合反复变空又变非空的过程要正确维护 `size`。

## 样例

### 样例 1

```input
10
1 106465
4 1
1 317721
1 460929
1 644985
1 84185
1 89851
6 81968
1 492737
5 493598
```

```output
106465
84185
492737
```

`4 1` 时集合里只有 106465，第 1 小就是它；`6 81968` 时集合为 {84185, 89851, 106465, 317721, 460929, 644985}，大于 81968 的最小元素是 84185；插入 492737 后，`5 493598` 的前驱是 492737。

### 样例 2

```input
12
1 5
1 3
1 5
1 8
3 5
4 2
2 5
3 5
5 5
6 5
4 1
4 3
```

```output
2
5
2
3
8
3
8
```

逐条解释：插入后多重集合为 {3, 5, 5, 8}；`3 5` 的排名 = 严格小于 5 的元素个数 1，再加 1 得 2；`4 2` 是第 2 小 = 5；`2 5` 只删掉一个 5，剩 {3, 5, 8}；`3 5` 仍为 2；`5 5` 的前驱是 3，`6 5` 的后继是 8；`4 1` 是 3，`4 3` 是 8。

## 实现提示

- 结点里同时维护 `height` 和 `size`，旋转后**先**更新被转下去的结点，**再**更新新根；漏掉 `size` 会让排名与第 k 小悄悄出错，而高度看起来一切正常；
- 插入递归返回新的子树根，回溯时逐层 `rebalance`；删除"至多一个孩子"的情形直接让孩子顶替，把再平衡交给回溯路径；
- LR 形态的判据是"左孩子的左子树高度 **小于** 左孩子的右子树高度"；删除时可能遇到左右等高、单旋即可恢复的情况，判据写成 `<=` 与 `<` 都要推一遍为什么正确；
- `rankOf(x)` 沿树下行：`x` 不大于当前键就往左走，否则把"左子树 size + 1"累加进答案再往右走；`kth(k)` 反向利用同一个 `size`；
- 对拍是本章核心题的必做步骤：写一个基于有序数组（或 `multiset` 语义）的暴力程序，随机生成小规模混合操作，与你的 AVL 逐行比对输出。重复值 + 删除的组合最容易暴露 `size` 维护的 bug。
