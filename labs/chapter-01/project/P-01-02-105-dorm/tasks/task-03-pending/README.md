# Task 3：一楼门口的待送清单

门口的物品陆续送达，也会有人取消帮送或补上一单。用带头结点的单链表维护这份清单，再复用 Task 2 按顺序尝试完成它。

## 本关交付

只修改 `student/pending_list.cpp`。构造、析构、清空、只读访问、引用查询和基础校验已在 `../../src/pending_support.cpp` 中提供。

空表满足 `head_.next == nullptr`、`tail_ == &head_`、`size_ == 0`。非空时尾节点的 `next` 为 `nullptr`，`size_` 等于业务节点数。头结点不保存有效任务。禁止复制这份链表，避免两个对象释放同一批节点。

| 函数 | 行为 |
| --- | --- |
| `append(request, students)` | 校验后尾插，成功返回 true |
| `insertAfter(afterId, request, students)` | 在指定任务后插入；指定任务不存在时失败 |
| `cancel(requestId)` | 删除指定任务，释放节点；不存在时返回 false |
| `processOnce(students)` | 每条原有任务尝试一次，删除成功项，返回本轮成功数 |

## 输入和失败边界

`Request` 包含任务编号、帮助者学号和收件人学号。只保存 ID，不保存学生指针或学生表下标。`acceptable` 已检查容量、任务编号、当前重复、自取和双方存在；追加和补单都应复用它。

当前任务编号唯一，删除后可重用；清单上限为 105。插入失败时不新建残留节点、不改变长度和链接。取消任务不会返还体力或改变热心值，因为待送任务尚未成功结算。

## 遍历中删除

按链表顺序调用 `tryDeliver`，成功项立即删除，失败项保留。处理失败后继续下一项；下一次调用才重新尝试保留项。不要重新安排顺序或自动更换帮送者。

~~~text
原清单：A -> B -> C -> D
结果：  成功 成功 失败 成功
结束：  C
返回：  3
~~~

若某同学只剩 7 点体力，他的第一单送往十楼会失败，后面送往三楼的任务仍可成功；不能遇到第一个失败就终止整轮。

::: details 提示：先在纸上维护前驱
在每次循环开始，标出“当前要检查的节点”和“它的前驱”。成功删除后，前驱是否仍在同一个位置？失败保留后呢？比较这两个分支，再决定指针何时移动。
:::

::: details 提示：最后一个节点
删除尾节点之后，谁成为新尾节点？如果删除的是唯一一个节点，新的尾指针又应指向哪里？随后立即追加一条任务，可以暴露尾指针失效的问题。
:::

`cancel` 的按编号定位为 O(m)，局部改链为 O(1)。`processOnce` 遍历 m 个任务，但每次还要在线性表中找学生，因此总体为 O(mn)，额外工作空间为 O(1)。只展示链表时，框架的按下标访问可能重复遍历；这不是本关算法评分项。
