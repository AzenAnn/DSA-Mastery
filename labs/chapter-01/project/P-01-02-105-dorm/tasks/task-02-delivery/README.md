# Task 2：热心的同学

几位同学在一楼门口集合，每次替另一名同学送一件快递或外卖。给定帮送顺序，计算谁成功完成了任务，以及谁积累了最高热心值。

## 本关交付

只修改 `student/delivery.cpp`，复用 Task 1 的 `StudentTable`。`Student` 已包含 `stamina`、`helpScore`、`delivered`，无需修改结构体定义或重新维护另一份名单。

| 函数 | 契约 |
| --- | --- |
| `deliveryCost(floor)` | 合法楼层返回 `3 * (floor - 1) + 1`；非法楼层返回 -1 |
| `deliveryReward(floor)` | 合法楼层返回 `10 + 2 * (floor - 1)`；非法楼层返回 -1 |
| `tryDeliver(students, helperId, receiverId)` | 检查、结算一趟帮送，返回状态、消耗和奖励 |
| `findTopHelpers(students, indices)` | 输出全部并列第一的下标，返回人数 |

## 完整规则

每次从一楼取件，到收件人所在楼层，然后回到一楼。上楼每层耗 2 点、下楼每层耗 1 点，另收取送消耗 1 点。帮送者自己的寝室楼层不影响这一趟成本；不考虑同楼层走廊距离。快递和外卖在本模型中没有差异。

`tryDeliver` 依次检查并返回：

1. 任一学生不存在：`UnknownStudent`。
2. 学号相同：`SelfDelivery`。
3. 剩余体力小于完整成本：`NoStamina`。
4. 其余情况：`Delivered`，扣除帮助者体力，增加热心值和成功次数。

失败时两个数值字段均为 0，整份学生表不变。体力恰好够时成功；体力不自动恢复。使用收件人当前楼层，且不改变收件人的任何字段。

排行榜只考虑 `delivered > 0` 的学生。同分者按名单顺序返回，不能只返回一个最大值下标。调用方提供 105 个整数的结果数组；无人成功帮送时返回 0。

## 手算与引导

~~~text
001 初始体力 100。
001 -> 三楼：消耗 7，奖励 14，剩余体力 93，成功次数 1。
001 -> 十楼：消耗 28，奖励 28，剩余体力 65，累计热心值 42。
~~~

::: details 提示：如何保证失败不改变状态
先在局部变量中得到完整成本和奖励，完成所有判断之后，再修改学生记录。思考“先扣去程体力，后来发现不够返程”的程序为何违反契约。
:::

::: details 提示：不排序也能找出全部第一名
对分数 12、25、18、25 手算两轮扫描。第一轮只回答“最大值是多少”，第二轮回答“谁达到了这个值”。两轮 O(n) 仍然是 O(n)。
:::

`tryDeliver` 的查学生过程为 O(n)，拿到合法记录后的体力计算和状态更新为 O(1)。给出 m 条已指定的指令并逐条调用，整体可为 O(mn)，不要把整个流程称为 O(m)。
