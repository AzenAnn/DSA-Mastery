# Lab 01-P-02：105 栋的热心同学

去年，中山大学计算机学院的一群男生住在南校园 105 栋。大家喜欢这栋寝室，也记得一起生活时那些顺手帮忙的小事。

这次，把故事放进一个 C++ 程序：宿管王需要查学生住在哪间寝室；热心同学从一楼门口帮别人拿快递、送外卖；门口的待送清单不断增加、取消，完成的任务又从清单中划去。你将逐步补全这个小系统。

**故事背景来自对 105 栋的回忆；学生姓名、房间、楼层上限和体力规则是实验模型，不代表真实人员资料或楼栋布局。**

## 学习目标与前置知识

- 用顺序表保存完整记录，处理增删改查及同名查询。
- 用读写双指针稳定批量删除，解释它为什么不需要反复搬移。
- 按指定顺序模拟帮送，先判断再更新状态，扫描找出全部并列第一。
- 用带头结点的单链表维护任务，正确处理遍历中的连续删除。
- 复用前一关实现，理解数据如何在多个模块之间传递。

只要求已经学过 Ch1 的数组、结构体/基础类、字符串、函数、指针和链表；不要求图、最短路、背包、排序或复杂调度算法。固定容量、输入解析、菜单、构造析构和测试框架已经提供。

## 统一规则

### 学生与寝室

- 学生表最多 105 人；学号是 1～20 位 ASCII 数字字符串，唯一且不可修改，`001` 与 `1` 不同。
- 姓名是非空字符串，允许同名和中文。姓名查询是完全匹配，返回全部匹配者，保持名单顺序。
- 实验模型的楼层为 1～10，楼层内房间号为 1～30；二者分别存储，例如楼层 3、房间号 7。楼栋固定为 105。
- 新学生体力为 100，热心值和成功帮送次数为 0。修改姓名或寝室不会重置这些数值。
- 非法输入、重复学号、表满、找不到修改或删除目标时，操作失败且原记录不变。

### 帮送与热心值

每趟从一楼出发，只送一件，到收件人的寝室后回到一楼。上楼每层耗 2 点，下楼每层耗 1 点，取送物品另耗 1 点。

| 目标楼层 f | 总体力消耗 | 成功奖励 |
| --- | --- | --- |
| 任意合法楼层 | `3 * (f - 1) + 1` | `10 + 2 * (f - 1)` |
| 一楼 | 1 | 10 |
| 三楼 | 7 | 14 |
| 十楼 | 28 | 28 |

先检查双方存在，再检查是否自取，最后检查是否有足够体力完成整趟。恰好足够时允许帮送；失败不扣体力、不加分、不计成功次数，返回的 cost/reward 为 0。收件人的状态不变。

帮送者由输入指定，不需要自动选人或优化路线。体力不自动恢复。并列最高分的成功帮送者全部上榜，顺序与学生表相同；无人成功帮送时榜单为空。

### 待送清单与删除保护

清单最多 105 条，每条保存任务编号、帮送者学号、收件人学号，一条就是一件物品。任务编号也使用 1～20 位数字字符串，当前清单内唯一；完成或取消后允许重新使用该编号。

加入时双方必须存在且不能是同一人。新单默认尾插，也可以在指定任务后插入。取消不存在的任务、编号重复、满表或插入位置不存在时，清单不变。

`processOnce` 按当前顺序对每条原有任务尝试一次：成功后删除，失败项原地保留，然后继续后面的任务。同一帮送者可能前几单成功、后来体力不足；失败单不会阻止后面更便宜的任务。再次处理不会重复结算已经删除的成功单。

待送清单只保存学号，执行时查最新房间。Final 中，有待送任务关联的帮送者或收件人不能被删除；批量搬离时先检查全部受影响学生，再决定整批是否执行。Task 1 底层容器只负责删表，Final 负责这项业务保护。

### 统计范围

程序每次启动是一轮独立模拟，不读写历史存档。“今日热心榜”汇总的是**当前学生表**中的累计成功次数和热心值。学生合法搬离后，其记录及统计也移出当前榜单；重新登记视为新记录。汇总不会恢复体力或改变任何记录。

## 环境与第一次运行

需要 Node.js 22.13+、仓库指定版本 pnpm、C++17 编译器和 CMake 3.25+。Windows 可直接使用 pnpm 入口，无需 GNU Make；编译器缺失时按 doctor 给出的提示安装。

在仓库根目录执行：

~~~powershell
pnpm install --frozen-lockfile
pnpm lab:doctor -- labs/chapter-01/project/P-01-02-105-dorm
pnpm lab:validate -- labs/chapter-01/project/P-01-02-105-dorm
pnpm lab:run -- labs/chapter-01/project/P-01-02-105-dorm --task students
~~~

此时出现未满分是正常的：模板中的核心函数仍是 TODO。先打开 `tasks/task-01-students/student/student_table.cpp`，从 `findIndex` 和 `add` 开始。

完成每关后分别运行：

~~~powershell
pnpm lab:run -- labs/chapter-01/project/P-01-02-105-dorm --task delivery
pnpm lab:run -- labs/chapter-01/project/P-01-02-105-dorm --task pending
pnpm lab:run -- labs/chapter-01/project/P-01-02-105-dorm --task final
pnpm lab:score -- labs/chapter-01/project/P-01-02-105-dorm
~~~

四关都是自动评分，没有人工待评分。每关内部测试合计 100 分，再按权重折算。`run` 会展示结果；严格 `score` 未满分时退出码为 1，工具或环境错误为 2。

有 Make 时可以在本 Lab 目录运行 `make run TASK=students`、`make score`。VS Code 插件中打开整个课程仓库，进入 Ch1 的 Project `01P02`，逐 Task 打开学生代码并运行测评。

每行一个命令，姓名可以用双引号包围；`HELP` 查看语法，`QUIT` 或输入结束退出。空行和以 `#` 开头的整行注释会被忽略。

## 正常、边界与错误情况

| 情况 | 应观察到的结果 |
| --- | --- |
| 同名两人 | 两个结果都出现，学号不同 |
| 同寝室连续多人搬离 | 返回正确人数，剩余顺序不变 |
| 体力恰好够 / 不够 | 前者扣到 0；后者完全不修改 |
| 连续几个任务成功 | 每个都被删除，后面的任务仍被处理 |
| 清单删除到空后再加入 | 头尾指针仍正确，可继续使用 |
| 换寝后执行旧任务 | 使用新寝室楼层计算 |
| 命令缺参数、多参数或数字溢出 | `ERROR INPUT`，该行不执行，继续读取下一行 |
| 参数语法正确但违反业务规则 | `ERROR ADD` 等操作错误，或明确帮送失败状态 |
