# Lab 14-E-20：疯狂的采药

## 学习目标

- [ ] 能独立写清状态含义、合法转移与初始化，而不是只背代码模板。
- [ ] 能实现本题的 C++17 动态规划，并解释为什么循环顺序满足依赖关系。
- [ ] 能用边界与反例检查「完全背包必须允许本轮的新状态再次参与转移，因此容量正序。」这一常见错误。

## 前置知识与环境

先阅读 [第 14 章对应小节](../../../../content/chapter-14-dynamic-programming/04-knapsack-dp.md)，并确保本机可使用 C++17。首次运行可执行 `make doctor`；Windows 未安装 Make 时可在仓库根使用 pnpm 命令。

## 题目

有 M 种药草，每种可采任意多次。每次消耗固定时间并得到固定价值，总时间不超过 T，求最大价值。

### 输入格式

第一行 `T M`，随后 M 行为 `time value`。

### 输出格式

输出最大价值。

### 数据范围

所有时间为正，且 `M×T ≤ 10^7`。

### 样例输入

```text
10 2
3 4
4 5
```

### 样例输出

```text
13
```

## 做题前先填状态卡

| 问题 | 本题答案 |
| --- | --- |
| 状态 | `dp[c]` 表示容量 c 内的最大价值。 |
| 选择 | 不增加当前种类，或再采一株当前种类。 |
| 转移 | `dp[c]=max(dp[c],dp[c-time]+value)`。 |
| 初值 | 初值为 0。 |
| 顺序 | 种类在外，容量从 time 正序到 T。 |
| 答案 | `dp[T]`。 |

不要急着写循环。先用一个最小输入手算状态表，再检查每个右侧依赖是否已经计算；如果依赖来自“当前物品的新状态”，还要说明这是否意味着允许重复选择。

## 复杂度目标

时间 `O(MT)`，空间 `O(T)`。

## 测试设计提示

公开测试共 20 组、总分 100 分，覆盖样例、最小规模、单行/单列或单元素、不可达/全负/重复值等题型边界，以及容易暴露循环方向和初始化错误的回归输入。测试只接受标准输出；调试信息请写到标准错误。

## 思考与复盘

1. 如果改用另一种状态定义，转移和循环顺序会怎样变化？
2. 哪个最小反例最容易暴露「完全背包必须允许本轮的新状态再次参与转移，因此容量正序。」？
3. 能否压缩空间？压缩后会不会覆盖本轮仍需读取的状态？
