# Lab 14-E-23：零钱兑换

## 学习目标

- [ ] 能独立写清状态含义、合法转移与初始化，而不是只背代码模板。
- [ ] 能实现本题的 C++17 动态规划，并解释为什么循环顺序满足依赖关系。
- [ ] 能用边界与反例检查「不可达状态不能直接加 1；金额为 0 时答案是 0。」这一常见错误。

## 前置知识与环境

先阅读 [第 14 章对应小节](../../../../content/chapter-14-dynamic-programming/04-knapsack-dp.md)，并确保本机可使用 C++17。首次运行可执行 `make doctor`；Windows 未安装 Make 时可在仓库根使用 pnpm 命令。

## 题目

给定若干种正整数面额，每种硬币可使用任意多枚。求凑成指定金额需要的最少硬币数；无法凑成时输出 -1。

### 输入格式

第一行 `n amount`，第二行 n 个互不相同的面额。

### 输出格式

输出最少硬币数或 `-1`。

### 数据范围

`1 ≤ n ≤ 12`，`0 ≤ amount ≤ 10000`。

### 样例输入

```text
3 11
1 2 5
```

### 样例输出

```text
3
```

## 做题前先填状态卡

| 问题 | 本题答案 |
| --- | --- |
| 状态 | `dp[s]` 表示凑成金额 s 的最少硬币数。 |
| 选择 | 选择一枚面额 coin 作为最后一枚。 |
| 转移 | `dp[s]=min(dp[s],dp[s-coin]+1)`。 |
| 初值 | `dp[0]=0`，其他状态为不可达正无穷。 |
| 顺序 | 硬币在外、金额正序，或金额在外枚举硬币。 |
| 答案 | 若 `dp[amount]` 可达则输出它，否则 -1。 |

不要急着写循环。先用一个最小输入手算状态表，再检查每个右侧依赖是否已经计算；如果依赖来自“当前物品的新状态”，还要说明这是否意味着允许重复选择。

## 复杂度目标

时间 `O(n·amount)`，空间 `O(amount)`。

## 测试设计提示

公开测试共 20 组、总分 100 分，覆盖样例、最小规模、单行/单列或单元素、不可达/全负/重复值等题型边界，以及容易暴露循环方向和初始化错误的回归输入。测试只接受标准输出；调试信息请写到标准错误。
