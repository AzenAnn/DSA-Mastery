# Lab 00-01：制作个人 DSA 学习地图

## 目标

「我要学数据结构」这句话没法执行——它没有顺序、没有边界，也没有「怎么算学会了」。这个 Lab 要你把这句话改写成一份**可检查、可迭代**的个人学习地图：你知道先学什么、后学什么，每个主题做到哪一步算数，以及进度落后时先砍掉什么。

做完之后，你应该能：

- 从一堆想学的东西里，挑出本学期真正要啃的 6～10 个主题，并说清谁依赖谁；
- 为其中任意一个主题，写出「解释、实现、测试、审阅」四类最小可交付产出；
- 拿这张图去和同伴互相挑毛病，而不是自己闷头改。

## 建议用时

30～45 分钟。第一次做会偏慢，因为难的不是画图，是把「想学」翻译成「做哪几件具体的事」。

## 前置知识

- 已经浏览过课程总目录，知道本课程分哪些章节、各章大概讲什么；
- 不需要会写代码——这份地图是「学习计划」，不是代码题。

## 先自己判断一下

动手前，先回答这三个问题（不用写下来，想清楚即可）：

1. 如果这个学期只能学会 3 个主题，你会选哪 3 个？为什么是它们，而不是别的？
2. 有没有哪个主题，你其实不知道「学完它」意味着能做什么？
3. 你觉得「学完链表」和「会做链表的题」是一回事吗？

如果你对第 2 题答「有」、对第 3 题答「不是一回事」，那这份作业正是为你准备的。

## 任务

### 1. 挑 6～10 个主题，画出先后依赖关系

从本课程里挑出你本学期准备学的 6～10 个主题。把它们排成一张**有方向**的图：A 在 B 前面，意味着「不先弄懂 A，B 就学不动」。

- 至少要有 6 个主题，但不要超过 10 个——超过 10 个通常说明你还没砍掉「以后再说」的那部分；
- 依赖关系用箭头画清楚。可以用 Mermaid、ASCII 图，或直接列「前置 → 主题」。

### 2. 为其中一个主题写出四类最小产出

选图里**最靠前**的一个主题，为它写出四类最小产出：

| 产出类型 | 回答的问题 | 最小可交付物 |
| --- | --- | --- |
| 解释 | 能用大白话讲清它是什么 | 一段不超过 150 字的口头解释 |
| 实现 | 能把它写出来 | 一段能跑的最小代码（哪怕 10 行） |
| 测试 | 能证明它是对的 | 至少 3 个用例，含 1 个边界用例 |
| 审阅 | 能挑出它哪里可能错 | 一条具体的 Review 意见 |

::: tip 为什么是这四类
「解释」逼你把概念讲给自己听；「实现」逼你落地；「测试」逼你定义「对」；「审阅」逼你怀疑自己。四类都做到，才算把这个主题从「听说过」变成「会了」。少一类，就是给自己留了一个「我以为我懂」的坑。
:::

### 3. 与同伴交换地图，互相挑刺

把地图发给一个同伴，同时看 ta 的。各提出：

- **一个范围过大点**——哪部分野心太大，这学期根本做不完；
- **一个遗漏点**——哪部分缺了，会导致后面卡住。

### 4. 根据反馈修订一次，保留修订说明

改完地图后，写一段**不超过 150 字**的修订说明：你接受了哪条意见、改了什么、为什么没接受另一条（如果有）。

## 产出模板

把成果填进下面这个模板即可（Markdown）：

````markdown
# 我的 DSA 学习地图（本学期）

## 主题与依赖

<!-- 用箭头表示先后，例如：数组 → 链表 → 栈与队列 -->

## 第一个主题的四类产出

**主题：** ______

- 解释：______（≤150 字）
- 实现：______（贴代码或说明）
- 测试：______（≥3 个用例，含 1 个边界）
- 审阅：______（一条具体 Review 意见）

## 同伴反馈与修订

- 范围过大点：______
- 遗漏点：______
- 修订说明：______（≤150 字）
````

## 提交物

- 一份 Markdown 学习地图（按上面的模板）；
- 一段不超过 150 字的修订说明。

## 约束

- 主题必须来自本课程目录，不能自己另起一套；
- 依赖关系必须是有向的——如果画不出「谁必须先于谁」，说明这个主题要么太独立，要么你还没想清；
- 四类产出必须都是「可检查」的：写得出来、跑得起来、判得出对错、挑得出毛病。

## 验收标准

- [ ] 地图里恰有 6～10 个主题，且每个主题都有一条「前置 → 主题」的依赖箭头；
- [ ] 至少一个主题有完整的四类产出，四类都非空且能对应到「可交付物」那一列；
- [ ] 能指出本月「必须做」和「以后再做」的内容（在图上标注出来）；
- [ ] 记录了同伴的「范围过大点」和「遗漏点」各一条；
- [ ] 修订说明 ≤150 字，且写明了「接受了什么 / 改了什么」。

## Review 提示

审阅者可检查：依赖图里有没有「环」（A 依赖 B、B 又依赖 A）；四类产出里的「测试」是否真的能判对错（而不是「跑一遍没报错」）；修订说明是否真的对应了同伴的某条具体意见，而不是一句空话。

## 思考

如果两周后进度落后，你会删减哪些非核心工作，同时保留怎样的最小学习闭环？
