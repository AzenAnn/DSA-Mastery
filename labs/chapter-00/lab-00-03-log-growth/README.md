# Lab 00-03：用减半策略观察对数增长

## 目标

通过记录“每步将规模减半”的循环迭代次数，直观认识 `O(log n)` 的增长趋势，并与 Lab 00-02 中观察过的 `O(1)`、`O(n)`、`O(n²)` 形成对照。

## 建议用时

45～60 分钟。

## 任务

1. 编写一个“减半”函数：每轮迭代将当前规模减半（例如对 `n` 反复执行 `n = n // 2`，或用有序数组上的二分查找），并统计循环的迭代次数。
2. 对 `n = 10、100、1000、10000、100000` 记录迭代次数。
3. 将结果与 Lab 00-02 的 `1`、`n`、`n²` 数据放进同一张对照表。
4. 验证以下两个关键结论：
   - 规模 `n` 翻倍时，迭代次数大约只增加 `1`；
   - `n` 从 `1000` 增大到 `100000`（100 倍）时，次数约从 `10` 增加到 `17`。

## 提交物

- 可运行代码；
- 一张与 Lab 00-02 对照的操作次数表；
- 100～200 字结论。

## 验收标准

- [ ] 计数器统计的是明确写出的基本操作（如循环迭代次数）；
- [ ] 实验至少包含 4 组递增规模，且最大规模不小于 `100000`；
- [ ] 记录次数与 `⌊log₂ n⌋ + 1` 相符，或解释了差距的来源；
- [ ] 能说出“规模翻倍、次数约加 1”这一关键关系；
- [ ] 结论没有把 `O(log n)` 解释成“常数时间”或固定秒数；
- [ ] 对照表能看出相同规模下 `n²` 与 `log n` 的巨大差距。

## 加分项

- 实现真正的有序数组二分查找（而不是单纯计数），比较“命中”与“未命中”两种情况下迭代次数的差异；
- 用递归改写减半函数，记录并解释递归调用次数。

## 思考

如果 `n = 2³⁰`（约 10 亿），减半循环最多执行多少次？对比 Lab 00-02 中 `n²` 算法在 `n = 1000` 时的表现，这个差距说明了什么？
