# Lab 10-02：排序性能基准

## 目标

对插入、冒泡、选择、归并、快排、堆排序做系统基准测试，验证理论复杂度，重点演示快排的退化输入与插入排序在小规模上的常数优势。

## 前置知识

- 10.1、10.2 节全部排序算法与复杂度分析；第 2 章时间复杂度的测量方法。

## 建议用时

120～150 分钟。

## 任务

1. 实现六类排序，统一接口 `sort(int a[], int n)`，并给每类排序注入比较计数器。
2. 测试矩阵（规模 × 分布）：

   | 规模 | 随机 | 已有序 | 逆序 |
   | --- | --- | --- | --- |
   | 1,000 | ✓ | ✓ | ✓ |
   | 10,000 | ✓ | ✓ | ✓ |
   | 100,000 | ✓ | ✓（注意快排退化） | ✓ |

3. 每格记录：耗时与比较次数；`O(n²)` 算法在 100,000 规模耗时过长时允许跳过并注明。
4. 对随机数据画"规模翻 10 倍耗时翻几倍"的表格，验证 `O(n²)` 与 `O(n \log n)` 的增长差异。
5. 重点实验：对 10,000 已有序数据运行快排（固定首元素枢轴），记录耗时的惊人退化；改为随机枢轴或三数取中后复测。

## 提交物

- 基准测试代码（含比较计数器）；
- 完整的耗时/比较次数矩阵；
- 100～200 字结论：规模增长规律是否符合复杂度、快排退化的原因与规避、小规模数据哪种算法最快。

## 验收标准

- [ ] 三张表（随机/有序/逆序）数据完整；
- [ ] 随机数据下 `O(n²)` 算法耗时约按 100 倍增长，`O(n \log n)` 约按 10~20 倍增长（允许噪声）；
- [ ] 能复现快排在有序输入上的退化并给出规避后的对比；
- [ ] 结论明确说明实测与理论的偏差及原因（常数、缓存、递归开销）。

## 加分项

- 加入 STL `std::sort`（introsort）与 `std::stable_sort` 作对照基线；
- 对 10,000 规模输入运行排序稳定性检查（与 Lab 07-01 联动），验证"快排不稳定"在基准数据上是否可见。
