# Lab 10-01：排序稳定性对比

## 目标

用"关键字 + 序号"形式的记录验证六类排序的稳定性，直观观察不稳定排序如何打乱相同关键字的相对顺序，并解释原因。

## 前置知识

- 10.1 节比较排序与稳定性定义；10.2 节堆排序与基数排序。

## 建议用时

60～90 分钟。

## 任务

1. 定义记录类型 `(key, id)`，排序时只按 `key` 比较，`id` 是插入时的原始序号。
2. 实现六类排序：插入、冒泡、选择、归并、快排（固定枢轴取首元素）、堆排序。
3. 生成测试数据：`key` 含大量重复值（如从 `{1,2,3,4,5}` 中随机取 50 个），`id` 从 1 递增。
4. 对每个算法排序后，检查所有相同 `key` 的记录是否仍按 `id` 升序排列，输出：

   | 算法 | 排序结果是否稳定 | 观察到的反例（若有） |
   | --- | --- | --- |
   | 插入排序 | | |
   | 冒泡排序 | | |
   | 选择排序 | | |
   | 归并排序 | | |
   | 快速排序 | | |
   | 堆排序 | | |

5. 对不稳定的算法，找出并打印第一组被交换相对顺序的相同关键字记录（如 `(key=3, id=5)` 排到了 `(key=3, id=2)` 前面）。

## 提交物

- 六类排序的可运行代码；
- 稳定性测试结果表；
- 100～200 字结论：选择、快排、堆排序各自在哪个步骤破坏了稳定性（配具体例子）。

## 验收标准

- [ ] 六类排序按 `key` 正确排序（`id` 不作为比较依据）；
- [ ] 插入、冒泡、归并输出稳定，选择、快排、堆排序输出不稳定，与理论一致；
- [ ] 每个不稳定算法至少打印一个具体反例；
- [ ] 结论能对应到具体代码步骤（如交换、划分、堆顶交换）。

## 加分项

- 对不稳定的算法实现稳定化改造（如选择排序改用"找最小并顺序移动"），对比改造前后结果；
- 实现基数排序，验证它的每趟稳定分配如何保证整体稳定。
