# Lab 09-E-05：设计哈希映射·线性探测

> 题目来源：改编自 [LeetCode 706. 设计哈希映射](https://leetcode.cn/problems/design-hashmap/)。本 Lab 使用课程自定义输入输出协议和独立测试，不复制来源站点的代码或测试。

## 学习目标

- [ ] 手写一个基于**开放定址 + 线性探测**的哈希映射：桶数组、散列函数 $H(k)=k \bmod C$、探测序列 $H+i$；
- [ ] 解释**为什么删除必须用墓碑（TOMBSTONE）而不是把槽清回空槽（EMPTY）**，并在实现中正确区分两种"非占用"状态；
- [ ] 实现 put 的两个探测目标：先**跨过墓碑**寻找同键槽覆盖旧值，再落回首个墓碑槽或空槽；
- [ ] 体会装填因子逼近 1 时线性探测的**堆积**代价，以及"表内至少留一个空槽"这条约定保护了什么。

## 任务

设计一个哈希映射，支持三种操作：

- `put k v`：把键 `k` 映射到值 `v`；若 `k` 已存在，**覆盖**旧值；
- `get k`：输出键 `k` 对应的值；`k` 不存在时输出 `-1`（键与值的取值范围保证非负，`-1` 不会与真实数据混淆）；
- `remove k`：删除键 `k`；`k` 不存在时无任何效果。

实现口径已钉死：**开放定址 + 线性探测 + 墓碑删除**。每个槽记录 `{state, key, value}`，`state ∈ {EMPTY, USED, TOMBSTONE}`；散列函数 $H(k)=k \bmod C$，冲突时依次探测 $H, H+1, H+2, \ldots$（对 $C$ 取模绕回）。

删除的语义必须用**墓碑标记**：把被删槽标记为 `TOMBSTONE`，而不是清回 `EMPTY`。直接清空会**截断探测链**——在它之后落入的同义词从此查不到（见样例 2）。墓碑槽允许被后续 `put` 复用：探测时墓碑"看起来不存在"，落位时优先占用它，探测链保持完整。

数据保证**全程不同键的个数 ≤ C−1**：表里永远至少留一个空槽，探测不会绕表一整圈仍然找不到落脚点。

### 输入格式

- 第一行：两个整数 `C` 和 `n`，分别为桶数组容量与操作数；
- 接下来 `n` 行，每行一条指令，格式为 `put k v`、`get k` 或 `remove k`。

### 输出格式

对每条 `get` 指令，输出一行一个整数：键存在时为其当前值，不存在时为 `-1`。

### 数据范围与限制

| 项目 | 范围 |
| --- | --- |
| 桶数组容量 `C` | 8 ≤ C ≤ 10⁴（不要求质数） |
| 操作数 `n` | 1 ≤ n ≤ 2×10⁵ |
| 键 `k`、值 `v` | 0 ≤ k, v ≤ 10⁶ |
| 不同键个数 | 全程 ≤ C−1（表内至少留一个空槽） |
| 时间复杂度要求 | 单次操作平均 $O(1)$（摊还）；每步探测 $O(1)$，不要对整表线性扫描 |
| 输出上限 | 8 MB（`get` 行数最多 2×10⁵，判题器放宽了默认 1 MB 输出上限） |

### 正常、边界与错误情况

- **正常**：`put` 覆盖已有键；`get` 命中输出当前值；`remove` 后 `get` 输出 `-1`；
- **边界**：对空表 `get`；`get`/`remove` 不存在的键；删除后重新 `put` 同散列地址的新键；表接近满（不同键数 = C−1）时所有操作仍正确；
- **错误陷阱**：删除聚集区中间的键后，必须仍能 `get` 到落在它后面的同义词——把槽清回 `EMPTY` 的写法在这里直接出错；墓碑只对"查找"透明，`put` 落位时可以且应该复用它。

## 样例

### 样例 1

```input
16 11
put 1 10
put 2 20
put 2 99
get 1
get 2
get 3
remove 2
get 2
put 3 30
get 3
get 2
```

```output
10
99
-1
-1
30
-1
```

`put 2 20` 后再次 `put 2 99` 覆盖旧值，故 `get 2` 输出 `99`；`remove 2` 之后两次 `get 2` 都是 `-1`；`get 3` 在覆盖前查不到，`put 3 30` 之后输出 `30`。

### 样例 2

```input
10 9
put 0 5
put 10 6
put 20 7
get 20
remove 0
get 20
get 10
remove 0
get 0
```

```output
7
7
6
-1
```

$C=10$ 时键 `0`、`10`、`20` 散列地址都是 0，依次落进槽 0、1、2。`remove 0` 把槽 0 标成墓碑；此后 `get 20` 与 `get 10` 都要**跳过墓碑**继续探测才能找到答案（输出 `7`、`6`）。如果把槽 0 直接清回 `EMPTY`，`get 20` 会在槽 0 提前终止，错答 `-1`。最后的 `remove 0` 操作的对象已不存在，无效果，`get 0` 输出 `-1`。

## 实现提示

- 槽结构：`struct Slot { State state; long long key, value; }`，`State` 取 `EMPTY / USED / TOMBSTONE`，初始全部 `EMPTY`；
- `get(k)`：从 $H$ 起步线性探测，`USED` 且键相等即命中；`TOMBSTONE` 跳过继续；`EMPTY` 立即判定不存在；
- `put(k, v)`：探测途中记录**首个墓碑槽**下标；遇到同键 `USED` 槽就覆盖返回；遇到 `EMPTY` 说明键不存在，落位时优先复用记录的墓碑槽，没有墓碑才占用这个空槽；
- `remove(k)`：按 `get` 的方式定位，命中后把 `state` 改成 `TOMBSTONE` 即可，`key/value` 无需清理；
- 不要在 `put` 里遇到第一个空槽就插入而不管墓碑——那样会让墓碑后面的探测链分叉吗？想清楚"查找跨墓碑、落位用墓碑"两件事的差别。
