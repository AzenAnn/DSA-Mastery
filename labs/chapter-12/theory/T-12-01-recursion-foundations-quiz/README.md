# Lab 12-T-01：递归基础与分治思想选择题精练

## 目标

- 判断递归边界、递归调用次数与调用栈空间；
- 解释朴素递归中的重复子问题，并选择记忆化优化；
- 掌握分治法的分解、求解、合并过程；
- 区分分治与动态规划的子问题关系。

## 前置知识

建议先阅读[递归基础与调用语义](../../../../content/chapter-12-divide-conquer-recursion/01-recursion-foundations.md)和[分治模式与典型路径](../../../../content/chapter-12-divide-conquer-recursion/02-divide-and-conquer-patterns.md)。

## 环境、输入与预期输出

- **环境**：任意浏览器；建议准备纸笔绘制递归调用树。
- **输入**：本页按顺序给出的 10 道选择题。
- **预期输出**：独立作答记录，以及每道错题对应的递归边界或分治依据。

## 作答方法

1. 先明确函数语义、基准情况和子问题规模，再选择答案；
2. 涉及调用次数时画出完整调用树，不要只数递归边；
3. 点击“提交答案”后核对解析，并记录错误前提；
4. 完成全部题目后再查看答案总览。

## 题型覆盖与边界

| 类型 | 本 Lab 的处理方式 |
| --- | --- |
| 基础概念 | 递归边界、调用栈、局部变量和适用结构 |
| 递归优化 | 识别 Fibonacci 重复子问题与记忆化 |
| 分治模型 | 分解、求解、合并以及主定理基础 |
| 易错边界 | 明确阶乘基准条件后再统计调用次数 |

- [ ] 10 道题均在展开答案前独立作答；

## 思考题

1. 为什么递归写法更简洁，并不意味着时间复杂度一定更低？
2. 记忆化为什么改变 Fibonacci 的时间复杂度，却仍可能保留线性栈深度？
3. 子问题存在大量重叠时，为什么通常要考虑动态规划而非直接分治？

## 复盘

- 我是否在分析递归前先确认了基准情况？
- 我能否区分递归调用次数、递归深度和总工作量？
- 哪个错误选项利用了“一看到递归就认为更慢”的误区？
