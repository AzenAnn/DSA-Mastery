# Lab 03-01：字符串匹配工具

## 目标

实现朴素匹配与 KMP 匹配，用计数器对比两者的比较次数，验证 KMP 在退化输入上的优势。

## 前置知识

- 第 3.2 节模式匹配与 KMP 的 next 数组推导。

## 建议用时

90～120 分钟。

## 任务

1. 任选一种语言实现 `naive_match(s, p)` 与 `kmp_match(s, p)`，两者都返回首次匹配位置，未找到返回约定值（如 -1）。
2. 为 `kmp_match` 实现 next 数组构建，并在两个函数内部统计字符比较次数。
3. 用以下输入对比：

   | 编号 | 主串 | 模式 | 期望 |
   | --- | --- | --- | --- |
   | 1 | `"abababc"` | `"ababc"` | 位置 2 |
   | 2 | `"aaaaaaaaab"` | `"aaab"` | 位置 7（朴素最坏输入） |
   | 3 | `"hello world"` | `"world"` | 位置 6 |
   | 4 | `"abc"` | `"xyz"` | 未找到 |

4. 输出每个用例的匹配位置与两种算法的比较次数。

## 提交物

- 可运行代码（含 next 构建与计数逻辑）；
- 运行结果（四个用例的位置与比较次数）；
- 100～200 字结论：KMP 在哪些输入上节省了比较，哪些输入两者几乎相同。

## 验收标准

- [ ] 四个用例的匹配位置全部正确；
- [ ] 用例 2 中朴素算法比较次数明显大于 `n + m`，KMP 不超过 `n + m` 量级；
- [ ] next 数组构建正确（可对照 `"ababc"` 的 `0 0 0 1 2` 手工核对）；
- [ ] 未找到时返回约定值且程序不崩溃；
- [ ] 报告每个用例的比较次数与断言结果。

## 加分项

- 实现统计函数记录 next 构建本身的比较次数，验证其为 `O(m)`；
- 生成随机长串做 100 组基准，画出两种算法比较次数随 `n` 的增长趋势。
